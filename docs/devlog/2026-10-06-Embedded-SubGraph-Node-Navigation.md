# 내장 SubGraph의 노드 생성과 페이지 탐색

작성: 2026-10-06  
갱신: 2026-10-07  
유형: 구현·결정 기록  
대상: KataGraph·KataGraphEditor의 내장 생성과 페이지 전환  
기준: #27의 1·2단계 미커밋 변경과 노드 중심 UX 수정

## 배경과 결론

사용자는 SubGraph 노드를 만들고 더블클릭하면 내부 페이지로 들어가는 흐름을 기대했다고 설명했다.
기존 구현은 별도 SubGraphs 패널에서 원본을 먼저 만드는 방식이어서 기대와 달랐다.
사용자의 구현 승인에 따라 패널을 제거하고 노드 배치 시 원본을 함께 만들도록 바꿨다.
런타임 평탄화 연결은 예정된 3단계에 남겨 둔다.

## 변경 내용

| 항목 | 반영 내용 |
|---|---|
| 노드 생성 | 우클릭 메뉴의 SubGraph가 `UKataSubGraphNode`와 부모 소유 원본·Entry를 한 트랜잭션에서 생성한다 |
| 연결 지점 | SubGraph 노드는 In과 Out을 함께 표시한다. 기존 Port In/Out은 추가 참조 지점으로 유지한다 |
| 페이지 탐색 | 더블클릭으로 내부 페이지를 열고 상단의 부모 이름 버튼으로 돌아간다 |
| 표시 이름 | F2로 원본 이름을 바꾼다. 공백뿐인 이름·대소문자를 무시한 중복 이름을 거부한다 |
| 패널 제거 | 목록 위젯·탭 등록·패널 전용 작업 API를 제거하고 레이아웃 버전을 변경했다 |
| 원본 소유 | 노드를 삭제해도 원본과 다른 포트 참조는 남긴다. 내장 콤보에서 기존 원본을 다시 선택할 수 있다 |
| Details | 소유 목록은 직렬화·GC용 Instanced 프로퍼티로 유지하고 기본 Details의 인라인 객체 트리에서는 숨긴다 |

## 주요 결정과 이유

노드 배치 경로가 원본과 참조를 준비한 후 편집 노드를 선택한다. 생성 직후부터 제목·더블클릭·Details가
같은 원본을 가리키게 하기 위해서다. 내장 안에서 다시 내장을 생성하는 메뉴는 제공하지 않아 첫 구현의 한 단계 소유를 유지한다.

원본의 소유자는 계속 부모 그래프다. 노드 삭제를 원본 삭제로 확장하면 같은 원본을 쓰는 다른 포트나 복사한 노드의
설정을 잃을 수 있으므로 원본을 보존한다. 원본 영구 삭제 UI는 이번 수정 범위에 넣지 않았다.

화면 전환은 Core ticker에서 입력 콜백이 끝난 후 적용한다. 요청이 여러 번 오면 마지막 요청을 적용하며,
대기 대상은 GC로 추적하고 에디터 종료 때 ticker를 해제한다. 참조 콤보는 프로퍼티 변경 알림 중
Details가 교체되어도 실행 중인 커스터마이제이션과 핸들을 유지하도록 했다.

## 크래시 진단과 확인 범위

사용자가 조작 경로를 특정하지 못한 접근 위반을 보고했다. 스크린샷은 엔진 FName 비교·생성 프레임을 보여 주며,
최근 프로젝트 로그에는 fatal 호출 스택이 없었다. 첫 KataGraphEditor 프레임과 주변 호출 경로를 요청했다.
이 근거만으로 SubGraph UI의 특정 동작이나 엔진 결함을 원인으로 확정하지 않았다.

화면 전환과 프로퍼티 변경 콜백의 수명 경로는 수정했지만, 보고된 크래시가 해결됐다는 결과는 없다.
에이전트는 빌드·테스트·별도 검사를 수행하지 않았다. 이번 수정의 컴파일·UI·Undo/Redo·저장·GC는 미확인이다.

## 후속 수정: 배치 저장과 삭제한 후보 정리

사용자가 패널 크기를 바꾸고 다시 열면 초기화되는 현상과, SubGraph 노드를 삭제한 뒤에도
Embedded 후보가 남는 현상을 보고했다. 앞선 원본 보존 정책을 마지막 저작 참조 삭제 시 제거하는 정책으로 변경했다.
다른 SubGraph 노드나 내장 포트가 같은 원본을 참조하면 그 원본은 유지한다.

삭제 명령의 트랜잭션에서 저작 EdGraph 노드를 기준으로 사용처를 모으고 미참조 원본을 소유 목록에서 제거한다.
제거한 객체는 transient 패키지로 옮기되 파괴하지 않아 Undo로 원본 내용과 노드를 함께 복구할 수 있다.
이전 정책으로 남은 미참조 원본은 그래프를 열 때 같은 기준으로 정리하고 변경 상태를 남긴다.
잘라내기에서는 붙여넣기 전 클립보드의 경로가 끊어지지 않도록 즉시 정리를 생략한다.

엔진 툴킷은 저장 레이아웃 복원을 제공하고 크기 변경 저장을 지연할 수 있다. 그래프 편집기에는
닫기 요청이 승인된 직후, 도킹 영역이 해체되기 전에 `SavePersistentLayout()`을 호출하도록 추가했다.
직전 UI 변경에서 레이아웃 키를 v4에서 v5로 바꿨으므로 이전 키의 배치는 한 번 초기화될 수 있다.
이번 수정에서는 v5를 유지한다. 사용자 현상의 정확한 재현 조건과 수정 후 복원 결과는 확인하지 않았다.

관련 근거는 `FKataGraphAssetEditor::OnRequestClose`, `RemoveUnusedEmbeddedSubGraphs`,
`KataEmbeddedSubGraphEditor::RemoveUnused`다. 에이전트는 이번 후속 수정의 빌드·테스트·별도 검사를 실행하지 않았다.
manual과 plan의 삭제 계약을 갱신했으며 GitHub 게시·커밋은 수행하지 않았다.

## 후속 변경: 마우스 뒤로가기

사용자가 뒤로가기 버튼으로 부모 그래프에 돌아가도록 요청했다. 그래프 화면의 마우스 뒤로가기 버튼으로 해석해
SGraphEditor의 `OnNavigateHistoryBack`에 `NavigateBack`을 연결했다.
내장 편집 중에는 기존 예약 전환 경로로 부모 페이지를 열고, 부모 페이지에서는 전환하지 않는다.
별도 탐색 이력이나 앞으로가기 동작은 추가하지 않았다. 이번 입력 연결의 빌드·UI 실행은 미확인이다.

## 남은 제한과 연관 문서 반영

- 이 UI 변경 당시 내부 원본 재구성·평탄화와 단일 노드의 입출력 실행 연결은 후속 3단계였다.
  이후 LightAttack 미실행 보고에 대응한 [저장·실행 연결](2026-10-06-Embedded-SubGraph-Runtime.md)을 추가했다. 실행 결과는 미확인이다.
- 붙여넣기 후 참조 정리·전체 에셋 복제·저작 연결을 사용하는 자동 배치는 후속 범위다.
  이후 [편집 동작 보완 기록](2026-10-06-Embedded-SubGraph-Editing.md)에 붙여넣기와 배치 변경을 추가했다. 전체 에셋 복제의 실행 확인은 남아 있다.
- [에디터 사용법](../manual/Editor-Usage.md)과 당시 설계 계획(종료 후 삭제), [문서 목록](../README.md)에 변경을 반영했다.
- [#27](https://github.com/jaykop/Kata/issues/27) 댓글·라벨은 변경하지 않았다. 공개 게시는 초안 확인 후 수행한다.
