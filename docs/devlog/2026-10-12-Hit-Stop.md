# 히트스톱

작성: 2026-10-12  
갱신: 2026-10-12  
유형: 구현 기록 / 결정 기록  
대상: KataFramework `UKataHitHandler_ApplyGameplayEffect`, `UKataCombatSettings`  
기준: #72 구현 커밋. 같은 날 사용자 Editor 빌드·실행 확인 결과 포함

## 배경과 결론

[피격 반응 계획](../plan/Hit-Reaction-Plan.md)의 HR9로 피해가 실제로 들어간 순간 공격자와 피격자만 잠깐 멈추는 히트스톱을 구현했다.
실행 위치(처리기에서 `WasSuccessfullyApplied()` 확인 뒤)와 시간 배율 요청 사용은 plan에서 이미 확정했고, 이번 작업에서는 값의 위치와 기본값을 정했다.

## 변경 또는 진단 내용

| 항목 | 이전 상태 | 반영 결과 |
|---|---|---|
| 처리기 | `Apply Gameplay Effect` 처리기가 GE 적용 결과를 버렸다 | 반환 핸들이 성공이고 `Hit Stop Duration`이 0보다 크면 공격자·피격자에게 `UKataTimeDilationSubsystem` 액터 요청을 건다. 요청은 Duration으로 풀리며 핸들을 보관하지 않는다 |
| 설정 | 없음 | Kata Combat의 Hit Stop 항목 `Hit Stop Time Dilation`(0.05)·`Hit Stop Priority`(100) |
| 샘플 | 없음 | `KA_BlackKnight_Attack01`의 두 Hit Trace 처리기에 0.08초 |

## 주요 결정과 이유

- **정지 시간은 처리기, 배율·Priority는 Combat 설정(사용자 결정).** plan이 공격별 값으로 정한 것은 시간뿐이다. 배율까지 처리기에 두면 공격 에셋마다 같은 값을 반복 입력하게 된다. 방어 결과 행의 "히트스톱 배율"([#87](https://github.com/jaykop/Kata/issues/87))도 공격별 시간에 곱하는 방식이라 이 구조와 맞는다.
- **기본 배율 0.05(사용자 결정).** 0도 Duration으로 반드시 풀려 허용되지만, 액션 프리뷰 탐색은 Kata 시각 단계를 배율로 나눠 월드를 진행하므로 배율이 아주 작으면 단계 수 상한에 걸린다([시간 배율 요청 사용법](../manual/Time-Dilation.md)). 0.05는 눈으로는 정지에 가깝고 이 문제를 피한다.
- **Priority 100.** Time Dilation 태스크의 기본 Priority 0보다 높여, 슬로모션 구간 중 맞아도 짧고 강한 히트스톱이 이기게 했다. 히트스톱이 끝나면 남은 슬로모션 요청이 다시 적용된다.
- **핸들 미보관.** 처리기는 공유 태스크 에셋의 일부라 실행 상태를 저장할 수 없다. Duration 요청은 Subsystem이 스스로 정리하므로 보관할 필요가 없다.

## 남은 제한과 후속 작업

- 멈추는 공격자는 Kata Context의 Avatar다. Kata 실행기를 소유한 액터가 Avatar와 다르면 실행기 타임라인은 멈추지 않는다. 처리기 시그니처에 실행 인스턴스가 없어 현재는 제한으로 둔다.
- 처리기를 거치지 않는 피해(낙사·환경 피해)에는 걸리지 않는다. 방어 결과별 배율은 #87에서 다룬다.
- 다른 샘플 공격에는 아직 값을 넣지 않았다.
