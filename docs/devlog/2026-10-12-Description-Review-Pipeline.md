# Claude 작성·Codex 설명 검토 파이프라인

작성: 2026-10-12  
갱신: 2026-10-12  
유형: 결정·구현 기록  
대상: 자체 코드 주석·manual·태그 DevComment의 작업별 기록과 부분 교정  
기준: 2026-10-12 작업 트리. 앞선 태그·manual 교정과 이번 도구·지침 변경은 미커밋이다.

## 배경과 결론

Claude가 기능을 구현하면서 추가·변경한 주석과 manual, 태그 설명을 Codex가 교정할 때 매번 프로젝트 전체를 읽으면 범위와 비용이 커진다. 사용자가 변경 부분을 공유 목록으로 남기는 제안을 수용했다. 작성자가 설명 변경과 로직의 영향을 기록하고, Codex가 대기 항목의 문맥·관련 구현을 대조하는 절차를 적용했다.

## 변경 내용

- 작업마다 localdocs에 설명 검토 목록을 남긴다. 명시적 작업 파일의 시작 상태·기준 커밋과 기존 변경을 기록하고, 작업 종료 때 바뀐 파일·diff 구간을 캡처한다.
- 항목의 태그·문서 제목·선언 등 의미 있는 anchor로 설명과 관련 구현을 지정한다. 블록 내용의 SHA-256을 비교하므로 무관한 줄 이동만으로 다시 검토하지 않는다.
- 검토 시작 시 token과 스냅샷을 기록하고, 완료 시 관련 구현이 그대로인지와 최종 설명 해시를 확인한다. Codex가 직접 고친 문장은 최종 내용으로 기록하고 이후 변경은 다시 대기로 돌린다.
- 기록 중 잠금과 내용 비교로 다른 목록 쓰기를 덮어쓰지 않는다. 설명에 영향이 없는 변경도 이유를 남기고, 항목이 없는 변경 파일은 알림으로 보여 준다.
- 실제 목록 갱신 중 Windows의 파일 교체가 한 번 거절됐다. 내용을 다시 확인하며 제한적으로 재시도하도록 바꿨고 이후 capture가 완료됐다. 계속 거절되면 오류로 종료한다. 임시 쓰기·잠금 파일은 Diversion에서 제외했다.
- 공용 AGENTS.md, Claude의 feature-impl·feature-doc-sync·doc-polish와 Codex 전용 description-delta-review를 연결했다. 기능 작업의 사용자 빌드 확인이나 문서화 후속 질문 전에도 인계 기록을 남기게 했다.
- feature-doc-sync의 별도 내장 템플릿을 제거하고 실제 카테고리 템플릿을 사용하게 했다. 개인 시행착오가 공개 devlog로 자동 이동하던 안내는 localdocs 유지 규칙에 맞췄다.

## 결정과 이유

기록 도구는 의미를 판정하지 않고 범위·변경·스냅샷을 관리한다. 주석 구문 전체를 자동 해석하기보다 작성자가 anchor와 근거를 정하는 방식으로 시작했다. 로직 변경으로 오래된 설명이 생기는 경우는 단순 diff 추출로 찾을 수 없으므로 Claude가 영향 항목이나 영향 없음의 이유를 남긴다.

공유 목록은 기존 localdocs 정책대로 Git에서 제외하고 Diversion에서 추적한다. 도구와 사용법·공용 지침은 공유 소스·문서이며, 로컬 스킬은 기존 추적 제외 정책을 유지한다. 작업 상태는 GitHub Issue, 설명 검토 상태는 목록으로 구분한다. AI 간 자동 메시지·자동 실행·커밋 차단 훅은 추가하지 않았다.

## 남은 제한

파일 단위 미등록 알림은 같은 파일 안의 누락 항목을 모두 찾지 않는다. 시작 전에 수정되어 있던 파일은 해시·상태만 기록하므로 이전 변경과 이번 변경의 의미상 구분은 작성자가 남긴 위치·이유에 의존한다. anchor를 찾지 못하면 해당 항목은 대기하며 위치를 바로잡아야 한다. 사용자 빌드·문장 품질 확인은 스냅샷 일치로 대체할 수 없다.

## 연관 문서 반영

사용법과 형식은 새 Description-Review manual에 두고 docs/README에 등록했다. 공용 지침은 절차와 진입점만 유지하며 상세 명령을 복사하지 않았다. 런타임 동작·에셋 사용 계약은 바뀌지 않아 게임 기능 manual에는 추가 변경이 없다. 공개 이슈 게시 초안은 로컬에 준비하며 사용자 게시 확인 전에는 외부에 올리지 않는다.
