# 그래프 실행 불가 노드 타입 결정

작성: 2026-10-16  
갱신: 2026-10-16  
유형: 결정 기록  
대상: KataGraph 전이 해석, Conduit·Alias·SubGraph 포트 노드  
기준: [#25](https://github.com/jaykop/Kata/issues/25) 종료(2026-10-05) 시점의 결정. [#76](https://github.com/jaykop/Kata/issues/76)에서 삭제한 `docs/plan/Graph-Node-Types-Plan.md`(2026-09-26 작성, 2026-10-16 갱신)의 결정을 옮긴 기록

## 배경과 결론

콤보 그래프에서 출발지 N개와 목적지 M개를 직접 이으면 엣지가 N×M개가 되고, 공통 조건도 엣지마다 반복된다. 액션을 실행하지 않는 노드 타입을 도입해 엣지를 N+M개로 줄이고 공통 조건을 한 곳에 모으기로 했다. 이런 노드는 상태가 아니라 전이를 해석하는 동안만 지나가는 지점이다.

전이 해석 단계, Conduit, Alias(Any State 포함), SubGraph 포트와 평탄화를 구현했고 Reroute는 도입하지 않았다. 현재 사용법은 [에디터 사용법](../manual/Editor-Usage.md)과 [런타임 사용법](../manual/Runtime-Usage.md)을 따른다.

## 주요 결정과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| 상태와 경유의 구분 | `UKataNode::IsExecutableState()`가 정한다. 기본값은 false이고 `UKataActionNode`만 true다 | 액션 하나가 곧 상태 하나라는 전제를 타입으로 드러내, 이후 추가할 실행 불가 노드가 같은 규칙을 따르게 한다 |
| 출발지 자격 | 머무를 수 있는지와 Alias 출발지가 될 수 있는지를 따로 둔다 | SubGraph Port Out은 머무를 수 없지만 펼치면 머무를 수 있는 노드가 되므로 출발지 자격은 참이다 |
| 전이 해석의 원자성 | `UKataGraphInstance::ResolveExecutableTarget()`이 실행 가능한 노드까지 내려가며 지나는 모든 EntryCondition과 엣지 Condition을 확인한다. 한 곳이라도 막히면 전이가 성립하지 않는다 | 경유 노드에는 머무를 수 없기 때문이다 |
| 순환 방어 | 갈래마다 방문 기록을 복사해 내려간다 | 한 갈래에서 지난 노드가 다른 갈래를 막지 않으면서 순환 그래프에서도 끝난다 |
| Conduit 출구 엣지 | Required Window Tag와 Timing을 보지 않는다. 트리거가 비었거나 같으면 통과하고, 우선순위는 첫 엣지 값으로 경쟁한다 | 떠나는 액션이 없고 트리거는 첫 엣지에서 이미 받았다. 경유 경로와 직결 경로를 같은 기준에서 비교한다 |
| Alias 대상 선정 | 노드 목록과 `bAnyState` 토글. Any State는 별도 타입이 아니라 Alias의 한 모드다. 목록에 Port Out도 넣을 수 있다 | 서브그래프 여러 개를 묶거나 일반 노드와 섞을 때 필요하다 |
| Alias 출발 엣지 | Required Window Tag와 Timing을 그대로 적용한다 | Alias는 현재 액션을 떠나는 순간이고, Conduit은 이미 떠난 뒤의 경로다 |
| SubGraph 방식 | 컴파일 시 부모 그래프로 펼치는 평탄화 | 실행기를 바꾸지 않고 "액션 하나 = 상태 하나" 전제를 유지한다. 중첩 실행 인스턴스는 현재 위치가 두 인스턴스로 쪼개진다 |
| SubGraph 포트 구조 | 같은 서브그래프를 가리키는 포트를 여러 개 놓을 수 있고, 펼치면 사본은 한 벌만 생긴다 | 진입 지점은 쓰는 노드 옆에, 이탈 지점은 목적지 옆에 두어 긴 엣지를 없앤다 |
| 포트의 런타임 대응 | Port In은 Conduit처럼, Port Out은 Alias처럼 해석된다. 둘 다 펼칠 때 사라진다 | `UKataGraphInstance`에 새 기계장치가 필요하지 않다 |
| 포트를 Conduit·Alias에 얹지 않음 | 별도 노드 클래스로 둔다 | 연결 규칙이 반대다. 한 클래스에 조건부 규칙을 섞으면 에디터가 잘못된 연결을 막을 수 없다 |
| 포트 노드 구성 | 추상 기반 `UKataSubGraphPortNode`와 `UKataSubGraphPortInNode`·`UKataSubGraphPortOutNode` | 방향을 프로퍼티로 두면 연결 뒤 방향을 바꿔 조용히 깨진 상태가 생긴다 |
| 사본의 원천 | 서브그래프의 런타임 그래프를 `DuplicateObject`로 복사한다 | `Rename`은 원본 에셋에서 노드를 빼앗아 온다 |
| 재컴파일 시점 | 부모 그래프 저장 시 `RebuildKataGraph()` 안에서 펼친다 | 이미 그 시점에 도는 단계다. 낡은 사본 처리는 [중첩과 외장 의존 갱신 기록](2026-10-07-Nested-SubGraph-Dependencies.md)을 따른다 |
| 포트의 내장·외장 선택 | 토글 하나와 필드 둘. 꺼진 쪽은 `EditConditionHides`로 숨긴다 | 한 필드로 합치면 에셋 브라우징까지 직접 만들어야 한다. 구현은 [#27](https://github.com/jaykop/Kata/issues/27) |

### 도입하지 않은 것과 재검토 조건

| 항목 | 재검토 조건 |
|---|---|
| Alias를 태그로 선정(ByTag) | 출발지 집합은 언제나 그 그래프 안에 있다. 공용 서브그래프 안에서 부모의 부분집합을 가리켜야 하는 상황이 실제로 생기면 다시 본다 |
| 자기 전이 허용 옵션 | 쓸 사례가 확인되지 않았다. 추가해도 기본값이 지금 동작이라 직렬화된 에셋에 영향이 없다 |
| 포트 이름 규칙 | 입구 선택은 각 진입 노드의 조건과 엣지 우선순위가 가른다. 입구가 여럿인 서브그래프를 실제로 만들 때 `UKataEntryNode` 런타임 이름과 Exit 노드 타입을 함께 도입한다 |
| 같은 서브그래프 두 벌 | 포트마다 엣지·조건이 따로라 맥락 차이는 이미 표현된다. 필요하면 포트에 인스턴스 이름을 더한다 |
| Reroute 노드 | 2026-10-03 결정. 엣지가 조건을 가진 노드라 시각용 Reroute는 조건 소유 규칙을 새로 요구한다. 포트 중복 배치·Alias·Comment·출구를 비운 Conduit으로 풀리지 않는 꼬임이 생기면 에디터 전용 Reroute나 엣지 경유점을 다시 본다 |
| 그래프 병렬 실행 | 상·하체처럼 두 줄기가 동시에 도는 구조는 평탄화로 표현할 수 없는 별개 기능이다 |

## 남은 제한과 후속 작업

- 경유 노드가 막다른 길이면 전이가 조용히 성립하지 않는다. 에디터 검증은 없다.
- 펼쳐진 노드는 사본이라 런타임에 어느 서브그래프에서 왔는지 드러나지 않는다.
