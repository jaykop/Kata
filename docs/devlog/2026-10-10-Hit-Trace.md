# Hit Trace 설계 결정

작성: 2026-10-10  
갱신: 2026-10-10  
유형: 결정 기록  
대상: KataFramework `HitTrace`, `UKataTask_HitTrace`, `KataFrameworkEditor` 프리뷰 토글  
기준: [#6](https://github.com/jaykop/Kata/issues/6) 구현 커밋(37510a5, c1b97b9 등)과 2026-10-10 작업 트리. 삭제한 Hit Trace 계획(2026-09-24 작성, 2026-10-04 갱신)의 결정 사항을 옮겼다.

## 배경과 결론

액션 타임라인의 한 구간 동안 공격 판정을 하는 Hit Trace 태스크를 KataFramework에 구현했다.
판정 기준 메시를 정하는 방법, 저프레임·빠른 동작에서 대상을 놓치는 문제, 판정 결과를 GE·이벤트로 넘기는 경로,
태스크 Tick 시점에 이번 프레임 포즈가 확정되지 않는 문제를 해결해야 했다.
현재 사용법은 [Hit Trace 사용법](../manual/Hit-Trace.md)에 있다. 사용자가 2026-10-10에 실행 확인을 마쳤다고 보고했다.

## 주요 결정과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| 플러그인 위치 | KataFramework | 태스크가 코어에 있을 필요가 없다. 엔진 `TargetingSystem` 의존이 생기므로 코어에 넣지 않는다 |
| 판정 방식 | SocketTrace와 ShapeSweep 둘 다 | 칼날처럼 긴 판정과 주먹·둔기처럼 덩어리 판정이 모두 필요하다 |
| SocketTrace 구성 | 소켓 목록(2개 이상) | 직선 칼날은 2개, 휜 칼날은 휘는 지점마다 소켓을 더해 같은 구조로 표현한다 |
| SocketTrace 판정 | 이전·현재 소켓 점으로 만든 삼각형 띠와 대상 도형의 직접 교차 | 1차 구현은 소켓마다 경로를 선으로 추적해 경로 사이에 빈틈이 있었다. 얇은 상자 스윕 같은 엔진 스윕 근사는 HurtBox 도입 때 다시 써야 해서 택하지 않았다 |
| 판정 대상 | `UKataHurtBoxComponent`만 | Physics Asset 바디보다 부위·속성을 명시적으로 다룰 수 있다. Physics Asset·일반 콜리전 경로는 없앴다 |
| HurtBox 조회 | 전용 Object Type 질의 | 판정이 묻는 것은 "무엇에 반응하는가"가 아니라 "HurtBox인가"다. HurtBox는 모든 채널을 무시한다 |
| HurtBox 설정 위치 | KataFramework `UKataHitTraceSettings`의 `HurtBoxCollisionProfile` 하나 | 프로필 하나가 기본 콜리전과 판정 Object Type을 함께 정한다. 코어에 공용 설정을 두면 의존 방향을 어긴다(선례 `UKataFactionSettings`). 채널 정의는 프로젝트가 소유한다 |
| HurtBox 도형 | `UPrimitiveComponent` 하나로 Sphere·Capsule·Box | 엔진 `UShapeComponent`의 BodySetup 생성 도우미가 모듈 밖에 공개되지 않아 BodySetup을 직접 만든다 |
| HurtBox 태그 | `HurtBoxTags`와 프리셋 `HurtBoxTagQuery` | 약점·판정 제외 같은 속성을 프로젝트가 정한다. 태그 검사는 대상 1회 규칙보다 먼저 한다 |
| 기준 메시 제공 | `UKataHitBoxComponent`가 보관 | 인터페이스 없이 어떤 액터에도 붙일 수 있다. 무기는 장비 슬롯 태그 키로 등록한다(#30 EQ-4에서 `SetWeaponMesh`를 대체) |
| HitBox 정의 위치 | `UKataHitBoxPreset` 에셋에만 | 같은 무기를 쓰는 여러 공격이 정의를 공유한다 |
| 결과 처리 구조 | 태스크는 판정만 하고 `UKataHitSubsystem`이 같은 프레임에 제출 순서대로 처리기 호출 | 정상 완료 뒤 마지막 판정이 태스크 인스턴스가 끝난 뒤에 일어나므로 히트 목록과 직전 포즈를 Subsystem 등록 항목이 가진다 |
| 처리기 | 태스크가 Instanced `UKataHitHandler` 배열 보유, 기본 처리기 두 종 | 피해 수치는 GE가 가진다. Kata 에셋에 데미지 값을 넣지 않는다 |
| 스윕 실행 시점 | Subsystem(`UTickableWorldSubsystem`) Tick | UE 5.8 `LevelTick.cpp`에서 `TickObjects`가 `TG_PostPhysics` 뒤에 실행된다. `TG_PrePhysics`에서 Tick하는 `UKataActionComponent`보다 늦어 `AfterMeshPose` 훅 없이 이번 프레임 포즈를 읽는다 |
| 서브스텝 | 거리·각도 기준 분할, 기본 20cm·15°·상한 32 | 20fps 로그에서 칼끝이 한 프레임에 약 290cm 움직인 공격이 10fps까지 상한에 걸리지 않는다 |
| 프레임 사이 포즈 보정 | 활성 몽타주 원본 재샘플링과 양 끝 차이값 보간 | 서브스텝 직선이 호 궤적을 근사하는 한계를 줄인다. 베이크 궤적 대신 런타임 재샘플링을 택했다. 압축 데이터를 써서 패키징 빌드에서도 동작한다 |
| 첫 프레임 직전 포즈 | `UKataHitBoxComponent`가 매 프레임 기록 | 태스크 인스턴스는 구간 시작 시각에 생겨 그 전 프레임을 기록할 수 없다. 엔진 직전 본 버퍼는 본 트랜스폼 리비전이 정확히 1 늘었을 때만 유효로 본다(텔레포트는 2 증가) |
| 시작·종료 판정 | `bCheckOnStart`, 정상 완료만 종료 시각까지 잘라낸 마지막 판정 | 프레임보다 짧은 구간도 최소 한 번 판정한다. 취소된 공격이 마지막에 맞히지 않게 한다 |
| 대상 필터 | Filter 태스크만 담은 `UTargetingPreset`을 직접 Init·Execute | `UTargetingSubsystem`은 GameInstance Subsystem이라 프리뷰 월드에 없다. 팩션은 KataTargeting의 Kata Filter Faction을 그대로 쓰므로 Hit Trace 코드에 KataTargeting 의존이 없다 |
| 프리뷰 | EditorPreview 월드에서도 Subsystem 생성 | 프리뷰에서 런타임과 같은 경로로 판정·처리기를 실행한다 |
| 디버그 | `ENABLE_DRAW_DEBUG` 안에 두고, 게임은 CVar `Kata.HitTrace.Debug`, 프리뷰는 `KataFrameworkEditor` 툴바 토글 | 디버그 기능은 구현한 모듈에 둔다. 코어 변경은 프리뷰 툴바 메뉴 이름 공개 하나뿐이다 |

미룬 범위: 다단히트 `ReHitInterval`, 태스크 간 히트 목록 공유, HitScan, 투사체, 태스크 출력 채널, 피격자 쪽 처리기(가드·패리), 히트스톱.
히트스캔은 전용 Trace Channel을 두고 HurtBox 프로필에 Block을 더하고, 이동 투사체는 전용 Object Type을 두고 Overlap을 더하는 방향으로 정리해 두었다(구현 전).

## 진단 기록

- HurtBox 1차 구현은 `GetBodySetup`에서 물리 상태를 다시 만들었다. 바디가 이중으로 초기화되고 소유 컴포넌트가 사라진 바디가 씬에 남아,
  질의 결과의 컴포넌트가 None으로 나오고 정상 HurtBox가 맞지 않았다. `GetBodySetup`은 BodySetup만 채우도록 고쳤다(2026-09-26).
- 프리뷰 액터는 BeginPlay를 받지 않아 포즈 기록이 빠지고 저프레임 판정 구간 절반이 누락됐다. 컴포넌트 등록을 `OnRegister`로 옮겼다.
