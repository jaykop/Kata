## 배경과 결론

사용자가 게시된 이슈와 구현 상태를 바탕으로 마일스톤과 목표를 정하자고 요청했다. 만들 게임의 장르는 정하지 않았고, Kata는 어떤 액션 게임이든 만들기 위한 기반이며 게임은 Sample 프로젝트에 구현한다. 외부 공개 목표는 없다.

결정한 내용은 다음과 같다.

- 기간 목표를 GitHub Milestone 세 개(M1 전투 샌드박스, M2 범용성 검증, M3 버티컬 슬라이스)로 관리하고 로드맵 이슈 #24를 닫았다.
- 이슈 순서를 중요도 a와 규모 b의 곱으로 정하고, 선행 작업은 자기가 막는 작업의 등급을 물려받게 했다.
- 순서표와 규칙 위반을 보여 주는 `Scripts/IssuePriority.py`를 만들었다.
- 이슈 목록에 없던 작업을 진단해 새 이슈로 만들고 열린 이슈 전체를 다시 배정했다.

## 주요 결정과 이유

### Milestone과 구성

- 로드맵 이슈는 순서를 손으로 유지해야 했고 기간이 없었다. Milestone은 마감과 진행률을 제공하고 이슈 하나를 하나의 마일스톤에만 배정하므로, 기간을 정한 목표에 맞는다(사용자 결정).
- 장르와 무관한 기반을 먼저 마무리하고(M1), 형태가 다른 샘플 두 개로 Kata의 범용성을 확인하면서 장르를 정한 뒤(M2, G1), 정한 장르로 루프 하나를 만든다(M3). 장르 탐색과 기반 검증이 같은 작업이 되도록 했다.
- 외부 공개 목표가 없어 공개 데모 단계는 두지 않았다. 백뷰 근접 형태는 M1의 샌드박스가 곧 기준 샘플이라 별도 스파이크에서 뺐다.
- 상호작용·레벨 이벤트·퀘스트·인벤토리처럼 장르에 따라 범위가 달라지는 시스템은 백로그에 두고, 샘플이 요구할 때 마일스톤으로 옮긴다. 쓰는 곳 없이 만들면 추상화를 잘못 잡을 위험이 크다.

### 중요도×규모 등급

- 사용자가 정한 규칙은 작업 자체의 우선순위 a, 작업의 규모 b, a×b로 정하는 최종 등급, 선행 작업에 따른 순서 변경이다. 사용자가 언급한 "Ben's Matrix"의 공개 정의는 찾지 못해 이 규칙을 기준으로 설계했다.
- 규모 점수는 작을수록 높게 뒤집었다(S 3, M 2, L 1). 그대로 곱하면 큰 작업이 앞에 서기 때문이다. 이렇게 하면 L을 M 두 개로 나눌 때 등급이 올라 작게 쪼개기를 유도한다. 8시간을 넘는 XL은 등급 없이 하위 이슈로 나눈다.
- 규모는 코드 양이 아니라 사용자가 직접 손대는 시간(빌드·확인, 에디터 작업, 결정)으로 잰다. 구현은 에이전트가 맡으므로 병목은 사용자의 시간이다. 경계는 작업 세션 단위(짧은 세션, 긴 세션, 한 주)에 맞췄다. 불확실한 작업은 한 단계 크게 잡는다.
- 두 축 모두 3단계로 두었다. 경계가 실제 세션 단위와 맞고, 몇 시간짜리 추정 오차보다 잘게 나눌 수 없으며, 마일스톤당 이슈가 10~15개라 동점은 a와 선행 관계로 충분히 갈린다.
- 등급 표기는 A1·A2·B1·B2·C1·C2로 했다. 처음 제안한 "A·6"처럼 점수를 붙이면 숫자가 클수록 먼저인지 작을수록 먼저인지 헷갈렸다. 작을수록 먼저인 관례에 맞췄다.
- 3단계 체계는 다 필수로 매기기 쉽다. 필수 이슈 규모 합이 마일스톤 용량의 60%를 넘으면 이슈를 빼기보다 목표를 줄이도록 했다. 합산은 칸의 가운데 값(S 1, M 2, L 5.5시간)으로 한다. 상한으로 더하면 M1·M2가 모두 경고에 걸려 경고가 신호 역할을 하지 못했다.
- C 등급은 마일스톤에 두지 않는다. 중요한데 큰 일(중요·L)은 쪼개면 B가 되고, 선택이면서 시간이 드는 일은 백로그가 맞다.

### 선행 작업과 라벨

- 선행 작업이 자체 등급만으로 정렬되면, A 작업을 막는 B·C 작업이 뒤로 밀려 A가 계속 막힌다. 그래서 선행 작업은 자기가 막는 열린 이슈 중 가장 높은 등급을 유효 등급으로 물려받는다.
- 선행 관계는 GitHub 기본 Blocked by로 저장한다. 이 저장소에서 REST와 GraphQL 모두 동작하는 것을 확인했다.
- grade 라벨은 자체 등급만 기록한다. 유효 등급은 선행 관계가 바뀔 때마다 달라지므로 스크립트가 실행할 때 계산한다.
- 채택하지 않은 대안: GitHub Projects 보드(필드 간 계산을 지원하지 않고 관리 도구가 하나 늘어난다), 4·5단계 척도(추정 정밀도보다 세밀하다), 점수 라벨(등급과 중복된다).
