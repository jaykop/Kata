# 작업 상태 관리 통합

작성: 2026-10-03  
갱신: 2026-10-03  
유형: 결정 기록  
대상: 작업 추적·문서·에이전트 지침  
기준: 관련 미커밋 변경을 포함한 작업 트리

## 배경과 결론

사용자는 GitHub Issue로 작업 현황을 관리하는 상황에서 전체 구현 상태 문서가 계속 커지고 관리되지 않는 문제를 지적했다. 별도의 `Implementation-Status.md`를 폐지하고 작업 상태를 Issue로 통합하기로 확정했다.

## 주요 결정과 이유

- 구현 범위, 진행·완료 상태, 사용자 확인 여부와 후속 작업은 GitHub Issue에서 관리한다. 외부 게시 전 사용자 확인 절차는 유지한다.
- 현재 사용법과 제한은 manual, 중요한 변경과 결정 이유는 devlog, 미확정 설계는 연결 이슈의 plan에 기록한다. 전체 구현 상태 요약은 다시 만들지 않는다.
- 기존 상태 문서의 미커밋 기록과 과거 확인 결과는 추적에서 제외한 `docs/localdocs/`에 동결 보존한다. 새로운 현황 기록에 사용하지 않는다.
- 사용자의 추가 요청에 따라 작업별 thread와 완료 archive를 `docs/localdocs/threads/`, `docs/localdocs/archive/`로 옮긴다. 새 작업 시작 시 작업별 파일을 만들거나 갱신하고 같은 작업은 이어 쓴다.

## 근거와 연관 문서 반영

- [공용 지침](../../AGENTS.md): 상태 문서 의무 제거, 문서 역할과 작업 시작 시 로컬 인계 규칙 반영.
- [문서 목록](../README.md): 현재 상태의 진입점을 Issue로 변경.
- [스포너 사용법](../manual/Spawner.md): 기존 상태 문서에만 있던 생성 설정과 미리보기 안내 반영.
- 로컬 에이전트 스킬·안내와 문서 템플릿도 같은 역할 및 thread 경로로 변경했다.
- 과거 devlog의 당시 기록은 보존하고 폐지 안내와 보존본 링크를 붙였다. 보존본은 다른 환경에서 열 수 없는 로컬 자료다.

## 확인 범위와 남은 제한

이번 작업은 문서와 지침 정리다. 빌드·테스트·PIE는 실행하지 않았다. 기존 사용자 확인 기록을 새 검증 결과로 취급하지 않는다. GitHub 이슈 생성·댓글·라벨 변경은 수행하지 않았다.
