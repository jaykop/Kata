# 내장 SubGraph 중첩과 외장 의존 갱신

작성: 2026-10-07  
갱신: 2026-10-07  
유형: 구현 기록 / 결정 기록  
대상: KataGraph, KataGraphEditor  
기준: #27의 기존 미커밋 구현에 이어 수정한 작업 트리

## 배경과 결론

사용자는 독립 복제 변경의 테스트 완료를 보고한 뒤 내장 안에서 다시 내장을 만들 수 있는지 질문했다.
기존의 한 단계 제한과 다음 단계 SG5의 외장 갱신을 함께 확장하는 순서를 설명했고,
사용자가 "ㅇㅋ 그럼 작업 진행 ㄱㄱ"로 진행을 승인했다.

각 페이지가 직계 내장을 소유하는 구조를 유지하면서 생성 깊이를 확장했다. 실행은 저장 시 평탄화를 유지한다.
외장 원본과 전이 의존의 저장 세대를 기록하고, 미저장·오래된 의존 사본을 부모가 최신 실행 데이터로 받아들이지 않도록 했다.
이 기록은 소스 구현 기준이며 이번 확장의 빌드·실행 확인 결과는 없다.

## 변경 내용

| 항목 | 이전 | 반영 결과 |
|---|---|---|
| 생성·선택 | 루트 바로 아래 한 단계 | 유효한 소유 트리의 모든 페이지에서 생성. 선택 후보는 그 페이지의 직계 자식 |
| 탐색 | 내장에서 루트 복귀 | 마우스 뒤로가기는 직계 부모, 상단 에셋 버튼은 루트. 현재 내장 경로 표시 |
| 복사 | 하위 내장이 없는 원본만 복사 | 소유 트리 전체를 한 번 복제해 내부 참조를 재매핑하고 각 페이지의 실행 사본을 제거 |
| 삭제·Undo | 루트의 원본 목록만 처리 | 페이지별 미참조 원본 제거, 각 원본의 소유 페이지를 약한 참조로 기억해 Undo에서 Outer 복구 |
| 저장 | 직접 내장만 로컬 빌드 | 루트 트리 전체를 가장 안쪽부터 빌드. 외장 원본은 재구성하지 않음 |
| 외장 최신성 | 저장 순서에 의존, 별도 표시 없음 | 루트의 저장용 빌드 세대와 외장·전이 의존 세대 기록. 상단 안내와 루트 dirty 상태 갱신 |
| 저장 훅 | 열린 툴킷마다 PreSave 등록 | 모듈의 PreSave 한 경로. 닫힌 그래프 저장에도 적용하며 쿠킹은 저장된 실행 데이터 사용 |

## 주요 결정과 이유

`OwnsEmbeddedSubGraph()`는 직계 소유 계약을 유지한다. `ContainsGraph()`와 `GetRootGraph()`는
목록과 Outer가 모두 일치하는 경로만 유효하게 본다. 다른 페이지의 형제·조상 내장 참조는 허용하지 않는다.
중첩 깊이에 인위적인 UI 제한을 추가하지 않았으며, 런타임 중첩 인스턴스도 추가하지 않는다.

복사할 때 전체 저작 트리를 한 번 복제해야 같은 원본을 가리키는 하위 포트와 노드의 공유 관계가 새 트리 안에서 유지된다.
각 페이지의 `AllNodes`, `RootNodes`, 실행 연결과 별칭의 실행 출발지는 비운다. 액션 에셋과 유효한 외장 참조는 유지한다.
붙여넣기는 하위 노드 GUID와 트랜잭션 상태를 함께 준비하고 대상 소유 관계에서 참조를 정규화한다.

삭제한 원본은 하위 트리를 유지한 채 transient로 옮긴다. 약한 원본→소유 페이지 맵으로 복구 위치를 기억한다.
현재 편집 페이지가 분리되면 가장 가까운 유효한 부모로 돌아간다. Undo 대상에 `MarkAsGarbage()`를 적용하지 않는다.

세대는 루트의 저장용 사전 검사를 통과하고 실행 데이터를 재구성한 뒤 FGuid로 발급한다.
메모리 갱신과 내장 클립보드 사본은 저장 기준을 새로 발급하지 않는다.
외장 B가 C의 이전 세대를 담고 있으면 최종 부모 A도 B를 최신으로 받아들이지 않는다.
외장 dirty 상태, 기존 세대 누락, 잘못된 참조와 순환은 실행 데이터를 지우기 전에 판정한다.

열린 편집기는 약 1초 간격으로 현재 저작 참조와 저장 기록을 비교한다. 갱신 상태를 표시하고 루트를 dirty로 만들며
상태 감지 자체는 다른 에셋을 빌드·저장하지 않는다. 창이 닫힌 부모는 다음 개봉에서 판정한다.
원본 내용이 같아도 다시 저장해 세대가 바뀌면 부모 갱신을 요구하는 보수적 정책이다.

## 후속 수정: 저장한 부모의 dirty 반복

사용자가 외장 SubGraph를 연결하고 저장했는데 다시 dirty가 된다고 보고했다.
상태 갱신 코드는 안내가 비어 있지 않으면 종류와 관계없이 매초 `MarkPackageDirty()`를 호출했다.
미저장 원본·기존 세대 누락·잘못된 참조 등으로 재구성이 중단돼 경고가 남으면
부모의 파일 저장 뒤에도 다시 dirty가 켜지는 경로가 있었다. 사용자의 실제 안내 문구는 아직 받지 않았다.

`GetDependencyStatus()`가 경고 문구와 부모 갱신 가능 여부를 따로 반환하도록 수정했다.
사전 검사를 통과하고 부모의 저장 세대·의존 기록이 낡았을 때만 갱신 필요를 반환한다.
갱신을 막는 원본 경고는 표시를 유지하되 저장한 부모를 반복 dirty로 만들지 않는다.
원본을 수정한 편집기의 정상 dirty 상태를 지우거나 실패한 부모 빌드를 성공으로 기록하지 않는다.

이번 수정의 빌드·실행은 에이전트가 수행하지 않았다. 원본 저장 전 경고 유지,
원본 저장 뒤 부모 갱신 표시, 부모 저장 뒤 dirty 유지 해소는 사용자 재확인 대상이다.

이후 사용자가 할당한 외장 KataGraph가 미저장이어서 dirty가 떴던 것으로 설명하고 "테스트는 완료 했어"라고 보고했다.
사용자 테스트 완료 보고로 기록하되, 최초 증상의 원인을 에이전트가 실행으로 확정한 것은 아니다.
경고와 부모 갱신 가능 여부를 나눈 후속 수정은 유지한다. 개별 항목·빌드 로그·후속 수정의 적용 여부는 미상이다.

## 남은 제한과 후속 작업

- 기존 외장 에셋에 세대가 없으면 안쪽 외장부터 다시 저장해야 한다.
- Save All의 에셋 순서를 자동 정렬하지 않는다. 안내가 남으면 안쪽 원본부터 최종 부모까지 다시 저장한다.
- 사전 검사 실패는 기존 실행 데이터와 세대를 유지하지만 파일 저장 자체를 막지는 않는다. 안내와 로그를 해결한 뒤 다시 저장해야 한다.
- 저장용 빌드 세대 발급은 PreSave 시점이다. 디스크 쓰기 실패와 실제 저장 결과는 엔진의 저장 결과를 따라야 한다.
- 내용 지문, 미개봉 부모 자동 갱신, 전체 에셋 자동 저장, 이름 있는 Exit는 추가하지 않았다.
