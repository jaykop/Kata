# 프리뷰 멀티 타겟 배치 보류 결정

작성: 2026-10-10  
갱신: 2026-10-10  
유형: 결정 기록  
대상: 액션 에디터 프리뷰의 Target 액터 구성  
기준: [#10](https://github.com/jaykop/Kata/issues/10) 종료 시점. 삭제한 `docs/plan/Preview-Multi-Target-Plan.md`(2026-09-24 작성, 2026-10-03 갱신)의 설계를 옮긴 기록

## 배경과 결론

프리뷰에는 Target 액터를 하나만 배치할 수 있다. 히트 판정과 거리 조건을 여러 대상으로 확인하려고 여러 개를 배치하는 기능을 #10으로 계획했고, 설계까지 정한 뒤 구현하지 않은 채 보류 상태였다.
2026-10-10 사용자가 앞으로 쓰지 않을 것 같다고 판단해 진행하지 않기로 했다. #10은 구현 없이 닫았고 계획 문서는 삭제했다. 프리뷰 Target은 지금처럼 하나로 유지한다.

## 주요 결정과 이유

| 결정 | 일자 | 이유·근거 |
|---|---|---|
| 프리뷰 멀티 타겟 배치를 진행하지 않는다 | 2026-10-10 | 사용자 결정. 쓰지 않을 것으로 판단했다 |
| 프리뷰 Target은 `PreviewTargetClass`·`PreviewTargetTransform` 단일 쌍으로 유지한다 | 2026-10-10 | 구현하지 않았으므로 직렬화된 프리뷰 설정과 에셋 이전 작업이 생기지 않는다 |

## 보존한 설계안

다시 필요해지면 새 이슈에서 아래 안을 출발점으로 삼는다. 당시 확정했던 내용이며 구현은 하지 않았다.

| 항목 | 설계 |
|---|---|
| 설정 구조 | 단일 쌍을 `TArray<FKataPreviewActorSpec>`으로 교체한다 |
| 기존 에셋 이전 | 단일 프로퍼티를 Redirect 또는 `PostLoad` 승격으로 옮긴다. 방식은 착수 때 정하기로 했다 |
| Context 대상 | `FKataContext::TargetActor`는 단일 필드로 유지한다. 배열의 Primary만 Context에 넣고 나머지는 히트 판정·거리 조건 확인용으로만 둔다 |
| 뷰포트 조작 | 조작은 `EKataPreviewActorSlot`으로 이미 일반화되어 있다. 자리를 `Target`에서 `Target[i]`로 넓히고 `GetActorForSlot`·`ApplyPreviewActorTransform`의 분기만 배열 인덱스로 확장한다 |
| 범위 | 프리뷰 전용이다. 런타임 다중 타겟은 별도 설계가 필요하다 |

## 남은 제한과 후속 작업

- 프리뷰에서 여러 대상을 놓고 히트 판정이나 거리 조건을 확인할 수 없다. 대상 하나씩 바꿔 가며 확인해야 한다.
