# 오토 대시

작성: 2026-10-10  
갱신: 2026-10-10  
유형: 결정 기록·구현 기록  
대상: KataFramework `UKataRootMotionCurveComponent`(거리 보정 단계)·`UKataTask_AutoDash`·`KataFL::ExtractMontageRootMotion`, KataTargeting `UKataTargetingComponent::ResolveApproachLocation`  
기준: 커밋 41d2edc와 이 기록을 담은 커밋. #37 종료 시 삭제한 `docs/plan/Auto-Dash-Plan.md`의 결정을 옮겼다

## 배경과 결론

[#37](https://github.com/jaykop/Kata/issues/37)은 공격을 시작할 때 대상과의 거리에 맞춰 루트 모션 전진 거리를 늘이거나 줄여 대상 앞에서 멈추게 하는 기능이다.
처음에는 엔진 Motion Warping을 감싸려 했으나, #36에서 루트 모션을 커브로 대체하기로 하면서 자체 구현으로 정했다
([루트 모션 이동량 커브 결정 기록](2026-10-10-Root-Motion-Curve.md)).

결론은 다음과 같다. #36 컴포넌트가 소유한 `ProcessRootMotionPreConvertToWorld` 처리를 단계로 나누고, 2단계에서 거리 보정을 한다.
보정 구간은 Kata 타임라인의 `Kata Task: Auto Dash`가 정한다. 사용법은 [루트 모션 커브 사용법](../manual/Root-Motion-Curve.md#오토-대시)을 따른다.

## 변경 내용

| 항목 | 이전 상태 | 반영 결과 |
|---|---|---|
| 루트 모션 처리 | `bUseRootMotionCurves`가 꺼지면 처리 전체를 건너뜀 | 1단계 커브 대체(`bUseRootMotionCurves`)와 2단계 거리 보정(요청이 있을 때)으로 나눴다. 커브를 끈 캐릭터에서도 보정이 동작한다 |
| 거리 보정 요청 | 없음 | `BeginDistanceCorrection`/`EndDistanceCorrection`(핸들, 한 번에 하나). 요청은 대상 지점을 구하는 함수, 구간 길이, Stop Distance, 최소·최대 전진 거리, 대상 추적 여부를 담는다 |
| 이동 태스크 | `EKataTaskPhase::Movement`를 쓰는 태스크 없음 | `UKataTask_AutoDash`(Duration 0.3초, Stop Distance 50cm, Min Dash Distance 0, Max Dash Distance 500cm, Track Target 켬) |
| 대상 기준 위치 | 방향 API(`ResolveFacingDirection`)만 있음 | `ResolveApproachLocation`(BlueprintNativeEvent). 기반은 대상 위치, PC는 그 대상에 락온 중이면 락온 지점 |
| 남은 이동량 계산 | `ExtractMontageRootMotion`은 시퀀스 커브가 있으면 항상 커브 사용 | 시퀀스 커브 사용 여부 인자 추가. 섹션 경로 생성을 시작 위치·길이로 일반화했다 |

## 주요 결정과 이유

| 결정 | 채택 | 검토한 대안과 제외 이유 |
|---|---|---|
| 활성화 구조 | 단계마다 켜는 조건을 따로 둔다. 바인딩은 항상 한다 | 커브 설정 하나로 전체를 켜면 커브를 쓰지 않는 캐릭터에서 오토 대시를 쓸 수 없다 |
| 늘이고 줄이는 방식 | 남은 이동의 수평 성분 전체에 같은 배율. 방향은 회전 태스크가 맡는다 | 남은 경로를 대상 쪽으로 꺾는 워프식: 몸이 대상을 향하지 않으면 옆으로 미끄러지는 게걸음이 생긴다 |
| 틀어진 몸의 이동 거리 | 경로 위에서 대상에 가장 가까워지는 지점까지(원하는 거리 × cosθ). 90도 넘게 틀어지면 보정하지 않는다 | 처음 구현은 대상 쪽 성분으로 배율을 구해 경로 전체에 곱했다. 락온 중 몸이 대상에서 크게 틀어져 있으면 배율이 폭주해 엉뚱한 방향으로 멀리 돌진했다(사용자 PIE) |
| 전진 한도 | 구간 동안 실제 수평 이동 총량을 Min·Max Dash Distance(cm)로 제한(사용자 결정) | 배율 한도(기본 0~3배): 애니메이션마다 원래 전진 거리가 달라 기획자가 실제 거리를 예측하기 어렵다 |
| 기준 지점 | 락온 지점이 대상의 지점이면 그 위치(대상 반지름을 빼지 않음), 아니면 대상 위치와 두 캡슐 표면 간격 | 항상 대상 위치: 큰 몬스터는 부위마다 거리가 다르다 |
| 기준 지점 API 위치 | 기반 타게팅 컴포넌트의 BlueprintNativeEvent | KataFramework 태스크에서 PC 컴포넌트로 형변환: AI가 재정의할 수 없다 |
| 보정 구간 고정 | 요청 뒤 블렌드 아웃 중이 아닌 루트 모션 몽타주를 처음 만난 갱신에서 인스턴스에 고정하고, 남은 트랙 길이(Duration × 재생 속도 × Rate Scale)로 센다 | 태스크가 매 Tick 남은 Kata 시간을 넘김: Kata Tick과 CharacterMovement가 둘 다 `TG_PrePhysics`라 순서에 따라 한 프레임 오차가 난다. 같은 시각에 시작하면 Movement 단계가 Animation 단계보다 먼저라 시작 시점에는 몽타주가 없다 |
| 배율 갱신 | 매 갱신 남은 구간 전체로 다시 정한다 | 시작 시 한 번만 정하면 대상이 움직이거나 창 끝에서 오차가 모인다 |
| 제자리 애니메이션 | 보정하지 않는다 | 이동을 더하는 기능은 필요하면 후속 이슈로 다룬다 |
| 이름 | 컴포넌트 이름 `UKataRootMotionCurveComponent` 유지 | 이름을 바꾸면 기본 서브오브젝트 이름과 BP 직렬화에 Redirect가 필요하다 |

### 회전과 겹칠 때의 경로

루트 모션은 캐릭터 기준 앞 방향으로 나오므로, 회전 태스크가 몸을 돌리는 동안 대시하면 이동 방향도 함께 돌아 호를 그린다(사용자 PIE에서 확인).
D1에서 몸 방향과 이동 방향을 일치시키기로 한 결과이며, 회전을 대시 전에 끝내도록 배치해 해결한다. 대상 방향으로 꺾는 선택지는 필요하면 후속으로 검토한다.

## 남은 제한과 후속 작업

- 오토 대시 구간이 끝난 뒤의 전진과 Min Dash Distance로 강제한 전진은 대상에게 파고들 수 있다. 같은 처리의 3단계 전진 제한은 [#38](https://github.com/jaykop/Kata/issues/38)에서 다룬다. #38에서 오토 대시도 대상 HurtBox 표면 기준으로 거리를 재게 바꿨다([전진 제한 결정 기록](2026-10-10-Approach-Limit.md)).
- 대상 방향으로 경로를 꺾는 선택지, 제자리 애니메이션에 이동 더하기는 요청이 있을 때 검토한다.
