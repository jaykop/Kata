# 추출 애니메이션과 원본 Behavior 구조 분석

작성: 2026-10-11  
갱신: 2026-10-11  
유형: 진단  
대상: KataFramework 애니메이션 레이어 구조, 샘플 DS3 캐릭터 애니메이션(`Content/KataSample/Art/Characters`)  
기준: Git `62f2fa1` 시점의 소스·문서와 같은 날 Content 상태. 이 분석으로 바꾼 코드·에셋은 없다

## 배경과 결론

추출한 애니메이션을 기준으로 AnimBP 구조를 어떻게 잡을지, 2족·4족 또는 비2족으로 나눠야 하는지 검토했다. 함께 원본 게임(DS3)의 애니메이션 시스템이 어떻게 구성되는지 원본 데이터로 확인했다.

원본의 적 캐릭터들은 몸 구조와 상관없이 공용 behavior 그래프 하나를 함께 쓴다. 몸 구조 차이는 캐릭터별 루트의 IK 설정에만 있다.
이는 [애니메이션 레이어 구조 결정](2026-10-04-Anim-Layer-Structure.md)의 "몸 구조로 Anim Instance를 나누지 않는다"와 같은 구조이므로 그 결정을 유지할 근거가 된다.
아래 진단 외의 구조 제안은 사용자가 아직 확정하지 않았다.

## 진단 내용

| 항목 | 발견 내용 | Kata에 주는 의미 |
|---|---|---|
| 그래프 구성 | 적 7종(로스릭 기사·흑기사·은기사·사냥개·거인·고룡·폭풍의 왕)의 behavior가 모두 같은 공용 그래프(`c9997`, 크기 동일)를 참조한다. 캐릭터 고유 파일은 5~25KB짜리 루트뿐이다. 로스릭 기사·사냥개·폭풍의 왕은 상태 스크립트(HKS)도 바이트 단위로 같다 | Template ABP 하나와 캐릭터별 얇은 자식 ABP 구조와 대응한다 |
| 몸 구조 차이 | 루트 IK 구성이 기사·고룡은 발 2개, 사냥개는 발과 앞발 4개, 거인은 접점 8개다. 폭풍의 왕은 IK 없이 날개 흔들림과 Twist만 있다 | 다리 수는 Body 레이어(Biped·Quadruped·없음)에서만 갈린다 |
| 동작 묶음 | 상태마다 선택기가 `a000~a005` 중 같은 번호의 클립을 고른다. 묶음은 NPC 행에 붙은 패시브 특수효과의 `animIdOffset`(100만 단위)으로 정해진다. 기사는 무기 세트(로스릭 기사 a001 = Spear), 고룡은 배치 지점 세트다(Alt1 로스릭 높은 벽, Alt2·Alt3 로스릭 성 두 곳). 거인 Alt2 행은 추출한 맵에서 배치를 찾지 못했다 | 고룡 Alt는 무기 종류 태그가 아니라 캐릭터 행마다 다른 레이어 설정으로 다룰 수 있다 |
| 비행 | 폭풍의 왕의 NPC 이동 유형은 기사와 같은 값(3)이고 캡슐은 높이 10.1m·반지름 5m다. 클립 57개 모두 루트 이동의 높이가 0이고, 몸은 뼈 애니메이션으로 최대 약 24m(화면 밖 이탈 클립은 약 100m)까지 오른다. 고룡도 같으며, 이벤트 클립 3개만 수직 루트 이동이 있다 | 지상 캡슐에 애니메이션으로 날게 하는 구성과 같다. 피격·락온 지점은 뼈를 따라야 한다 |
| 시작·정지 | 시작 상태는 적·플레이어 모두 없다. 정지 상태는 플레이어만 있다(걷기·달리기 정지 각 4방향, 질주 정지, 질주 반전, 퀵턴). 적은 비전투와 전투 스탠스를 전환 클립(`001040` 진입, `001020` 해제)으로 오간다 | 적에는 시작·정지 대신 스탠스 전환이 필요하다. AI 계획 Combat의 Engage 단계와 대응한다 |
| 발 고정·동기화 | 발 IK 드라이버의 발 고정 옵션(`lockFeetWhenPlanted`)이 플레이어·기사·사냥개·거인 모두 꺼져 있다. 플레이어 전환 효과 일부(3·7·10·12프레임)는 동기화 플래그를 쓴다. 적 공용 그래프에는 이동 방향 블렌더가 없어 방향별 클립을 바꿔 끼우고, 상체 비틀기 모디파이어로 대상을 본다 | 발 고정은 후순위다. 플레이어 동기화는 UE의 Sync Group·Sync Marker에 해당한다 |
| Strafe·뒷걸음 | 공용 AI 목표(접근·옆걸음·뒷걸음·거리 유지·회전)가 이동 방향을 정한다. 애니메이션은 전투 스탠스의 4방향 걷기 중 하나를 이동 각도로 고른다. 달리기는 전방뿐이다 | Kata AI에는 옆걸음·뒷걸음·거리 유지 목표가 아직 없다 |
| 추출 이름 대응 | `Idle_Normal`(000020)은 전투 대기, `Unknown_000000`은 비전투 대기, `Move_002300`은 비전투 걷기, `Transition_Candidate_001040/001020`은 전투 진입·해제다 | 이름 정정은 결정 전이며 이번에 바꾸지 않았다 |

## 주요 결정과 이유

새로 확정한 결정은 없다. 2026-10-04의 몸 구조 비분리 결정을 원본 데이터로 보강했다. 다음은 사용자가 확정하지 않은 제안이다.

- 메인 상태 머신은 하나로 두고, 2족·4족은 Body 레이어에서만 나눈다.
- 제자리 회전은 ABP 상태가 아니라 KataAction 몽타주로 처리한다.
  - 원본 AI도 회전을 이벤트로 요청한다.
  - Kata에서는 액션이 몸을 돌린다.
  - 회전 클립에 Yaw가 루트 이동으로 들어 있다.
  - 구성 예는 Action Group 하나와 [Angle 조건](../manual/Conditions.md)이다.
- 비행 상태는 두지 않고 지상 캡슐을 유지한다.
- 적에는 시작·정지 상태 대신 스탠스 전환 액션을 둔다.
- Strafe는 ABP 분기가 아니라 회전 방식(이동 방향 회전 / 대상 바라보기) 전환으로 만든다. 기존 Move BlendSpace를 그대로 쓰고, 대각선 품질을 위해 Sync Marker를 추가한다.

## 근거

- [애니메이션 레이어 사용법](../manual/Animation-Layers.md): 메인 Template ABP, 무기·Body 레이어, 레이어 설정 위치.
- [발 IK 구현과 사족 리그 진단](2026-10-11-Foot-IK.md): Body 레이어의 2족·사족 리그 구성.
- [AI 계획](../plan/AI-Plan.md): Combat의 Engage(첫 발견 반응)·Position(대치·거리 유지) 단계.
- [타게팅 사용법](../manual/Targeting.md): `Rotate To Facing`, 컨트롤러 회전과의 충돌 제한.
- 원본 데이터
  - 로컬 변환 환경에서 읽기 전용으로 확인했다: 캐릭터 behavior(packfile·tagfile), 캐릭터 HKS, 공용 AI 스크립트 묶음(문자열), 레귤레이션의 `NpcParam`·`SpEffectParam`, 맵 배치(MSB).
  - 파라미터 필드 배치는 [Paramdex](https://github.com/soulsmods/Paramdex) DS3 정의를 따랐다.
  - 분석 스크립트와 측정 결과는 저장소 추적 대상이 아닌 로컬 작업 폴더에만 있다.
