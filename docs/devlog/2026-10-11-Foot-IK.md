# 발 IK 구현과 사족 리그 진단

작성: 2026-10-11  
갱신: 2026-10-11  
유형: 구현 기록, 진단  
대상: 샘플 콘텐츠 Body 레이어(`ALI_KataBody`, `ABP_BodyLayer_Biped`, `ABP_StarvedHound_Body`), 발 IK Control Rig(`CR_FootIK_Biped`, `CR_FootIK_Quadruped`), 메인 Template ABP `ABP_CharacterBase`  
기준: git `2ff4848`, Diversion dv.commit.118. Kata 플러그인 소스 변경 없음. [#52](https://github.com/jaykop/Kata/issues/52)

## 배경과 결론

경사면에서 발이 지면에 뜨거나 파묻히는 문제를 스켈레톤별 Body 레이어의 Control Rig로 해결했다.
메인 Template ABP의 Slot 뒤에서 Body 레이어 함수 `Body_PostProcess`를 호출하고, 레이어 안의 Control Rig가 다리별 트레이스, 골반 보정, Two Bone IK를 수행한다.
2족(BlackKnight·SilverKnight)은 처음 구성대로 동작했다. 사족(StarvedHound)은 실행 확인 중 여러 문제가 드러나 리그를 고쳤다.

## 변경 또는 진단 내용

| 항목 | 이전 상태 또는 발견 내용 | 반영 결과 |
|---|---|---|
| Body 레이어 호출 | 메인 ABP에 Body 레이어 호출 지점이 없음 | `ALI_KataBody`의 `Body_PostProcess`(입력 포즈 하나)를 `ABP_CharacterBase`가 구현. 그래프는 Slot → Body → Kata Tilt |
| 2족 리그 | 없음 | `CR_FootIK_Biped`: 발 아래 트레이스, 두 발 중 낮은 쪽에 맞춘 `Root` 하강, Two Bone IK, 지면 법선 발 정렬(최대 30°) |
| 사족 Template Body 레이어 | Template `ABP_BodyLayer_Quadruped`에서 로코모션·몽타주가 모두 기준 포즈로 나옴. Control Rig를 건너뛰면 정상, Alpha 0이어도 깨짐 | 스켈레톤 지정 `ABP_StarvedHound_Body`로 교체해 해결. 원인 미확인. 2족 Template은 정상 |
| 사족 IK 목표 이중 적용 | 트레이스는 `Toe0`, IK 목표는 `Foot`을 따로 읽어 목표가 몸통 회전·이동 뒤 위치를 읽음 | 실행 맨 앞에서 끝 본 Transform을 변수에 저장해 IK 목표로 사용 |
| 사족 골반 상한 | 골반을 내리기만 허용해 엉덩이 중심 Pitch에서 다리가 모두 접힘 | 올림 허용(±60cm) |
| 사족 발 정렬 회전 | 긴 발등·손등뼈를 회전해 발끝이 최대 18cm 이동 | 끔(Max Foot Angle 0) |
| 사족 골반 계산 근사 | 발끝 앞뒤 위치로 엉덩이·어깨 높이 변화를 근사해 앞다리 약 6cm 오차 | `Thigh`·`UpperArm` 위치에 몸통 회전을 적용해 계산 |
| 사족 좌우 기울기 | Pitch만 처리해 비스듬히 서면 위쪽 다리가 접혀 지면을 뚫음 | Roll 추가(최대 15°), 몸통 회전 = Pitch × Roll |
| 사족 트레이스 범위 | 대기 자세의 오른쪽 뒷발이 몸 중심에서 1m 넘게 뒤에 있어, 30° 경사에서 지면이 시작 높이(50cm)보다 높아 미적중. 미적중 0이 Roll 평균을 오염 | Trace Up 120, Trace Down 80, Max Foot Offset 70cm |
| 사족 몸 높이 | 골반을 요구값 최솟값에 맞춰 몸이 평지보다 낮게 내려앉음 | 최솟값과 평균을 Pelvis Average Weight(0.5)로 혼합 |

## 주요 결정과 이유

#52 종료 시 발 IK 계획(삭제)의 결정을 이 절로 옮겼다. 확정 일자는 2026-10-10~11이며 출처는 사용자 결정이다.

### 구현 수단 (F2, Control Rig 채택)

| 안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| 엔진 Foot Placement + Leg IK (Animation Warping) | 골반 보간·착지 판정·발 고정 내장, 노드 하나 | Experimental, 플러그인 기본 비활성, IK 발 본 필수(DS3 스켈레톤에 없음), 골반 본 하나를 위아래로만 옮겨 4족 몸통 정렬 불가 |
| Kata C++ AnimNode | 추가 플러그인 없음 | 보간·계단·다리 수·공중 처리를 C++로 직접 구현해야 하고 엔진 기능과 겹침 |
| **Control Rig (채택)** | 엔진 기본 활성, Experimental 아님, IK 발 본 불필요, 4족 몸통 Pitch를 같은 그래프에서 처리, 같은 본 이름의 스켈레톤끼리 리그 공유 | 보간·공중 처리를 직접 조립해야 하고 RigVM 실행 비용이 노드 하나보다 큼 |

### 확정 사항

| 항목 | 결정과 이유 |
|---|---|
| F1 위치 | 스켈레톤별 Body 레이어(`UKataAnimLayerSetup::BodyLayer`, 2026-10-04 장비·무기 계획 결정). 메인 Template ABP에는 스켈레톤이 없어 본을 지정하는 노드를 둘 수 없다 |
| F3 Body ALI | `ALI_KataBody`에 입력 포즈 하나를 받는 `Body_PostProcess` 하나. 무기 레이어 함수는 입력 없이 둔다는 결정의 예외다. Body 레이어는 받은 포즈를 고치는 후처리라서다 |
| F4 그래프 순서 | Slot → Body → Kata Tilt → LookAt. Tilt 체인은 다리·골반 보정 본을 포함하지 않아 순서를 바꿔도 결과가 거의 같고, Body를 먼저 두면 Tilt가 최종 몸 높이에서 회전 중심을 잡는다 |
| F5 골반 보정 본 | `Pelvis`와 `Spine`의 공통 부모(DS3 `Root`, DS3Player `RootPos`). DS3는 `Pelvis`와 `Spine`이 형제라 `Pelvis`만 내리면 상체가 남는다. `Root`의 부모 `Master`가 루트 모션 본이라 이동량과 충돌하지 않는다 |
| F6 IK 발 본 | Control Rig는 FK 발 위치에서 목표를 계산하므로 가상 본을 추가하지 않는다 |
| F7 발 고정 | 하지 않는다. 항상 지면 높이에 맞춘다. 발 속도 판정과 고정 위치 유지가 필요해 후속으로 둔다 |
| F8 예외 처리 | 공중은 `Is On Ground`로 페이드, 다운·구르기는 커브 `DisableFootIK`. 액션 타임라인에서 끄는 경로는 레이어가 메인 ABP의 Blueprint 변수를 읽지 못해 C++ 값이 필요하므로 커브로 부족할 때 정한다 |
| F9 4족 범위 | 네 다리 정렬과 몸통 Pitch까지 포함(구현 중 Roll 추가) |
| F10 플러그인 | 엔진 기본 활성인 Control Rig만 써서 프로젝트 설정을 바꾸지 않는다. Kata 플러그인은 Control Rig를 참조하지 않는다 |
| F11 트레이스 채널 | Visibility 기본값. 다른 캐릭터에 맞는지는 미확인 |
| F12 IK 솔버 | Two Bone IK와 리그에서 직접 계산하는 골반·몸통 보정. Full Body IK는 플러그인 활성화가 필요하고 조정 항목이 많다 |
| F13 레이어 공유 | 2족은 Template `ABP_BodyLayer_Biped`를 공유하고, 사족은 스켈레톤별 `ABP_StarvedHound_Body`를 쓴다. 사족 Template 실패 원인을 찾지 못해 동작이 확인된 구성을 택했다 |

### 리그 처리 구조

- 공통: 다리마다 발 아래로 스윕 트레이스하고, "맞은 지면 높이 − 컴포넌트 원점 높이"만큼 발 목표를 옮긴다(애니메이션의 발 높이는 유지). 보정은 시간 기반으로 보간하고 `Is On Ground`와 커브의 곱으로 페이드한다. 골반 보정 본에 수직 오프셋(사족은 회전 포함)을 준 뒤 다리마다 Two Bone IK를 푼다. Pole은 종아리 공간의 앞쪽 100cm 위치다.
- 2족: 골반은 두 다리 보정 중 낮은 값(0 이하, 최대 45cm). 발을 지면 법선 쪽으로 최대 30° 정렬.
- 사족: 몸통 Pitch(최대 35°)·Roll(최대 15°)을 다리 높이 차이로 구하고, 다리별 골반 요구값 "지면 보정 − 몸통 회전에 따른 엉덩이·어깨 높이 변화"의 최솟값과 평균을 Pelvis Average Weight로 섞는다(±60cm). 발등·손등뼈 정렬은 끈다.

### 실행 확인 중 정한 것

- 사족 골반 혼합 가중치는 0.5다(2026-10-11, 사용자가 판단을 맡김). 발을 크게 벌린 자세에서 몸 높이와 발 접지가 동시에 되지 않아 중간값을 골랐다. 리그 변수 하나로 조정한다.
- 가장자리 바깥 발이 바닥까지 내려가는 문제를 의심해 트레이스 범위를 줄였으나, 실제 원인은 범위 부족이었다. 범위를 다시 넓혔고 가장자리 처리는 후속으로 남겼다.

## 근거

- `RigVMCompiler.cpp`(UE 5.8): 순수 노드는 `ExprComplete`로 한 번만 평가된다. 사족 IK 목표 이중 적용의 원인.
- `RigUnit_OffsetTransform.cpp`: Offset Transform은 본 로컬 축 기준이라 골반 수직 보정에 쓰지 않고 Get/Set Transform(Global)을 썼다.
- `RigUnit_TwoBoneIKSimple.cpp`: Pole 값이 위치로 쓰여 Pole 공간을 종아리 본으로 두고 Location 종류를 썼다.
- `AnimNode_ControlRigBase.cpp`, `ControlRig.cpp`: 게임 화면 디버그 그리기는 `ControlRig.EnableDrawInterfaceInGame 1`과 `a.AnimNode.ControlRig.Debug 1`이 모두 필요하다.
- 런타임 값: PIE 중 `CR_FootIK_Quadruped` 인스턴스의 디버그 변수를 읽어 미적중과 Roll 오염을 확인했다.

## 남은 제한과 후속 작업

- 사족 Template Body 레이어 실패 원인 미확인.
- 발을 크게 벌린 자세에서 일부 발이 덜 닿는다(가중치 0.5에서 이번 자세 기준 약 11cm).
- 트레이스가 실패한 다리를 Pitch·Roll 평균에서 빼지 않는다. 가장자리 바깥 발 처리 없음.
- `DisableFootIK` 커브는 리그 계층에 커브 요소가 없어 아직 읽히지 않는다(FI-3).
- 트레이스 채널(Visibility)이 다른 캐릭터에 맞는지 미확인(F11).
- 사족 리그에 디버그 변수(`Dbg_*`)와 디버그 선이 남아 있다. 선은 `bDebugDraw` false로 꺼 두었다.
