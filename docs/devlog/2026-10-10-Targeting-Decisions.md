# 타게팅 시스템 결정 기록

작성: 2026-10-10  
갱신: 2026-10-10  
유형: 결정 기록  
대상: KataTargeting 플러그인(팩션, 타게팅 컴포넌트, Preset 확장 태스크, 대상·방향 Command, 락온 지점)  
기준: [#13](https://github.com/jaykop/Kata/issues/13) 종료 시점(d5a40fb). 삭제한 `docs/plan/Targeting-Plan.md`의 결정을 옮긴 기록

## 배경과 결론

#13에서 PC와 몬스터가 같은 방식으로 후보를 고르는 타게팅 시스템과 팩션을 KataTargeting 플러그인에 구현했다.
TG-2·3·4·6을 구현했고, TG-5는 #17·#22로 넘겼다. 2026-10-10 사용자가 빌드와 실행을 확인해 이슈를 닫았다.
설계 문서의 결정과 그 이유를 이 기록으로 옮기고 plan은 삭제했다. 현재 사용법은 [타게팅 사용법](../manual/Targeting.md)과 [팩션 사용법](../manual/Factions.md)을 따른다.

## 주요 결정과 이유

| 결정 | 일자 | 이유·근거 |
|---|---|---|
| PC와 몬스터 모두 엔진 `UTargetingPreset`으로 후보를 모으고 거르고 정렬한다 | 2026-09-24 | 후보 선택 규칙을 데이터로 두고 역할별로 같은 경로를 쓰기 위해서다 |
| 타게팅 상태는 `UKataActionComponent`가 아니라 전용 타게팅 컴포넌트가 소유한다. 공용 기반 `UKataTargetingComponent`와 역할별 파생(PC는 KataTargeting, 몬스터는 KataAI)으로 나눈다 | 2026-09-24, 09-25 | 액션 컴포넌트는 액션·그래프만 다룬다. PC와 몬스터의 필요 기능이 다르다 |
| PC 대상은 소프트 타겟과 락온 두 가지이며 락온이 우선한다 | 2026-09-24 | 락온은 사용자가 고른 대상이므로 자동 선택보다 앞선다 |
| 소프트 타겟은 액션 시작 때 PreCommand(`Resolve Target`)가 정한다. 이어받은 대상이 유효하면 다시 구하지 않는 옵션을 기본으로 켠다 | 2026-09-24 | 콤보 전이의 Keep Target과 뜻을 맞춘다 |
| 소프트 타겟은 공격 방향을 정하는 액터 단위 기준이며 카메라와 관계가 없다 | 2026-09-28 | 락온 지점을 도입한 뒤에도 액터 단위를 유지한다 |
| PC 공격 방향 우선순위는 락온 지점 → 이동 입력 → 소프트 타겟 → 정면이다. 락온이나 입력이 있으면 소프트 타겟을 정하지 않는다 | 2026-09-26 | 대상과 공격 방향이 어긋나지 않게 한다. [TG-4 기록](2026-09-26-Targeting-Resolve-Commands.md) |
| 락온 후보와 대상은 액터가 아니라 몬스터 부위에 붙인 타겟 지점이다. 같은 몬스터인지와 관계없이 Preset 기준으로 가장 우선하는 지점을 고른다 | 2026-09-28 | 한 몬스터의 여러 부위를 락온하고 지점마다 카메라 구도를 주기 위해서다. 액터 단위 락온을 대체했다 |
| 타겟 지점은 `RoleTags`로 역할을 가르는 `UKataTargetPointComponent`(`USphereComponent` 상속, 충돌 없음)다 | 2026-10-02 | Targeting 결과의 `FHitResult::Component`는 `UPrimitiveComponent`만 담으므로 Scene 컴포넌트로는 지점을 결과에 실을 수 없다. 2026-09-28의 Scene 컴포넌트 제안을 대체했다 |
| 지점 수집은 Preset이 액터를 모은 뒤 `Kata Expand Target Points`가 지점별 결과로 펼친다 | 2026-10-02 | 엔진 수집 태스크를 그대로 쓰고, 이후 필터·정렬은 지점 위치로 판정한다 |
| 락온 전환은 좌·우 입력별로 호출하고 방향별 Preset의 최고 점수 지점으로 확정한다. 스틱 입력 방향은 쓰지 않는다 | 2026-09-24 | 전환 방향은 호출하는 함수가 정한다 |
| 락온 알림 `OnLockTargetChanged`는 지점을 인자로 넘기고, `GetLockTarget()`은 지점의 소유 액터를 액션 대상으로 돌려준다. 락온 중 공격 방향은 지점 위치 기준이다 | 2026-10-02 | 큰 대상은 부위마다 수평 위치가 다르다 |
| 지점 비활성화와 락온 상실 시 동작은 옵션(해제 또는 다음 지점)으로 고른다 | 2026-09-28 | 게임마다 원하는 동작이 다르다 |
| 락온 중 자기 ASC와 대상 ASC에 Status 태그를 Loose로 붙인다. 태그 값은 설정이며 플러그인은 태그를 정의하지 않는다 | 2026-10-02 | 같은 액터의 다른 부위로 바뀌면 대상 태그를 다시 붙이지 않는다 |
| 락온 유효성 검사는 타이머가 아니라 락온 중에만 켜는 컴포넌트 Tick(기본 0.1초)으로 한다 | 2026-09-25 | 별도 타이머를 둘 이유가 없다는 사용자 판단 |
| 시야 조건은 카메라 기준 트레이스로 판정한다. 유지 중에는 유예 시간 뒤 상실로 보고, 처음 락온·전환 후보는 Preset 필터가 거른다 | 2026-10-09 | [시야 조건 기록](2026-10-09-Lock-On-Line-Of-Sight.md) |
| 팩션은 Gameplay Tag와 관계표(Developer Settings)로 관리하고 엔진 팀 인터페이스로 연결한다. 판정 함수는 `UKataFL_Faction`이다 | 2026-09-24 | AIPerception의 적·아군 구분도 Kata 팩션을 따르게 한다 |
| 관계표에 없는 팩션끼리는 중립이다. 관계는 한 줄이 양방향이며, 같은 팩션은 행이 없으면 우호다. 팀 번호는 등록 순서대로 0부터 부여한다(255 초과 시 경고) | 2026-09-24 | 적대 관계는 명시해야 생긴다 |
| `UKataFL_Faction`은 팀 인터페이스로만 팀을 찾고, 팩션 값은 컴포넌트에 둔다. NoTeam이 끼면 중립으로 판정한다 | 2026-09-25 | 엔진 기본 판정은 NoTeam끼리 우호로 본다 |
| Pressure·Capability는 KataAI에서 다룬다. 첫 번째 플레이어 조회 함수는 만들지 않는다 | 2026-09-24 | AI 전용 개념이다. 엔진 `Get Player Controller`·`Get Player Character`로 충분하다 |

## 엔진 제약과 대응

- 엔진 `TargetingSystem`은 UE 5.8에서 Beta(`Plugins/Experimental`)다. 사용 범위를 Preset, 태스크 상속, 즉시 실행 요청으로 한정했다.
- 엔진 정렬 태스크는 원점수를 태스크 안의 최고점으로 나눠 누적하므로 태스크별 비중을 줄 수 없다. 그래서 정규화 점수에 Weight를 곱하는 `UKataTargetingSortTask_Weighted`를 만들었다.
- 엔진 필터는 `RemoveAtSwap`으로 후보를 지우므로 필터를 정렬 앞에 둔다. [소프트 타겟 디버그 기록](2026-10-10-Soft-Target-Debug-Forward-Angle.md)
- 전역 팀 관계 판정 함수(`FGenericTeamId::SetAttitudeSolver`)는 나중에 등록한 쪽이 이긴다.
- 시작 조건은 PreCommands보다 먼저 평가되므로, 대상을 읽는 시작 조건은 이어받은 대상으로 판정한다. 사용법의 문제 해결 표에 적었다.

## 남은 제한과 후속 작업

- 샘플 공격 액션에는 아직 `Resolve Target`이 없다. 사용자가 다른 작업 이후에 추가하기로 했다.
- 몸 정면 기준 정렬 태스크는 필요하면 검토할 제안이며 결정하지 않았다.
- 몬스터 파생 타게팅과 AIController 팀 인터페이스는 [#22](https://github.com/jaykop/Kata/issues/22), 락온 카메라는 [#20](https://github.com/jaykop/Kata/issues/20)에서 다룬다.
