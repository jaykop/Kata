# 피격 연출 Cue

작성: 2026-10-12  
갱신: 2026-10-12  
유형: 구현 기록 / 결정 기록 / 진단  
대상: KataFramework `UKataHitHandler_ApplyGameplayEffect`, `UKataCombatSettings`, 샘플 `WindowsDualsense_ds5w`·입력·GAS 설정  
기준: #73 구현 커밋. 같은 날 사용자 Editor 빌드·PIE 확인 결과 포함

## 배경과 결론

[피격 반응 계획](../plan/Hit-Reaction-Plan.md)의 HR10으로 맞는 순간의 화면 흔들림·패드 진동(이후 VFX·SFX)을 Gameplay Cue로 재생한다.
피해가 실제로 적용된 히트에서 처리기가 맞은 쪽 Cue와 때린 쪽 Cue를 실행한다. 실행 확인 중 샘플 쪽 문제 세 가지(듀얼센스 진동, 서드파티 패드 입력, Cue 경로 설정)를 함께 진단했다.

## 변경 또는 진단 내용

| 항목 | 이전 상태 또는 발견 내용 | 반영 결과 |
|---|---|---|
| Cue 표 | Impact 행에 맞은 쪽 `HitCueTag`만 있었고 실행 코드가 없었다 | 때린 쪽 기본 `AttackerCueTag` 추가. 처리기에 공격별 `HitCueTag`·`AttackerCueTag` 추가 |
| Cue 실행 | 없음 | 피해 적용 확인 뒤 `UGameplayCueManager::ExecuteGameplayCue_NonReplicated`로 맞은 쪽은 피격자, 때린 쪽은 공격자에서 실행 |
| 샘플 Cue | 프로젝트에 VFX·SFX·흔들림·포스 피드백 에셋이 없었다 | Light·Heavy의 맞은 쪽·때린 쪽 `GameplayCueNotify_Burst` 4개, 카메라 흔들림 2개, 포스 피드백 2개. VFX·SFX는 없다 |
| 듀얼센스 진동 | 플러그인 `DeviceManager::SetChannelValues`가 출력 버퍼에 값만 쓰고 HID 출력을 보내지 않아 엔진 포스 피드백이 닿지 않았다 | 값이 바뀔 때 `UpdateOutput` 호출. 벤더 변경은 플러그인 `UPSTREAM.md`에 기록 |
| 서드파티 패드 입력 | Windows 기본 장치 배정 정책(`PrimaryUserSharesKeyboardAndFirstGamepad`)으로 먼저 연결한 듀얼센스가 1번 플레이어를 차지하고, 뒤에 연결한 XInput 패드는 새 플레이어(PlatformUser 1·2)로 배정되어 입력이 전달되지 않았다 | 샘플 `Config/Windows/WindowsInput.ini`에 `MapAllDevicesToPrimaryUser`(3) |
| Cue 경로 | `[/Script/GameplayAbilities.GameplayAbilitiesDeveloperSettings]`에 쓴 `GameplayCueNotifyPaths`가 읽히지 않았다 | 이 설정 클래스는 `OverrideConfigSection`으로 `[/Script/GameplayAbilities.AbilitySystemGlobals]`를 쓴다. 그 섹션으로 옮겨 경고가 사라졌다 |

## 주요 결정과 이유

- **Cue를 맞은 쪽·때린 쪽 둘로 나눔(사용자 결정).** UE 5.8 `UGameplayCueNotify_Burst`는 카메라 흔들림·포스 피드백이 각각 한 칸이고, 칸마다 Locally Controlled Source로 공격자나 피격자 한쪽만 고른다. 한 Cue의 World 재생으로 양쪽을 흔드는 안은 강도를 나눌 수 없고 근처 AI끼리의 전투에도 반응해 택하지 않았다.
- **두 Cue 모두 공격별 지정 → Impact 행 기본값(사용자 결정).** 때린 쪽 연출은 무기·스킬마다, 맞은 쪽 연출은 공격 속성(예: 화염)마다 같은 등급 안에서도 달라질 수 있다. 평범한 공격은 값을 넣지 않아도 등급별 기본 연출을 받는다.
- **재질·부위별 선택 로직은 Kata에 두지 않음(사용자 결정).** 재질은 엔진 Burst 항목의 Surface Type 조건이 고른다. 다만 Hit Trace가 HitResult에 Physical Material을 넣지 않아 현재는 항상 Default 재질이다.
- **각 Cue를 연출의 주인 액터에서 실행.** Spawn Condition의 Target Actor가 Cue를 실행한 액터이므로, Source를 Target Actor로 두면 두 Cue 모두 "자기 쪽이 플레이어일 때만" 흔들림·진동을 재생한다. 엔진 기본값 Instigator Actor는 두 Cue 모두 공격자를 가리키므로 샘플은 덮어쓴다.
- **비복제 실행.** 싱글플레이 전용 규칙에 따라 복제 경로 대신 `ExecuteGameplayCue_NonReplicated`를 쓴다.
- **듀얼센스 출력은 값이 바뀔 때만.** 엔진은 매 프레임 같은 값을 넘기므로 매번 HID 보고서를 보내지 않는다.

## 확인 범위와 결과

| 대상 | 확인 방법·수행자 | 결과 | 미확인 범위 |
|---|---|---|---|
| 때린 쪽 Cue | 사용자 PIE 보고(2026-10-12) | PC 공격 명중 시 화면 흔들림·진동 | — |
| 맞은 쪽 Cue | 사용자 PIE 보고 | 적에게 맞을 때 화면 흔들림 | 맞을 때 진동은 따로 보고 없음 |
| 무적 대상 | 사용자 PIE 보고 | 흔들림·진동 없음 | — |
| 듀얼센스·XInput | 사용자 PIE 보고 | 수정 후 둘 다 진동, 두 패드 모두 1번 플레이어 입력 | — |
| Cue 경로 | 에디터 로그 | 경고 사라짐 | — |
| Heavy 등급 | 없음 | — | 샘플 공격이 모두 기본 `Impact.Light` |

첫 PIE에서 흔들림·진동이 모두 없다가 에디터 재시작 뒤 동작했다. MCP로 CDO에 Cue 태그를 넣은 에셋이 시작 때 만든 Cue 목록에 반영되지 않았던 것으로 보이지만 확정하지 않았다.

## 남은 제한과 후속 작업

- VFX·SFX 샘플이 없다. 재료 에셋을 구하면 Burst에 추가한다.
- 재질별 연출은 Hit Trace의 Physical Material 전달이 필요하다.
- `Knock.Back`·`Knock.Down` 등급의 Cue 에셋이 없다.
