# 스포너 거리 활성화와 작업 순서 재정렬

작성: 2026-10-07  
갱신: 2026-10-07  
유형: 구현 기록·결정 기록  
대상: KataFramework 스포너, 월드 스포너 관리자  
기준: `cdd8a80` 이후 미커밋 작업 트리. 다른 작업자의 Graph·Config 변경은 포함하지 않음

## 배경과 결론

스포너 개선의 원래 요청은 타임 슬라이싱과 그리드 기반 작동이었고, 이후 대화에서 스포너 컴포넌트로 플레이어 거리 기반 생성·제거를 추가했다. 앞선 작업은 타임 슬라이싱과 수동 디스폰까지 구현한 뒤, 거리 기능을 개체별 휴면·스냅샷 복원 계약 뒤에 두고 그리드를 마지막 단계로 미뤘다.

사용자가 현재 상태 진단 후 순서를 거리 컴포넌트 → 그리드 → (선택) 스냅샷으로 바꾸는 안을 승인했다. 이에 상태 보존 없이 동작하는 `UKataSpawnerComponent_DistanceActivation`과 관리자의 주기 거리 평가를 구현했다. 휴면·스냅샷 계약은 후속 검토안으로 낮췄다.

## 변경 또는 진단 내용

| 항목 | 이전 상태 | 반영 결과 |
|---|---|---|
| 작업 순서 | 슬롯·스냅샷 캡처·복원 뒤 거리 연결, 그리드는 마지막 | 거리 컴포넌트, 그리드 순으로 진행. 스냅샷은 필요할 때 별도 검토 |
| 거리 설정 | 계획에만 존재 | `Distance Activation` 인라인 설정. SpawnDistance·DespawnDistance만 보관 |
| 거리 판정 | 없음 | `UKataSpawnerSubsystem`이 평가 주기마다 커서로 스포너를 나눠 평가하고 공용 시간 예산을 공유 |
| 개체별 제거 | 수동 전체 제거만 존재 | 플레이어와 먼 NPC 기록만 거리 제거 배치로 기존 제거 큐에 제출 |
| 재생성 | 없음 | 원점 재진입 시 거리로 제거·취소한 수만큼 원점 영역에서 새로 생성 |
| 수동 API | 항상 허용 | 거리 관리 스포너는 생성·제거를 거절하고 취소를 무시 |

## 주요 결정과 이유

- NPC 제거는 각 NPC의 현재 위치로 판정한다. 원점 기준 일괄 제거는 플레이어를 따라온 NPC를 눈앞에서 지운다.
- 생성은 원점 진입 시 한 번만 시도한다. 원점 상태를 SpawnDistance 진입·DespawnDistance 이탈로 나눠 경계 왕복과 범위 안 체류 중 반복 생성을 막는다. 원점 범위 안에서 멀리 간 NPC가 제거돼도 그 자리에서 바로 보충하지 않는다.
- 재진입 생성 수는 최초에 정한 수량 중 거리로 제거하거나 원점 이탈로 취소한 수다. 생성 실패·외부 제거·사망을 보충하면 처치한 적이 다시 나오므로 제외한다. 사망 통지가 없으므로 Destroy되지 않은 시체는 거리 제거 대상이 되는 제한이 있다.
- 거리 관리 스포너는 항상 분산 경로를 쓴다. 재진입 생성이 한 프레임에 몰리는 것을 피하기 위해서다.
- 거리 제거 배치는 수동 제거 상태(`ActiveDespawnBatch`)와 분리했다. `bDistanceDespawn` 배치의 완료는 실패 기록을 돌려주고 Destroy를 거절한 NPC 수만 재생성 수에서 뺀다.
- 판정·스케줄은 관리자, 실행 상태는 스포너가 소유하며 설정 객체에는 값만 둔다. 액터별 Tick은 추가하지 않았다.
- 잘못된 거리 설정을 일반 BeginPlay 생성으로 넘기지 않고 생성하지 않는다. 거리 관리를 기대한 배치에서 NPC가 계속 남는 것보다 경고와 함께 비어 있는 편이 원인을 찾기 쉽다.

## 남은 제한과 후속 작업

- 그리드 조회: 거리 관리 스포너 목록 순회를 셀 기반 후보 조회로 대체한다. 다음 단계.
- 에디터 거리 범위 미리보기와 디버그 표시.
- 사망 통지와 시체 처리. 캐릭터 제거·풀링 이슈와 함께 정한다.
- 이탈 판정 후 Destroy 직전 재확인. 현재는 판정 뒤 몇 프레임 안의 복귀를 반영하지 않는다.
- 상태 보존 재생성은 [휴면 계약안](../plan/Spawner-Dormancy-Contract-Plan.md)을 필요할 때 다시 검토한다.
