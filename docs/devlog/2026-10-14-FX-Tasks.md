# 연출 태스크

작성: 2026-10-14  
갱신: 2026-10-14  
유형: 구현 기록  
대상: `UKataTask_PlaySound`·`UKataTask_CameraShake`(KataRuntime), `UKataTask_SpawnVFX`(KataFramework), `EKataEffectEndPolicy`  
기준: [#7](https://github.com/jaykop/Kata/issues/7) 종료 시점 작업 트리. 다른 작업의 미커밋 변경은 확인 대상에서 제외했다

## 배경과 결론

[#23](https://github.com/jaykop/Kata/issues/23) 피격 반응 계획에서 맞는 순간의 연출은 Gameplay Cue Burst로 다루기로 했고, [#73](https://github.com/jaykop/Kata/issues/73)에서 히트 Cue를 구현했다.
#7은 휘두르는 소리, 칼날 궤적, 내려찍기 흔들림처럼 액션 타임라인의 시각에 맞춘 연출을 맡는다.
[기본 태스크 확장 계획](../plan/Base-Task-Plan.md)의 "셋을 하나로 묶지 않는다"에 따라 Play Sound, Camera Shake, Spawn VFX 세 태스크를 따로 만들었다.
사용법은 [연출 태스크 사용법](../manual/FX-Tasks.md)을 따른다.

## 변경 내용

| 항목 | 반영 결과 |
|---|---|
| Play Sound | 코어 `KataRuntime`. 오디오 컴포넌트를 직접 만들어 MetaSound 입력(`FAudioParameter`)을 넣은 뒤 재생한다. `KataRuntime`에 엔진 모듈 AudioExtensions 의존을 추가했다 |
| Camera Shake | 코어 `KataRuntime`. Avatar 카메라와 반경 안 로컬 플레이어 두 대상 모드 |
| Spawn VFX | `KataFramework`. `KataFramework`에 Niagara 플러그인(Private 모듈) 의존을 추가했다. 기준 메시는 Hit Trace와 같은 `EKataHitBoxMeshSource`·Weapon Slot 규칙 |
| `EKataEffectEndPolicy` | Sound·Shake가 함께 쓰는 정상 완료 정책(Keep Playing, Stop). VFX는 방출 중지와 즉시 제거를 나눠 `EKataVFXEndPolicy`를 따로 둔다 |
| 프리뷰 Play Sound | 프리뷰 월드에서는 UI 사운드로 표시하고 공간화를 끈다 |

## 주요 결정과 이유

2026-10-14 사용자와 정한 결정이다.

- **플러그인 위치.** Sound와 Shake는 엔진 모듈만 쓰므로 코어에 둔다. Niagara는 엔진 플러그인이라 코어에 넣을 수 없어(AGENTS.md "모듈 경계") Spawn VFX는 `KataFramework`에 둔다. 연출 태스크 세 개만으로 위성 플러그인을 새로 만들지는 않았다.
- **정리 규칙.** 정상 완료는 태스크별 옵션으로 고르고 기본은 끝까지 재생이다. Duration 0인 휘두르는 소리처럼 태스크보다 연출이 긴 경우가 흔하기 때문이다. 중단·취소·Kata 종료는 옵션과 관계없이 정리한다. 캔슬된 공격의 궤적과 소리를 남기지 않기 위해서다. 루프 에셋은 끝까지 재생이 끝나지 않으므로 정리로 처리하고 데이터 검증에서 경고한다.
- **실패해도 태스크를 일찍 완료하지 않는다.** 연출 실패가 의존 태스크의 시작 시각을 바꾸지 않게 한다. 프리뷰 Seek처럼 소리만 막힌 경우에도 타임라인 진행이 실제 재생 때와 같아야 한다.
- **MetaSound 입력 전달을 넣었다.** 사용자가 MetaSound 사용 여부를 정하려고 조사를 요청했다. `UMetaSoundSource`는 `USoundBase`이므로 재생 경로는 다른 사운드와 같고, 입력 전달만 AudioExtensions가 필요해 MetaSound 플러그인 의존 없이 넣을 수 있다.
- **보류.** `UKataTask_GameplayCue`는 타임라인에서 Cue를 부를 사용처가 생기면 만든다. 프리뷰 카메라 흔들림은 에디터 뷰포트 카메라 작업이 따로 필요해 다루지 않았다.

### 구현 중 확인한 사실

- **Seek 무음은 기존 장치를 쓴다.** 설계 단계에서는 런타임 액션 인스턴스에 "Seek 중" 표시를 추가하기로 했다. 구현 중 `SKataPreviewViewport::SimulateTo`가 이미 Seek 동안 `World->bAllowAudioPlayback`을 끈다는 것을 확인해, Play Sound가 이 플래그를 보도록 하고 코어 API는 추가하지 않았다.
- **프리뷰에서 소리가 나지 않았다.** PIE와 MetaSound 에디터에서는 들렸다. 엔진 `UAnimNotify_PlaySound`의 `bPreviewIgnoreAttenuation`이 프리뷰에서 2D UI 사운드(`PlaySound2D`)로 재생하는 선례를 따라, 프리뷰 월드에서 `bIsUISound`를 켜고 공간화를 끄자 들렸다. 재생 조건을 담은 엔진 cpp는 설치본에 없어 원인 코드는 확인하지 못했다.
- **셰이크 인스턴스는 재사용된다.** 카메라 매니저는 끝난 셰이크를 클래스별 풀(`ExpiredPooledShakesMap`)에 모았다가 다시 쓴다. 끝난 인스턴스를 계속 가리키면 다른 곳에서 새로 시작한 흔들림을 멈출 수 있어, 태스크가 Tick마다 끝난 항목을 놓는다.
- **거리 감쇠를 직접 계산한다.** `APlayerCameraManager::CalcRadialShakeScale`은 protected이고 `PlayWorldCameraShake`는 시작한 인스턴스를 돌려주지 않아 멈출 수 없다. 같은 규칙으로 카메라마다 배율을 계산해 직접 시작한다.
- **Niagara 풀링을 쓰지 않는다.** 셰이크와 같은 이유로, 풀로 돌아간 컴포넌트를 약한 참조가 가리키지 않게 한다.

## 확인 범위와 결과

| 대상 | 확인 방법·수행자 | 결과 | 미확인 범위 |
|---|---|---|---|
| Play Sound | 사용자 Editor 빌드, 프리뷰·PIE(2026-10-14) | ▶ 재생 시 소리, Seek 중 무음, PIE 소리, `Intensity` 입력에 따른 크기 변화 | Stop 정책, Attach To Mesh 끔, 루프 경고 |
| Camera Shake | 사용자 PIE·프리뷰 | 플레이어 공격 흔들림, 보스 공격 거리 감쇠, Avatar Camera에서 보스 공격 무반응, 프리뷰 무동작 | Stop 정책, 무한 셰이크 경고 |
| Spawn VFX | 사용자 Editor 빌드, 프리뷰·PIE | Weapon 메시 소켓 부착, 플레이어·보스 공격 표시, 회피 캔슬 뒤 재생성 없음 | Stop Emitting·Destroy Immediately 정책, Attach To Mesh 끔, 루프 경고 |

확인용 에셋(`MS_Test_Whoosh`, `NS_Test_Spark`, `KA_BlackKnight_Attack01`의 태스크)은 샘플 테스트 전용이다.
처음 만든 `NS_Test_Spark`는 템플릿 이미터가 월드 공간 1회 버스트라 칼끝을 따라가지 않았고, 이미터를 로컬 공간으로 바꿔 부착을 확인했다. `SM_BlackKnight_Greatsword`는 `Blade_Start` 소켓이 칼끝에 있다.

## 남은 제한과 후속 작업

- Niagara User Parameter 전달은 없다.
- `UKataTask_GameplayCue`와 프리뷰 카메라 흔들림은 보류했다.
- 실제 궤적·타격 이펙트와 효과음 에셋은 없다. 임시 에셋 확보는 별도로 다룬다.
