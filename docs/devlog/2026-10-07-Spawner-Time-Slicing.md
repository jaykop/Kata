# 스포너 타임슬라이싱과 로드 완료 큐

작성: 2026-10-07  
갱신: 2026-10-07  
유형: 구현 기록  
대상: KataFramework의 NPC 스포너·월드 관리자·캐릭터 생성 서비스  
기준: 1단계 커밋 `da3eada` 이후 2단계 작업 트리 변경

## 배경과 결론

사용자가 단계별 구현의 다음 단계 진행을 요청했다. 1단계에서 분리한 위치 진행 커서에 월드 공용 스케줄러를 연결했다. 스포너의 `Use Time Slicing`을 켜면 위치 준비부터 로드 요청 제출과 실제 생성까지 여러 프레임에 나눠 진행한다.

기존 스포너 기본값은 false다. PC GameMode와 일반 비동기 생성 노드는 기존 경로를 사용한다. 거리·그리드·완료 NPC 디스폰은 후속 범위다.

| 항목 | 이전 상태 | 반영 결과 |
|---|---|---|

| 요청량 | 전체 배치 제출 | 로드 중·준비 완료 요청을 합한 월드·스포너 상한 적용 |
| 순환 처리 | 없음 | 실제 생성과 위치 준비에 별도 순환 커서 사용 |

## 주요 결정과 이유

관리자는 게임·PIE 월드에서만 동작하며 스포너와 생성 서비스는 약한 참조로 보관한다. 생성 서비스에 자체 Tick이나 플레이어 참조를 추가하지 않았다. 그룹별 준비 큐는 스포너 정책과 분리된 생성 서비스의 API로 제공한다.

로드 완료 큐의 소비를 먼저 수행한 뒤 위치 준비·제출을 진행하고 두 종류의 차례를 별도로 보존한다. 큐 확인과 준비 방문에 각각 최대 처리 수를 적용하며, 둘은 한 시간 예산을 공유한다. 요청 제출에는 전역·개별 대기 상한을 적용해 실제 생성보다 로드가 과도하게 앞서가지 않게 한다.

일반 모드는 위치 사전 확인 실패 시 전체 요청을 거절한다. 분산 모드는 수락 이후 후보 실패를 개별 실패로 처리한다. 전체 후보를 미리 만들지 않으면서 먼저 완료한 개체를 되돌리지 않기 위한 계약이다. 수량·설정 복사와 검사는 시작 호출에서 수행하고, 개체별 위치·보정·제출을 분산한다.

캐릭터의 생성·행 적용·BeginPlay·결과 이벤트는 한 번의 호출에서 수행한다. 시간 제한은 작업 사이의 부드러운 상한이며 개별 Blueprint 훅과 실제 생성 비용을 강제로 끊지 않는다. 에셋 로드·GC와 일반 생성 경로의 비용도 직접 통제하지 않는다. 초기 예산과 상한은 조정 가능한 출발값이며 측정 결과가 아니다.

생성 중 BeginPlay에서 그룹이 취소되는 경우는 결과 전달 전 취소로 처리한다. 새 Pawn에 `DetachFromControllerPendingDestroy`를 호출한 뒤 제거하고 결과 콜백을 생략한다. 이미 성공 결과를 전달한 NPC는 기존 취소 계약대로 유지한다. 이 정리는 완료한 NPC의 세대별 디스폰 API를 대신하지 않는다.

## 남은 제한과 후속 작업

완료한 NPC와 Controller의 세대별 제거는 3단계, 플레이어 거리·그리드 활성화는 4단계에서 연결한다. 재진입·전투 중 이탈 정책은 미확정이다. 분산 옵션을 끈 생성과 외부의 일반 생성 요청은 공용 예산에 포함하지 않는다.

후속 변경: [디스폰과 Controller 수명 기록](2026-10-07-Spawner-Despawn-Lifecycle.md)에서 결과 전달 전 정리를 소유 기록 기반으로 연결하고, 생성·제거의 첫 처리 차례를 프레임마다 교대했다. 이 문서의 2단계 당시 처리 순서는 후속 변경 전 기록이다.

후속 설계: [개체별 휴면 계약 결정](2026-10-07-Spawner-Dormancy-Contract.md)에서 전투 판정 대신 NPC 현재 거리와 스냅샷 복원 요구를 반영했다. 위 미확정 정책은 2단계 당시의 기록이다.
