# 락온 카메라 블렌드·정렬 재작성

작성: 2026-10-05  
갱신: 2026-10-05  
유형: 구현 기록, 결정 기록  
대상: KataCamera CAM-5 락온 데이터·매니저·Rotation/Framing Feature  
기준: [#20](https://github.com/jaykop/Kata/issues/20) 작업 트리. [락온 카메라와 MainHUD 연결](2026-10-04-Lock-On-Camera-HUD.md)의 미커밋 카메라 구현을 대체한다. 입력·HUD·타게팅·컨트롤러 연결은 유지한다.

## 배경과 결론

사용자가 첫 락온 카메라 구현을 실행해 본 뒤, 블렌드가 너무 빠르고, 기본 카메라 데이터와 겹치는 값이 있으며, 좌우 정렬 방식이 없다고 지적했다.
진단 결과 회전 추적이 블렌드 가중치를 무시하고 첫 프레임부터 일정 각속도로 돌았고, 회전·구도·카메라 데이터 교체가 서로 다른 시간과 곡선을 썼다.
카메라 락온 내부만 다시 작성하고 `SetLockOnFocus` API와 다른 모듈의 연결은 유지했다.

## 변경 또는 진단 내용

| 항목 | 이전 상태 | 반영 결과 |
|---|---|---|
| 회전 블렌드 | 획득 즉시 360°/s로 추적, 가중치 미적용 | 전환 시작 회전에서 실제 지점 방향까지 BlendIn 진행도만큼 회전. 블렌드 뒤에만 Rotation Speed 적용 |
| 블렌드 시간·곡선 | Transition Time 0.25초 하나를 선형·EaseInOut으로 여러 용도에 사용 | BlendIn Duration과 Curve 에셋 하나. 획득·타겟 변경·좌우 전환·락온 CameraData 교체가 같은 진행도를 따르고, 해제는 같은 시간의 선형 |
| 설정 층 | 매니저 기본값 < CameraData 락온 기본값 < LockOnData | 매니저 기본값 또는 LockOnData 설정 전체 중 하나. 타겟 지점의 `bUseLockOnCameraData` 토글로 고른다. CameraData 락온 기본값과 항목별 오버라이드 제거 |
| 중복 값 | Pitch Min/Max, Distance Scale, Pitch Offset이 CameraData와 겹침 | 제거. Pitch는 활성 CameraData 범위, 거리는 LockOnData.CameraData 교체로 처리 |
| 상태 변경 중 튐 | 락온 중 CameraData가 바뀌면 설정이 블렌드 없이 바뀜 | 설정이 매니저 기본값과 지점 데이터로만 정해져 락온 중 바뀌지 않음 |
| 좌우 정렬 | Side Offset 부호 고정 | Right·Left·Auto. 옆 오프셋은 피벗·레일 오프셋과 무관한 최종 거리로 보정하고 화면 X를 정렬에 맞춰 뒤집음 |
| 조준점 | 락온 지점만 | 피벗과 락온 지점을 잇는 선 위의 비율 지점과 거리 상한 |
| 편집 UI | 별도 bool 묶음과 설정 구조체 | 매니저 기본값과 LockOnData 모두 같은 구조체를 쓰고 모드에 따라 항목을 숨긴다 |
| 해제 중 시점 입력 | 해제 블렌드 동안 고정된 초점을 다시 조준해 마우스 회전과 서로 당기며 화면이 출렁임 | 마지막 락온 프레임의 옆 이동·조준 보정량을 시점 기준 오프셋으로 저장하고 가중치 비율로 줄여 더함 |
| 피벗 오프셋 | CameraData에 있었으나 정상 Spline에서는 쓰이지 않고 레일 실패 시에만 적용되어 카메라가 옆으로 튀었음 | Boom Arm 배치로 옮김. Spline 대체 배치는 폰 위치를 피벗으로 사용 |
| 기본 블렌드 곡선 | 곡선 미지정과 해제가 선형이라 블렌드 끝에서 카메라가 딱 붙음 | 곡선 미지정과 해제에 Ease In-Out 적용. 락온발 CameraData 교체 레이어도 같은 곡선 |
| 공격 중 좌우 흔들림 | 진단 로그(2,647프레임)에서 자유 시점 카메라가 폰의 좌우 이동을 오차 0으로 그대로 따름. 공격 중 폰이 약 180°/s로 회전하며 화면 기준 좌우 이동이 0.3초 안에 뒤집혔고, 루트 모션 속도가 120fps에서 4프레임(30Hz)마다 계단식으로 바뀜. 락온 중에는 카메라 좌우 이동이 폰의 약 2배 | 카메라 데이터에 피벗 래그(수평·수직 임계 감쇠, 최대 거리) 추가. 락온 회전을 일정 각속도에서 임계 감쇠(`RotationLagTime`)로 바꾸고 래그된 기준을 보게 함 |
| 타겟 주위 회전 후 되돌아옴 | 진단 로그(13,462프레임)에서 회전을 멈춘 뒤 시선이 최대 15.6°(한 사례 40°) 반대로 되돌아감. 폰이 멈춘 뒤에도 래그된 피벗이 남은 속도로 목표를 지나쳤고(좌우 +2.09 → -0.19cm/프레임), 그 피벗을 보는 락온 회전도 같은 이유로 지나침. 임계 감쇠는 정지한 목표에 남은 속도가 있으면 한 번 넘어갈 수 있음 | 감쇠 스무딩이 목표를 지나치는 프레임에 목표에서 멈추고 속도를 버리도록 수정. 이후 재측정에서 되돌아감(최대 56°)이 남았고, Boom Arm Pivot Offset (50, 100, 85)의 X·Y가 시점 Yaw를 따라 반지름 약 112cm 원을 그리는 움직임까지 래그되어 락온 회전과 되먹임을 만든 것을 확인. 래그를 피벗이 아닌 폰 위치에 적용하고 그 차이만 피벗·카메라에 더하도록 변경 |
| 디버거 표시 | 카메라 데이터 이름과 레이어만 표시 | 활성 데이터의 FOV·Pitch·래그·배치 값, 래그 거리, 락온 상태·출처·설정을 실시간 표시 |
| 디버거 조준선 | 없음 | 락온 중 피벗–초점 선, 조준점(t), 거리 텍스트 표시 |
| 거리별 보정 | 없음 | Pitch Offset By Distance, Boom Distance Scale By Distance, Look At Alpha By Distance 곡선 추가. Max Look Distance는 곡선이 t를 정할 수 있어 숨김 조건을 없앰. 타겟 변경 중 이전·새 곡선 값을 진행도로 섞음 |

## 주요 결정과 이유

- 블렌드는 BlendIn 하나만 둔다. 사용자가 BlendOut을 추가하면 더 복잡해진다고 판단했고, 해제와 곡선 미지정은 같은 시간의 선형으로 정했다.
- 설정 층을 줄였다. 일반 카메라 데이터에 락온 값이 들어가면 에셋 하나로 최종 값을 알기 어렵고, `LockOnData.CameraData`가 다시 락온 기본값을 가지는 중복이 생긴다.
- 처음에는 LockOnData에 항목별 오버라이드 체크박스를 두었으나, 편집 화면에서 모든 값이 비활성으로 보여 무엇이 적용되는지 알기 어려웠다. 사용자 결정으로 타겟 지점에 사용 토글을 두고, 켜면 LockOnData 설정 전체를, 끄면 매니저 기본값을 쓰도록 바꿨다.
- 정렬은 플레이어 기준 타겟이 보이는 쪽이다. Right면 카메라가 플레이어→타겟 선의 오른쪽으로 비켜 타겟이 플레이어 오른쪽에 보인다.
- Auto는 획득·타겟 변경 시 현재 시점 기준 타겟 쪽을 고르고, 블렌드 뒤에는 카메라 Yaw와 플레이어→타겟 Yaw 차이로 판정한다. 추적 중에는 차이가 작으므로 타겟이 빠르게 가로지를 때만 전환된다.
- 조준선의 플레이어 쪽 기준점은 피벗이다. 카메라 위치는 비율 0에서 자기 자신을 보게 되고 Shrink·옆 오프셋에 따라 흔들린다. 폰 위치는 높이 기준이 자유 시점 조준과 다르다.
- 곡선 에셋은 단조 증가 결정을 강제할 수 없어 데이터 검증 경고로 알린다. 시간이 끝나면 곡선 끝값과 관계없이 가중치를 1로 한다.
- 래그는 레이어 안에 두지 않고 블렌드 뒤 별도 단계에서 임계 감쇠로 처리한다는 기존 결정을 따랐다. 처음에는 범위 밖으로 두었으나, 진단 결과에 따라 사용자 승인 후 피벗 래그와 락온 회전 감쇠를 추가했다.

## 남은 제한과 후속 작업

- 이전 구현으로 만든 `Kata Lock On Data` 에셋이 있다면 제거된 항목 값은 읽히지 않으므로 설정을 다시 확인해야 한다. 이미 Lock On Camera Data를 지정한 타겟 지점은 새 토글이 꺼진 상태라 켜야 적용된다.
- Shrink가 카메라를 당기면 화면 위치가 어긋날 수 있는 제한은 그대로다.
- 루트 모션의 30Hz 계단은 공격 애니메이션이 30fps 키에 Linear 보간이라 키 구간마다 속도가 일정하고 키에서 바뀌기 때문이다. 메시 URO는 꺼져 있고 Always Tick Pose다. 공격 초반 0.65초의 Rotate To Facing(180°/s)이 루트 모션 경로를 휘게 해 화면 기준 좌우 이동이 뒤집힌다. 둘 다 카메라 밖의 설정이다.
- 진단용 `Kata.Camera.Trace` 콘솔 변수는 확인 후 제거했다.
- 카메라 StateTree 태스크도 곡선 에셋을 고를 수 있게 할지는 결정 전이다.
- 기존 Boom Arm CameraData의 Pivot Offset 값은 새 위치로 옮겨지지 않는다. Boom Arm 에셋이 있다면 다시 지정해야 한다.
