# 입력 계층 결정

작성: 2026-10-10  
갱신: 2026-10-10  
유형: 결정 기록  
대상: KataFramework `UKataInputHandlerComponent`, `UKataInputConfig`, `AKataPlayerController`, `AKataPlayerCharacter`  
기준: [#19](https://github.com/jaykop/Kata/issues/19) IN-1(4e7258a)·IN-2(f4035a5)·IN-3(34a5549)·입력 캔슬(05da79b)·IN-4(8f8b9e0). 삭제한 입력 계층 계획(2026-09-26 작성, 2026-10-04 갱신)의 확정 사항을 옮겼다.

## 배경과 결론

플레이어 입력으로 KataGraph 콤보 전이, 이동·시점, 락온을 조작하는 입력 계층을 KataFramework에 만들었다.
IMC를 명시적으로 추가·제거해 플레이어가 할 수 있는 행동을 제어한다. 현재 사용법은 [입력 사용법](../manual/Input.md)에 있다.
2026-10-10 사용자가 IN-5 확인 항목(IMC 제거·복구, 공격 중 Alias 회피 캔슬, 락온 방향 회피)을 PIE에서 확인했다.

## 주요 결정과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| 계층 위치 | KataFramework. 입력 바인딩과 기본 IMC는 폰의 `UKataInputHandlerComponent`, 플레이어 단위 기능은 `AKataPlayerController` | 코어는 게임 프레임워크 구체 클래스를 갖지 않는다. 2026-09-26 PlayerController 중심안에서 캐릭터로, 2026-09-27 캐릭터에서 컴포넌트로 옮겼다. 캐릭터마다 입력 설정이 다를 수 있고, 늘어나는 입력 로직이 캐릭터 클래스에 쌓이지 않게 하려는 것이다 |
| 기본 IMC 수명 | 폰이 로컬 플레이어 컨트롤러에 빙의될 때 추가하고 해제될 때 제거 | 컨트롤러가 폰을 바꾸면 이전 폰의 해제가 먼저 일어나 IMC가 겹치지 않는다 |
| 행동 제어 | 호출하는 쪽이 엔진 Add/Remove Mapping Context를 명시적으로 부른다. 조건에 따른 자동 전환 규칙과 같은 기능을 감싸는 Kata API는 만들지 않는다 | 엔진이 Blueprint에 이미 공개한 기능을 중복하지 않는다. 같은 IMC 중복 추가는 호출 측 실수로 보고 참조 횟수를 세지 않는다. 액션 구간 동안 IMC를 넣는 태스크도 만들지 않는다 |
| 태그 분리 | `Input.*`(무엇을 눌렀나)과 `Trigger.*`(그래프 전이 사건)를 나누고 입력 설정에서 매핑한다. 그래프 엣지는 Trigger만 쓴다 | 그래프가 입력 장치와 키 구성을 몰라도 되고, StateTree Task 같은 다른 발신자도 같은 Trigger로 같은 그래프를 구동한다. 매핑은 선택 목록을 루트별로 거르기 위해 `TMap` 대신 구조체 배열로 둔다 |
| 입력 형태 | 누름·홀드·뗌은 Enhanced Input Trigger로 표현한다 | 자체 입력 형태 시스템을 만들지 않는다 |
| 고정 기능 입력 | 이동·시점·락온 InputAction은 `UKataInputConfig`에 두고 그래프를 거치지 않고 직접 처리한다 | 그래프 전이와 무관한 상시 기능이다 |
| 락온 입력 | 획득·해제 토글 하나와 카메라 기준 좌·우 전환 각각 하나, 입력 시작 시 한 번 처리. 스틱 방향은 타게팅 계산에 쓰지 않는다 | 2026-10-04 사용자 결정 |
| 그래프 발동 | 입력 처리 컴포넌트의 `Graph` 하나를 기본 그래프로 쓴다. 실행 중이 아니면 대상 없이 시작한 뒤 같은 트리거를 보내고, 진입하지 못하면 Cancelled로 멈춘다. 콤보가 끝나면 그래프도 끝난다 | 입력별 시작 액션은 Entry 엣지 트리거로 구분한다. 대상은 각 액션의 Resolve Target Command가 정한다. 몬스터 그래프는 KataAI StateTree Task가 지정한다 |
| 액션 중 캔슬 | 캔슬 시점은 액션의 Transition Window가 열고, 엣지의 Required Window Tag로 전이한다. 여러 액션에서 같은 곳으로 가는 캔슬은 Alias(Any State 포함)로 한 번만 긋는다 | 입력 계층은 트리거만 보내고 캔슬을 따로 처리하지 않는다. 그래프 전이 없는 기본 동작 복귀는 Cancel Window와 입력 설정의 Cancel Bindings가 맡는다 |
| 그래프 밖 직접 실행 | 모든 액션을 그래프로 실행한다. 단일 액션도 Entry → Action 그래프로 만든다 | 실행 경로를 하나로 둔다 |
| 입력 버퍼 | 범위에서 제외 | 실제 조작 후 [#8](https://github.com/jaykop/Kata/issues/8)에서 결정한다 |

계획 당시 "회피 노드에 직접 자기 엣지를 긋는다"고 적었던 연속 회피 안내는 그래프 스키마가 같은 노드 연결을 막아 실제로는 불가능했다.
[방향별 회피](2026-10-10-Directional-Dodge.md)에서 Conduit로 돌아가는 엣지로 해결했다.
