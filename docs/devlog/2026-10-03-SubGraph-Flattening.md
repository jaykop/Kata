# SubGraph 포트와 평탄화

갱신: 2026-10-03

## 요약

다른 그래프 에셋을 가리키는 SubGraph 포트를 추가하고, 그래프를 저장할 때 그 에셋을 부모 안으로
펼치도록 했다. 구현 중에 원인이 서로 다른 결함 다섯 건이 드러나 함께 기록한다.

## 배경

그래프는 무기별·몬스터별로 갈리는데 회피·피격경직·사망 같은 조각은 어느 그래프에나 똑같이
들어간다. 서브그래프가 없으면 그래프 수만큼 손으로 다시 짓고 고칠 때도 그만큼 돌아야 한다.
한 곳을 빠뜨리면 그 그래프에서만 조용히 안 되는 버그가 난다.

## 구현 요약

부모 그래프에 포트를 놓고 서브그래프 에셋을 지정한다. 같은 에셋을 가리키는 포트를 여러 개 놓아도
저장할 때 생기는 사본은 한 벌이며, 모든 포트가 그 사본으로 이어진다. 포트는 펼친 뒤 사라지므로
실행기는 서브그래프가 있었다는 사실을 모른다.

## 핵심 동작 흐름

1. 저장하면 `UKataEdGraph::RebuildKataGraph`가 편집기 그래프에서 런타임 그래프를 만든다.
2. 이어서 별칭의 `ResolvedSourceNodes`를 저작 목록에서 새로 만든다. 포트는 여기서 뺀다.
3. `FlattenSubGraphs`가 포트를 서브그래프별로 묶고, 묶음마다 그 그래프를 통째로 복제한다.
4. 복제한 노드와 엣지를 부모 소유로 옮기고 복제 껍데기는 버린다.
5. Port In은 들어오던 엣지를 사본의 진입 노드로 넘기고, Port Out은 사본을 출발지로 갖는 별칭이 된다.
6. 포트를 `AllNodes`에서 뺀다.

## 의사결정 기록

| 결정 | 대안 | 채택 사유 |
|---|---|---|
| 그래프 객체를 통째로 복제한다 | 노드와 엣지를 따로 복사한다 | 노드와 엣지가 그래프 아래 소유돼 있어 복제가 내부 참조를 사본끼리 이어 준다. 따로 복사하면 ChildrenNodes·Edges·StartNode·EndNode를 손으로 다시 맺어야 한다 |
| Port In을 사본의 진입 노드로 재배선한다 | 안쪽 액션 노드를 직접 찾아 잇는다 | 진입 노드는 머무를 수 없어 기존 전이 해석이 그대로 통과한다. 새 해석 로직이 필요 없고 진입 노드의 조건도 그대로 쓰인다 |
| 포트 방향을 클래스로 나눈다 | 방향을 프로퍼티로 둔다 | 프로퍼티로 두면 엣지를 다 연결한 뒤 방향을 바꿔 조용히 깨진 상태가 생긴다. 우클릭 메뉴에도 항목이 하나만 나온다 |
| 포트 제목이 에셋을 항상 따른다 | 직접 지은 이름을 허용한다 | 아래 시행착오 참고. 이름을 허용하면 클릭 한 번으로 제목이 굳는다 |
| 평탄화를 저장 시점에 한다 | 로드 시점에 한다 | 로드 시점이면 사본이 낡지 않지만 펼침 코드를 런타임으로 옮기고 참조 에셋의 로드 순서를 다뤄야 한다. 저장 시점은 기존 `RebuildKataGraph`에 얹으면 되고 배선이 늘지 않는다 |

## 시행착오

구현 자체보다 여기서 시간이 더 걸렸다. 다섯 건의 원인이 모두 달랐다.

**포트 제목이 에셋을 따라가지 않았다.** 처음에는 갱신 문제로 보고 `SNodeTitle`의 캐시를 무효화한
뒤 그래프 변경 알림까지 보냈는데도 그대로였다. 실제 원인은 값이 굳은 것이었다.
`SKataEdNode::OnNameTextCommited`가 인라인 이름 편집이 커밋될 때마다 글자가 바뀌지 않았어도
`NodeTitle`을 채운다. 노드를 클릭해 편집 상태로 들어갔다 빠져나오기만 해도 커밋이 일어난다.
`NodeTitle`이 차면 `GetNodeTitle`에서 그쪽이 이기고, `NodeTitle`은 `EditDefaultsOnly`라
디테일 패널에서 비울 수도 없어 되돌릴 길이 없었다. 포트는 `UKataActionNode`처럼 제목이 에셋을
항상 따르게 했고, 커밋한 글자가 자동 설명과 같으면 `NodeTitle`을 비우도록 공통 동작도 고쳤다.

**별칭이 이미 버려진 사본을 가리켰다.** 펼칠 때 저작한 `SourceNodes`에서 포트 항목을 사본으로
바꿔치기했는데, `SourceNodes`는 사용자가 저작한 데이터이고 `Clear()`가 지우지 않는다. 첫 저장에서
포트 지정이 사라지고, 두 번째 저장부터는 바꿀 포트가 없어 옛 사본을 계속 가리켰다. 저작용과
실행용을 `SourceNodes`와 `ResolvedSourceNodes`로 분리해 저작 데이터를 읽기만 하도록 바꿨다.

**포트를 만들 때 크래시가 났다.** `UKataGraphSchema::CanCreateConnection`이
`KataNode->GetGraph()->bEdgeEnabled`를 널 검사 없이 읽는다. `UKataGraphNodeBase::Graph`는
`RebuildKataGraph`에서만 채우므로 방금 만든 노드에서는 비어 있다. 같은 함수가 이미 편집기 그래프의
소유자에서 그래프를 가져오는 안전한 방법을 쓰고 있어 그쪽으로 통일하고, 노드를 만들 때 소유 그래프를
바로 채우도록 했다. `SKataEdNode::IsNameReadOnly`에도 같은 널 참조가 `check`로 들어 있었다.

**에셋 안에 복제 껍데기가 쌓였다.** `UKataGraphBase`는 편집기 그래프도 들고 있어서 통째로 복제하면
그것까지 복사된다. 노드만 꺼내 쓰고 껍데기는 참조가 없으니 수거되리라 보았는데, 껍데기 안의 편집기
노드가 옮긴 노드를 계속 가리켜 살아남았다. 저장할 때마다 하나씩 쌓이고 에셋을 지울 때 내부 참조로
걸린다. 껍데기와 그 편집기 그래프를 transient 패키지로 보내고 garbage로 표시해 저장되지 않게 했다.

**저장해도 dirty가 풀리지 않았다.** 저장이 끝난 뒤 `RebuildKataGraph`를 부르는 훅이 있었고 패키지
필터도 없었다. 저장 후에 다시 만들면 방금 쓴 데이터를 고치지 못하면서 패키지만 다시 더러워진다.
평탄화가 객체를 새로 만들기 시작하면서 이 문제가 드러났다. 저장 직전 훅으로 옮기고 자기 패키지일
때만 돌게 했다.

## 검증 상태

2026-10-03 사용자 Editor 빌드.

- 사용자가 확인한 것: 포트 생성과 제목, 연결 제한, 자기 참조 거부, 저장 후 dirty 해소.
- 저장된 에셋을 조회해 확인한 것: 사본 한 벌과 포트 제거, Port In 재배선과 양방향 연결,
  Port In 여럿이 사본을 공유하는 것, 두 번 저장해도 저작 목록이 보존되고 실행용 목록만
  새 사본을 가리키는 것, 복제 껍데기가 쌓이지 않는 것.

그래프 런타임 전이는 확인하지 못했다. 그래프를 실행해 트리거를 보낼 경로가 아직 없다.

## 남은 제한과 향후 확장

- 서브그래프 에셋을 고치고 부모를 다시 저장하지 않으면 부모가 낡은 사본을 쓴다. 에셋 의존 추적은 없다.
- 포트가 자기 그래프를 가리키는 것은 막지만 A가 B를 B가 A를 가리키는 간접 순환은 검사하지 않는다.
- 펼친 사본은 런타임에 어느 서브그래프에서 왔는지 드러나지 않는다.
- 포트 이름으로 서브그래프의 특정 입구·출구를 고르는 기능은 넣지 않았다. 정상 종료는 이름 없는
  Port Out에 트리거를 비운 자동 전이를 걸어 표현한다.
- 그래프 안에서 만드는 내장 SubGraph는 [#27](https://github.com/jaykop/Kata/issues/27)에서 다룬다.
