작성: 2026-09-24  
갱신: 2026-09-24

현재 상태 근거: [현재 구현 상태](../devlog/Implementation-Status.md)

## 목적과 현재 상태

Kata는 액션 에셋, 타임라인·프리뷰 에디터, KataGraph 콤보 전이까지 구현되어 있다.
실제 액션 게임으로 동작하려면 액션 실행 바깥의 기반 시스템이 필요하다.
이 문서는 사용자가 우선순위로 꼽은 카메라, 인풋, 타게팅, AI 퍼셉션, 스포너와
함께 필요한 전투 시스템을 정리하고, Kata와 연결되는 지점과 결정할 사항을 기록한다.

현재 이 문서의 시스템은 모두 구현되지 않았다. 각 항목은 후보이며 구현 권한을 뜻하지 않는다.

시스템 간 연결은 다음과 같다.

```
[입력] ──트리거 이벤트 태그──▶ [KataGraph 전이] ──▶ [KataAction 실행]
                                                        ▲
[퍼셉션] ──인지 목록──▶ [타게팅] ──TargetActor──▶ FKataContext
                          │
                          └──▶ [카메라] (락온 화면 구성)
[스포너] ──▶ AI 생성·수명 관리 ──▶ 퍼셉션·타게팅에 등록
```

## 범위

- 포함: 카메라, 인풋, PC·AI 공용 타게팅, AI 퍼셉션, 스포너. 함께 필요한 히트 판정·피해, 피격 반응, AI 공격 조율,
  Motion Warping, 타격감, 사망·부활, HUD 후보.
- 제외: 네트워크·예측, BT/StateTree 어댑터(KataAI 범위 결정 전까지), 구체적인 클래스·API 설계.

## 시스템별 요구

### 1. 카메라

- 카메라 모드: 탐색, 전투, 락온, 연출(처형·보스 등장). 모드 사이는 보간으로 전환한다.
- 락온 화면 구성: 플레이어와 대상이 모두 보이도록 피벗과 거리를 조정한다. 큰 대상은 거리를 늘리고 벽 근처에서는 충돌을 처리한다.
- 연출 효과: 카메라 흔들림, 히트스톱과 연동한 FOV 변화, 일시적인 오프셋 이동.
- 자동 정렬: 입력이 없으면 이동 방향 뒤쪽으로 천천히 복귀한다.
- Kata 연결: 흔들림·FOV·오프셋은 Kata 타임라인 태스크로 제공해 공격 타이밍에 맞춰 배치한다.
  태스크 완료·취소 시 효과를 원래 값으로 되돌린다.

### 2. 인풋

- Enhanced Input 입력을 Gameplay Tag 트리거 이벤트로 바꾸는 계층. KataGraph는 전이를 입력이 아니라 트리거 이벤트 태그로 받으므로
  이 계층이 입력과 그래프를 잇는다.
- 입력 버퍼: KataGraph 1단계에서는 트리거 버퍼를 끈다. 이후 선입력 유지 시간과 입력 간 우선순위(회피와 공격 등)를 정한다.
- 입력 형태: 누름, 홀드·차지, 뗌, 연타, 방향 조합, 저스트 입력(패리).
- 카메라 기준 방향 입력: 액션 시작 시 회전 결정과 타게팅 방향 가중치에 사용한다.
- 컨텍스트 전환: 전투·UI·연출 중 입력 차단을 Input Mapping Context 우선순위로 관리한다.
- Kata 연결: 입력 버퍼는 캐릭터별 실행 상태이므로 공유 에셋이 아닌 컴포넌트에 둔다. 입력 소비는 조건 평가가 아니라 실행 처리에서 수행한다.

### 3. 타게팅 (PC·AI 공용)

수집 → 필터 → 점수 → 선택 파이프라인을 PC와 AI가 공유하고 입력만 다르게 준다.

| 단계 | PC | AI |
|---|---|---|
| 수집 | 주변 오버랩, 화면 안 대상 | 퍼셉션이 인지한 목록 |
| 필터 | 팀, 생존 여부, 시야 차단 | 같음 |
| 점수 | 입력 방향, 화면 중심 거리, 실제 거리 | 위협도, 어그로, 거리 |
| 선택 | 소프트 타겟과 하드 락온 | 현재 전투 대상 |

- 소프트 타겟팅: 공격 시작 시 적절한 대상 방향으로 회전하고 Motion Warping으로 거리를 보정한다.
- 하드 락온: 스틱 플릭이나 좌우 입력으로 대상을 전환한다. 대상 사망·거리 초과 시 해제하거나 자동 전환한다.
- 팀·진영: `IGenericTeamAgentInterface`를 사용하면 AI 퍼셉션의 소속 판정과 바로 연결된다.
- Kata 연결: 선택 결과를 `FKataContext::TargetActor`에 넣는다. 이는 멀티 타겟 보류 결정(Primary 하나만 Context에 넣음)과 일치한다.
  거리·각도 판정은 `UKataFL_Condition` 순수 함수로 공용화해 타게팅 필터와 액션 조건이 같은 판정을 사용한다.

### 4. AI 퍼셉션

- 엔진 `UAIPerceptionComponent`의 시각·청각·피해 감각을 사용한다.
- 인지 단계: 모름 → 의심(수색) → 발견 → 전투 → 놓침(마지막 위치 수색) → 복귀.
- 인지 전파: 발견한 개체가 주변 동료에게 알린다.
- 액션 소음: 공격음·발소리를 Kata 태스크에서 `ReportNoiseEvent`로 보고한다.
- 위치: StateTree 기반 `KataAI` 플러그인에 둔다(2026-09-24 결정). [플러그인 분리 모듈화 계획](Plugin-Modularization-Plan.md) 참고.

### 5. 스포너

- 스폰 포인트와 조우(Encounter) 볼륨: 진입 시 발동하고 웨이브, 동시 생존 수 상한, 전멸 시 다음 웨이브를 관리한다.
- 스폰 연출: 등장 애니메이션 동안 무적으로 두고 AI를 비활성화한다.
- 수명 관리: 사망 후 정리, 체크포인트·휴식 시 재스폰, 보스 등 처치 기록 저장.
- 풀링: 반복 등장하는 일반 적은 풀링을 검토한다.
- 스폰 시 설정 주입: 팀, 초기 인지 상태, 순찰 경로.

### 목록 외 우선순위가 높은 시스템

1. 히트 판정과 피해 파이프라인: 판정 → GAS Gameplay Effect → 반응. 히트 판정 태스크는 [#6](https://github.com/jaykop/Kata/issues/6)에서 진행한다.
2. 피격 반응·경직·포이즈: 방향별 피격 모션, 슈퍼아머, 다운·기상. 피격 반응을 Kata 액션으로 표현할지 결정이 필요하다.
3. AI 공격 조율(공격 토큰): 여러 적의 동시 공격을 제한한다.
4. Motion Warping: 엔진 플러그인을 Kata 태스크로 감싸 타게팅 결과로 공격 거리와 방향을 보정한다.
5. 타격감: 히트스톱(Time Dilation), 카메라 흔들림, VFX·SFX. VFX·SFX 태스크는 [#7](https://github.com/jaykop/Kata/issues/7)에서 진행한다.
6. 사망·부활·체크포인트: 스포너와 저장이 연결된다.
7. HUD: GAS Attribute 바인딩 체력·스태미나, 락온 마커, 적 체력바. 전역 메시지 라우터는 보류했다([검토 기록](../devlog/2026-09-24-Gameplay-Message-Router-Review.md)).

순서는 의존 관계 기준이다. 인풋이 있어야 그래프 전이를 시험할 수 있고, 피해 파이프라인이 있어야 전투 루프가 성립한다.
타게팅과 카메라 락온은 강하게 결합되어 함께 진행한다.

## 영향과 제한

- 모듈 경계: 타게팅·카메라 태스크를 KataRuntime에 추가하면 런타임 공개 API가 늘어난다. AI 관련 코드는 범위 결정 전 플러그인에 넣지 않는다.
- 자원 수명: 카메라 효과·입력 버퍼·락온 상태는 캐릭터별 실행 상태이므로 공유 에셋에 저장하지 않는다.
  카메라 태스크는 완료·취소 시 효과를 되돌려야 한다.
- 싱글플레이 전용: 입력·타게팅에 복제나 예측을 추가하지 않는다.

## 사용자 확인 항목

- 각 작업의 구현 완료와 실행 확인은 별도로 기록한다. 이 문서만으로 에이전트가 빌드·테스트를 수행하지 않는다.
