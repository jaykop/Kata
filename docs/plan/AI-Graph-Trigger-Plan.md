# AI 그래프 트리거 발신 계획

작성: 2026-10-08  
갱신: 2026-10-09  
연결 이슈: [#22 KataAI 플러그인](https://github.com/jaykop/Kata/issues/22)  
현재 상태 근거: [AI 사용법](../manual/AI.md)의 Action·Graph 실행 Task 항목, [KataEdge.h](../../Plugins/Kata/Source/KataGraph/Public/KataEdge.h)  
대체 관계: 같은 날 작성한 초안(StateTree Task가 창 태그를 보고 트리거를 보내는 방식)을 이 문서로 대체했다

## 목적과 현재 상태

액션의 전이·취소 가능 구간은 타임라인의 Task 구간이 정한다. Transition Window가 전이 구간, Cancel Window가 취소 구간이다.
PC는 입력 계층이 Input 태그를 Trigger 태그로 바꿔 이 구간 안에서 그래프에 보낸다.

AI에는 구간 안에서 트리거를 보낼 주체가 없다.

- `Play KataGraph`·`Play KataActionGroup` Task는 진입 트리거만 한 번 보낸다.
- 트리거 없는 자동 전이는 액션이 끝날 때만 평가되므로 액션 도중 창에서 이어지는 콤보를 만들 수 없다.

목표는 AI용 트리거 발신 Task를 액션 타임라인에 배치해, AI도 PC와 같은 트리거 전이 경로로 콤보를 잇게 하는 것이다.

## 범위

- 포함: KataAI의 `Kata Task: AI Send Trigger` 액션 태스크와 데이터 검증, AI 사용법 갱신, 샘플 몬스터 적용.
- 제외: 코어 `KataGraph`·`KataRuntime`의 변경, 엣지의 AI 전용 옵션, AI의 자발적 이탈에 Cancel Window를 적용하는 작업(후속 항목), Pressure·공격 토큰.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 발신 방식 | 확정 | 트리거를 보내는 액션 태스크를 타임라인에 배치한다(2026-10-08 사용자 제안·결정). 타이밍을 창과 같은 타임라인에서 프레임 단위로 정할 수 있다. StateTree Task가 창 태그를 보고 보내는 초안과 엣지의 AI 옵션은 채택하지 않았다 |
| 모듈 | 확정 | 태스크는 KataAI에 `UKataTask` 파생으로 둔다. 코어는 AI와 그래프 발신을 모르게 유지한다. 발신은 소유자의 `UKataGraphComponent::SendTrigger`를 쓴다. KataAI는 이미 KataRuntime·KataGraph에 의존한다 |
| PC 제외 | 확정 | 소유 Pawn이 플레이어 조종이면 아무것도 하지 않는다. PC와 AI가 같은 액션을 공유해도 PC 콤보가 저절로 이어지지 않는다 |
| 판정 시점 | 확정 | 기본값은 Single Frame이다(2026-10-09 사용자 결정). 전이 가능 구간은 Transition Window가 정하므로 이 태스크는 입력처럼 한 시점에 보낸다. 시작한 프레임에 Chance를 굴리고 Condition을 확인해 보낸다. 같은 시각의 창 태스크보다 늦게 시작하도록 기본 Order Hint를 1로 둔다. Single Frame을 끄고 구간을 주면 Chance는 시작 때 한 번 굴리고 Condition이 참이 될 때까지 기다린다. 그래프가 받아들이면 더 보내지 않으며, 거절되면 구간 안에서 다시 시도한다 |
| 콤보 중단 | 확정 | Condition으로 다룬다. 구간이 끝날 때까지 조건이 참이 되지 않으면 보내지 않고, 액션 종료 시 자동 전이로 콤보가 끊긴다 |
| 분기 | 확정 | 갈래마다 태스크를 하나씩 둔다. 먼저 보낸 트리거로 그래프가 전이하면 같은 창의 다른 트리거는 성립하지 않는다 |
| 설정 항목 | 제안 | Trigger Tag(`Categories = "Trigger"`), Condition(`UKataCondition`, 비우면 통과), Chance(0~1, 기본 1). 실행 상태(굴린 결과, 발신 여부)는 태스크 인스턴스에 두고 에셋에 저장하지 않는다 |
| 창 정합성 검증 | 결정 필요 | 같은 액션 안에서 Transition Window 태스크와 구간이 겹치지 않으면 경고하기로 했다(2026-10-08). 액션 검증은 해석된 타임라인의 태스크별 `GetConfigurationError`만 보므로 태스크가 다른 태스크의 구간을 볼 수 없다. 코어에 해석된 타임라인 전체를 받는 검증 확장 지점을 둘지, KataAI에 에디터 모듈을 두고 Editor Validator로 검사할지 정한다 |
| Condition의 대상 | 확정 | AI 타게팅의 현재 대상을 쓴다. 타게팅 컴포넌트가 없으면 액션 Context의 대상이다. 콤보 도중 대상이 바뀌거나 사라진 것을 반영한다(2026-10-08) |
| 프리뷰 | 제안 | 액션 편집기 프리뷰에는 그래프와 AI가 없으므로 아무것도 하지 않는다 |

## 후속 항목: AI의 자발적 이탈과 Cancel Window

2026-10-08 사용자와 다음 원칙을 확정했다. 구현은 회피·가드 같은 반응 행동이나 Pressure를 설계할 때 함께 한다.

- AI가 스스로 고른 이탈(회피·가드·다른 행동으로 전환)은 PC처럼 액션의 Cancel Window를 지킨다. 후딜은 플레이어가 반격하는 틈이고, PC와 AI가 같은 타임라인 규칙을 따라야 디자이너가 적 행동을 예측할 수 있다. 적마다 다르게 하려면 그 적의 액션에 Cancel Window를 넓게 둔다.
- 강제 중단은 예외로 구간과 무관하게 끊는다. 피격 경직·넉다운(#23), 사망, 페이즈 전환이나 연출이 해당한다.
- 현재 StateTree가 공격 상태를 이탈하면 `Play KataGraph`가 그래프를 즉시 정리해 구간과 무관하게 끊긴다. 자발적 이탈은 `TryCancelKata`로 취소 가능 여부를 확인하는 조건이나 Task를 거치게 바꾼다.

## 영향과 제한

- 모듈: KataAI만 바뀐다. Condition을 쓰려고 KataAI의 Public 의존에 KataConditions를 추가했다. 코어 의존 방향은 그대로다.
- 사용 규정 변경: AI 사용법의 "Task가 반복 Trigger를 생성하지 않는다"는 문장을 고친다. StateTree Task는 계속 진입 트리거만 보내고, 이후 트리거는 액션 태스크가 보낸다.
- 트리거는 호출된 프레임에만 평가된다(입력 버퍼 없음). 태스크가 창보다 먼저 보내면 무시되므로 구간 배치가 중요하다.
- 수명: 태스크 인스턴스는 액션 종료·취소·중단 시 정리되며 이벤트 구독을 남기지 않는다.

## 사용자 확인 항목

- 구현 완료: GT-2 소스 반영.
