# AI 그래프 트리거 발신 계획

작성: 2026-10-08  
갱신: 2026-10-08  
연결 이슈: [#22 KataAI 플러그인](https://github.com/jaykop/Kata/issues/22)  
현재 상태 근거: [AI 사용법](../manual/AI.md)의 Action·Graph 실행 Task 항목, [KataEdge.h](../../Plugins/Kata/Source/KataGraph/Public/KataEdge.h)  
대체 관계: 없음

## 목적과 현재 상태

PC는 입력 계층이 Input 태그를 Trigger 태그로 바꿔 그래프에 보낸다. AI에는 이 역할을 하는 발신자가 없다.

- 엣지의 트리거 전이는 현재 액션의 Transition Window(`RequiredWindowTag`)가 열렸을 때 트리거를 받아 성립한다.
- 트리거 없는 자동 전이는 액션이 끝날 때만 평가된다. 액션 도중 창에서 끊고 넘어가는 콤보를 AI가 낼 수 없다.
- `Play KataGraph`·`Play KataActionGroup` Task는 진입 트리거만 한 번 보낸다. 이후 트리거는 "별도 발신자"에 맡겼지만 그 발신자는 없다.

목표는 KataAI가 PC의 입력 자리에서 트리거를 보내는 것이다. 그래프·액션 에셋은 PC와 공유하고, 언제 무엇을 보낼지는 AI 쪽 데이터가 정한다.

## 범위

- 포함: 실행 중인 그래프에 AI가 트리거를 보내는 규칙 데이터, 규칙을 평가해 `UKataGraphInstance::SendTrigger`를 호출하는 KataAI 실행 코드, `Play KataGraph`·`Play KataActionGroup`의 Graph 항목 연결.
- 제외: 코어 `KataGraph`·`KataRuntime`의 변경, 액션 타임라인의 트리거 발신 태스크, 엣지의 AI 전용 옵션, Pressure·공격 토큰.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 발신 위치 | 확정 | KataAI가 트리거를 보낸다(2026-10-08 사용자 결정, A안). 엣지 옵션(B안)은 코어 그래프에 AI 정책이 섞이고, 액션 태스크(C안)는 PC가 같은 액션을 쓸 때 자동 콤보가 되므로 채택하지 않았다 |
| 코어 변경 | 확정 | 없음. 엣지는 이미 트리거로 발동하며 입력·AI가 같은 경로를 쓰도록 설계됐다. 창 확인은 `UKataActionInstance::IsTransitionWindowOpen`을 쓴다 |
| 규칙 형태 | 제안 | 규칙 하나는 Trigger 태그, 대상 창 태그, 조건(`UKataCondition`), 확률, 창 안 지연으로 구성한다. 실행 중 판정 기록은 Task 인스턴스 데이터에 두고 규칙 에셋에는 저장하지 않는다 |
| D1 규칙 위치 | 결정 필요 | ① Task 파라미터: 단순하지만 상태마다 다시 적는다. ② 별도 데이터 에셋(예: 그래프별 AI 트리거 프로필): 여러 상태·몬스터가 재사용한다. ③ Action Group 항목 Payload: 그룹의 Graph 항목마다 규칙을 붙인다. ②를 기본으로 하고 Task·Payload가 에셋을 가리키는 방식을 제안한다 |
| D2 판정 방식 | 결정 필요 | ① 창이 열릴 때마다 한 번 판정(확률·조건)하고 결과를 그 창 동안 유지한다. ② 창이 열린 동안 조건이 맞으면 계속 보낸다. 예측 가능한 콤보 길이를 위해 ①을 제안한다 |
| D3 중단 정책 | 결정 필요 | 대상 상실·피격 때 콤보를 끊는 정책을 이 규칙에서 다룰지(조건이 거짓이면 보내지 않음), Pressure 후속으로 미룰지 정한다 |
| D4 창 없는 엣지 | 결정 필요 | `RequiredWindowTag`가 빈 엣지는 액션 내내 트리거를 받는다. 규칙의 창 태그를 비우면 액션 시작 직후 보낼지, 비운 규칙을 금지할지 정한다 |
| 진입 트리거 | 확정 | 기존 Entry Trigger 동작은 유지한다 |

## 작업 순서와 완료 조건

| ID | 우선순위 | 작업 | 선행 조건 | 완료 조건 |
|---|---|---|---|---|
| GT-1 | 높음 | D1~D4 결정과 규칙 데이터 정의 | 사용자 결정 | 규칙 구조와 위치가 이 문서에 확정된다 |
| GT-2 | 높음 | 규칙 평가와 `SendTrigger` 호출을 KataAI에 구현하고 `Play KataGraph`에 연결 | GT-1 | 창이 열린 액션에서 규칙대로 다음 노드로 전이한다 |
| GT-3 | 보통 | `Play KataActionGroup`의 Graph 항목 연결 | GT-2 | 그룹에서 고른 그래프도 같은 규칙으로 이어진다 |
| GT-4 | 보통 | 매뉴얼과 샘플 몬스터 적용 | GT-2 | AI 사용법에 설정 절차가 있고 샘플 그래프가 콤보를 잇는다 |

## 영향과 제한

- 모듈: KataAI만 바뀐다. 코어는 변경하지 않으며 의존 방향은 그대로다.
- 사용 규정 변경: AI 사용법의 "Task가 반복 Trigger를 생성하지 않는다"는 문장이 바뀐다.
- 수명: 판정 기록은 Task 인스턴스 데이터에 두고 상태 이탈 시 지운다. 그래프 인스턴스는 약한 참조로 본다.
- 트리거는 호출된 프레임에만 평가된다(입력 버퍼 없음). 창이 열린 뒤에 보내야 하며, 창의 선입력(PreAccept) 구간을 쓸지는 GT-1에서 정한다.

## 사용자 확인 항목

- 구현 완료: GT-2 소스 반영.
- 실행 확인: 샘플 몬스터가 창에서 다음 공격으로 이어지는지, 확률 0·1과 조건 거짓에서 이어지지 않거나 항상 이어지는지, 상태 이탈 시 트리거가 멈추는지.
