# 상호작용 시스템 계획

작성: 2026-10-12  
갱신: 2026-10-12  
연결 이슈: [#62 상호작용 시스템](https://github.com/jaykop/Kata/issues/62). 로드맵 [#24](https://github.com/jaykop/Kata/issues/24)  
현재 상태 근거: 구현 없음. [진행도·퀘스트 시스템 사전 검토](../devlog/2026-10-11-Progress-Quest-System-Review.md)가 목표 이벤트 소스로 상호작용이 없다고 기록했다. 재사용할 구조는 [피격 반응 사용법](../manual/Hit-Reaction.md), [입력 사용법](../manual/Input.md), [MainHUD 사용법](../manual/HUD.md), [기본 조건](../manual/Conditions.md)에 있다  
대체 관계: 없음

## 목적과 현재 상태

플레이어가 문·레버 같은 월드 오브젝트에 다가가면 프롬프트가 보이고, 입력하면 캐릭터가 상호작용 액션을 재생하며, 액션의 정해진 시점에 오브젝트가 반응해야 한다.
아이템 줍기([#42](https://github.com/jaykop/Kata/issues/42))와 퀘스트 목표([#59](https://github.com/jaykop/Kata/issues/59))도 이 사건을 이용한다.

현재 Kata에는 상호작용 대상의 정의, 후보 탐지, 프롬프트, 실행 경로가 없다. 다음 기반은 이미 있어 그대로 쓸 수 있다.

| 기반 | 위치 | 상호작용에서의 쓰임 |
|---|---|---|
| 이벤트로 활성화되어 Kata 액션을 재생하는 GA | `UKataHitReactionAbility`, `UAbilityTask_PlayKataAction` | 상호작용 GA의 실행 방식 |
| 타임라인의 한 시점에 Gameplay Event를 보내는 태스크 | `UKataTask_SendGameplayEvent` | 오브젝트가 반응할 확정 시점 |
| 부작용 없는 조건 판정 | `UKataCondition` | 상호작용 사용 가능 조건 |
| 그래프를 거치지 않는 고정 기능 입력 | `UKataInputConfig`의 락온 입력 | 상호작용 입력 |
| 폰의 알림을 컨트롤러가 HUD로 전달하는 경로 | `AKataPlayerController` → `UKataMainHUD`(락온 마커) | 프롬프트 표시 |
| Ability·Kata·그래프를 함께 끝내는 공용 중단 | `UKataActionComponent::CancelAbilitiesAndKata` | 사망 시 상호작용 정리 |
| 캐릭터별 Ability 부여 | Gameplay Data의 Granted Abilities | 상호작용 GA 부여 |

## 범위

- 포함: 상호작용 대상 컴포넌트(영역, 사용 조건, 액션 지정, 프롬프트 문구, 정렬 지점, 1회용·반복), 상호작용자 컴포넌트(후보 등록, 포커스 선택, 포커스 변경 알림),
  상호작용 GA(액션 재생, 확정·취소 알림), 위치 정렬, 입력 연결, HUD 프롬프트, 샘플 대상 하나(문 또는 레버).
- 제외: 1회용 상태 저장(세이브 계층이 없다), 아이템 줍기(#42), 퀘스트 목표 연결(#59), AI의 상호작용 사용(후속 StateTree Task), 선택지 메뉴와 NPC 대화.

## 설계안

아래 구조는 모두 제안이다. 사용자가 확정한 항목은 "확정 사항과 미확정 사항" 표에만 적는다. 클래스 이름은 가칭이다.

### 흐름

1. 상호작용자가 대상의 영역에 겹치면 대상이 상호작용자에 후보로 등록하고, 벗어나면 해제한다.
2. 상호작용자는 후보가 있을 때만 Tick하며 사용 가능한 후보 중 포커스 하나를 고른다. 포커스가 바뀌면 `OnFocusChanged`로 알린다.
3. 상호작용 입력이 들어오면 상호작용자가 포커스 대상을 Payload에 담아 Gameplay Event를 보내고, 이 이벤트가 상호작용 GA를 활성화한다.
4. GA는 대상을 점유하고 대상이 지정한 Kata 액션을 재생한다. Context의 `TargetActor`는 대상 액터이므로 Resolve Facing 같은 기존 Command를 그대로 쓸 수 있다.
5. 액션 타임라인의 `Send Gameplay Event` 태스크가 확정 이벤트를 보내면 GA가 대상의 `OnCommitted`를 부른다. 확정 이벤트가 없는 액션은 정상 종료 시점에 확정한다.
6. 액션이 끝나면 `OnEnded`, 확정 전에 끊기면(피격, 사망, 캔슬) `OnCancelled`를 부르고 점유를 해제한다.

### 구성 요소

| 구성 요소(가칭) | 붙는 곳 | 역할 |
|---|---|---|
| `UKataInteractableComponent` | 오브젝트 액터 | 영역 자체가 되는 Shape 컴포넌트다. 컴포넌트 하나가 상호작용 하나이며, 문 양면에 다른 동작을 주려면 두 개를 붙인다. 사용 조건, 액션 지정, 프롬프트 문구(`FText`), 우선순위, 정렬 지점(상대 Transform), 1회용·반복, 시작·확정·종료·취소 델리게이트를 갖는다 |
| `UKataInteractorComponent` | 폰 | 후보 목록(약한 참조), 포커스 선택, `OnFocusChanged`, `TryInteract`. PC 전용 기능을 넣지 않아 AI 폰에도 붙일 수 있게 둔다 |
| `UKataInteractAbility` | Gameplay Data로 부여 | Blueprint 자식에서 Ability Triggers(시작 이벤트)와 Activation Blocked Tags(사망·피격 중 등)를 설정한다. 점유, 액션 재생, 확정 대기, 대상 알림을 맡는다 |
| 정렬 태스크 | 상호작용 액션의 타임라인 | 위치 정렬 방식을 정한 뒤 추가 여부를 정한다 |

시작·확정 이벤트 태그는 기존 `Event` 루트 아래에 샘플이 정의하고, 플러그인은 태그를 정의하지 않는다.

### 포커스 선택

- 점수는 캐릭터 정면과 대상 방향 사이 각도, 거리, 대상 우선순위로 계산한다. 화면 중앙이 아니라 캐릭터 정면을 기준으로 둔다.
- 사용 조건을 만족하지 않는 후보는 포커스에서 뺀다. "잠겨 있다" 같은 메시지는 그 메시지를 보여 주는 별도 상호작용으로 표현한다.
- GA가 활성인 동안에는 포커스를 고정하고 프롬프트를 숨긴다.
- 조건은 `FKataConditionContext`에 상호작용자를 소유자로, 대상 액터를 대상으로 넣어 평가한다.

### 검토했지만 채택하지 않은 안

| 안 | 채택하지 않은 이유 |
|---|---|
| TargetingSystem Preset으로 주기 탐색 | UE 5.8에서 Beta이고 매번 탐색해야 한다. "문 앞 이 자리에서만", "한쪽에서만" 같은 조건은 영역 배치로 표현하는 편이 직접적이다 |
| 그래프 Trigger로 실행 | 그래프는 어느 대상과 상호작용하는지 모른다. 모든 캐릭터 그래프에 상호작용 종류마다 엣지를 그어야 한다 |
| 상호작용자 컴포넌트가 액션을 직접 재생 | GA의 차단 태그와 공용 중단, 종료 시 정리를 다시 구현해야 한다 |
| 엔진 SmartObjects | 5.8 정식이지만 AI가 오브젝트를 쓰는 슬롯·점유 체계에 초점을 둔다. 플레이어 프롬프트와 액션 연결은 결국 직접 만들어야 한다. AI가 오브젝트를 쓰는 단계에서 다시 검토한다 |
| 엔진 GameplayInteractions | 5.8에서 Experimental이다 |

상호작용 GA는 [Kata 액션과 Gameplay Ability 경계](../devlog/2026-10-11-Kata-Action-Ability-Boundary.md)에서 기각한 "모든 Kata를 범용 GA 안에서 실행"과 다르다.
피격 반응·사망 GA처럼 특정 사건 하나를 맡는 GA다.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 착수 범위 | 확정 | 2026-10-12 사용자 결정. 이번에는 계획 문서와 이슈만 만들고 구현하지 않는다 |
| 네트워크 | 확정 | 싱글플레이 전용이며 복제·RPC를 넣지 않는다([AGENTS.md](../../AGENTS.md)) |
| 배치 | 결정 필요 | (a) 새 위성 `KataInteraction`(코어 `Kata`와 GAS만 의존)에 두고 입력·HUD 연결은 `KataFramework`가 맡는다. (b) 전부 `KataFramework`에 둔다. 제안은 (a)다. 상호작용에는 타게팅·AI·카메라가 필요 없고, (b)는 통합 플러그인 없이 쓸 수 없다 |
| 상호작용 형태 | 결정 필요 | 문·레버·줍기처럼 한 번 재생하고 끝나는 형태만 둘지, 화톳불에 앉아 있기처럼 나갈 입력까지 유지하는 형태도 넣을지 정한다. 유지형을 넣으면 GA 수명과 종료 입력 설계가 늘어난다 |
| 액션 지정 방식 | 결정 필요 | (a) 대상이 Kata 액션을 직접 지정한다. (b) 대상은 상호작용 종류 태그만 갖고, 캐릭터 쪽 매핑이 스켈레톤에 맞는 액션을 고른다. (b)는 [장비의 Anim Layer 해석](Equipment-Plan.md)과 같은 원리이며 새 태그 루트가 필요하다. 상호작용하는 캐릭터의 스켈레톤이 여러 종류인지가 판단 기준이다 |
| 위치 정렬 | 결정 필요 | (a) 액션 앞 구간에서 캡슐을 정렬 지점으로 보간하는 자체 태스크. (b) 엔진 Motion Warping(5.8 Beta 0.1) 의존 추가. (c) 위치는 맞추지 않고 방향만 맞춘다. 제안은 (a)다. (b)는 루트 모션 커브 컴포넌트와 함께 쓸 때 충돌하는지 확인이 필요하다 |
| HUD 프롬프트 | 결정 필요 | [#61](https://github.com/jaykop/Kata/issues/61)에서 HUD 계층을 MVVM으로 바꿨다([MainHUD MVVM 결정 기록](../devlog/2026-10-14-Main-HUD-MVVM.md)). 프롬프트를 ViewModel로 만들지, 컨트롤러 전달 경로로 만들지 정한다 |
| 후보 탐지 | 제안 | 대상 영역의 겹침으로 후보를 등록한다. 위 "검토했지만 채택하지 않은 안" 참고 |
| 실행 경로 | 제안 | 상호작용 GA가 Kata 액션을 재생한다 |
| 확정 시점 | 제안 | `Send Gameplay Event` 태스크의 확정 이벤트. 없으면 정상 종료 시 확정한다 |
| 포커스 기준 | 제안 | 캐릭터 정면 기준 각도·거리·우선순위. 조건 불충족 후보는 제외한다 |
| 영역 모양 | 제안 | Box 파생 컴포넌트. 다른 모양이 필요해지면 다시 검토한다 |
| AI 사용 | 제안 | 이번 범위에서 제외한다. 상호작용자 컴포넌트를 폰 공용으로 만들어 후속 StateTree Task가 쓸 수 있게 둔다 |

## 영향과 제한

- 새 위성 플러그인으로 결정하면 [AGENTS.md](../../AGENTS.md)의 "프로젝트와 현재 범위"와 [플러그인 분리 결정 기록](../devlog/2026-10-10-Plugin-Modularization-Decisions.md)의 구성 표를 갱신하고, 이슈 라벨 `plugin: interaction` 추가를 검토한다.
- 입력 설정에 상호작용 InputAction 항목이 추가된다. 기존 입력 설정 에셋은 이 값이 비어 있으므로 상호작용 입력이 없는 것으로 동작한다.
- 후보 목록은 약한 참조로 두고, 대상이 파괴되거나 영역이 비활성화되면 해제한다. GA가 끝나면 점유와 이벤트 구독을 해제한다.
- 세이브 계층이 없으므로 1회용 대상의 사용 여부는 레벨을 다시 시작하면 초기화된다.
- 샘플 대상과 태그는 샘플 프로젝트에 두며 `Content/KataSample`은 cooked 빌드에 포함하지 않는다.

## 사용자 확인 항목

- 구현 완료 조건: IA-1~IA-5의 완료 조건을 코드와 샘플 에셋으로 충족한다.
- 실행 확인 조건: Editor·Game 빌드, PIE에서 프롬프트 표시·숨김, 여러 후보의 포커스 전환, 입력 시 액션 재생과 확정 시점 반응, 확정 전 피격 시 반응 없음, 사망 시 정리, 1회용 재사용 불가.
- 이 목록은 에이전트에게 빌드·테스트 실행 권한을 주지 않는다.
