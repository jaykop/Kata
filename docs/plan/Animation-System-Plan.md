## 목적과 현재 상태

Kata 의 애니메이션은 이미 다음 요소로 동작한다.

- 메인 Template ABP 하나와 Linked Anim Layer(무기 레이어, Body 레이어). 이동값은 `UKataAnimInstance` 가 계산한다.
- 행동은 KataAction 의 Play Montage 로 재생하고, KataGraph 가 트리거·전이 창·캔슬 창·선입력 보관·엣지 우선순위로 다음 행동을 정한다.
- 회전은 `Rotate To Facing`, 상체 기울기는 Target Tilt, 발 IK 는 Body 레이어의 Control Rig 가 맡는다.

이 계획은 참고 분석(비공개 자료)에서 정리한 액션 게임 애니메이션 구조를 이 구성 위에 옮기는 설계다. Animation Blueprint 를 대신하는 런타임은 만들지 않는다. #89 의 결정 대기 항목(제자리 회전, 방향 클립 처리, 출발·정지)과 워핑 사용 여부를 정하고, 그 뒤의 구성 작업 순서를 둔다.

## 범위

- 포함: ABP 상태 머신과 KataAction·KataGraph 의 역할 분담, 행동 판정 우선순위와 입력 종류별 창 규약, 액션 블렌드·회전·무적 저작 기준, 이동(방향·락온·제자리 회전·출발·정지), LookAt·발 IK 의 액션별 제어, 애니 묶음 선택 키.
- 제외: Animation Blueprint 를 대신하는 런타임, 엔진 버전 변경과 UAF 전환, Motion Matching 도입(이동 품질 요구가 정해진 뒤 다시 본다), 장비 계획 EQ-6 의 손별 레이어 구현 자체.

## 확정 사항과 미확정 사항

| ID | 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|---|
| D1 | 범위 | 확정 | ABP 를 대신하는 런타임은 만들지 않고 UE 기능 위에 옮긴다(2026-10-14, #105) |
| D2 | 역할 분담 | 확정 | ABP 상태 머신은 이동 루프(대기·이동·정지·공중)만 맡는다. 공격·회피·제자리 회전·피격·아이템 같은 행동은 모두 KataAction(몽타주)과 KataGraph 가 맡는다(2026-10-15 사용자 결정). 참고 구조에서도 행동 상태로 가는 길 대부분은 "어느 상태에서든 사건 하나로 바로 가는" 전이였다 |
| D3 | 판정 우선순위 | 확정 | 상태 종류마다 행동 후보를 고정 순서로 시험하는 구조를 엣지 Priority 규약으로 옮긴다(예: 회피 > 아이템 > 마법 > 공격 > 이동 캔슬). 동시에 들어온 입력은 지금처럼 "마지막 입력 하나만 보관"한다. KataGraph 의 보관 계약은 바꾸지 않는다(2026-10-15 사용자 결정). 규약의 Priority 값은 AS-5 에서 정한다 |
| D4 | 입력 종류별 창 | 제안 | 전이 창을 입력 종류별 태그로 나눈다(`Window.Transition.Attack`·`Dodge`·`Guard`·`Item`·`Magic`·`Skill`, 이동은 `Window.Cancel.Move`). 공격 뒤 창이 열리는 순서는 공격·회피가 먼저, 가드·마법·아이템, 이동이 마지막이다. 저작 기준값(마지막 판정 끝 기준 중앙값): 다음 공격·회피 약 0.4~0.6초, 가드·마법 약 0.65초, 이동 약 0.7~0.9초 |
| D5 | 선입력 | 제안 | 각 전이 창의 Pre Accept Seconds 를 최소 2프레임(약 0.067초) 이상으로 둔다. 판정을 창보다 2프레임 앞에서 시작하는 것이 참고 구조의 값이다 |
| D6 | 콤보 | 제안 | 액션 노드마다 "입력 종류 → 다음 액션" 엣지 표를 둔다. 반복 콤보(2·3 단 반복 등)는 순환 엣지, 콤보 상한·초기화는 엣지 조건으로 둔다. 다른 입력에서 이어 들어올 때 쓰는 "이어서 시작" 변형은 별도 액션으로 둔다 |
| D7 | 액션 블렌드 | 제안 | 행동 블렌드 길이는 액션(몽타주 Blend In)이 정하고 기본 0.2초(대개 0.1~0.33초)로 둔다. ABP 상태 머신의 전이는 짧게(0~0.1초) 두어 이중 블렌드를 피한다 |
| D8 | 공격 중 회전 | 제안 | 공격 시작 회전 구간은 약 0.8초 이내, 속도는 PC 기본 540°/s 를 기준으로 하고 그 뒤는 회전을 막는다. 샘플의 "공격 회전은 시작 0.15초만"(LV_CombatSandbox 플레이 메모 조치)은 이 기준보다 짧다. 플레이로 다시 정한다 |
| D9 | 제자리 회전 (#89) | 제안 | ABP 상태가 아니라 KataAction 몽타주(좌우 90°·180°)로 한다. 적은 AI 가, PC 는 입력·각도 조건으로 시작한다(2026-10-11 분석의 제안과 같다) |
| D10 | 방향 이동 (#89) | 제안 | PC 는 4방향 BlendSpace 와 Sync Group(발 접촉 Sync Marker)으로 방향이 바뀔 때 위상을 맞춰 섞는다(참고 기준 약 0.23초). 방향 클립이 앞뒤뿐인 캐릭터와 락온 옆걸음은 Orientation Warping 을 시험한다(신기술 고문 진단의 시험 계획). 시험에서 워핑 노드가 요구하는 IK 발 본을 가상 본으로 채우는 것은 허용한다(2026-10-15 사용자 결정. 발 IK 결정 F6 의 "가상 본 추가 안 함"은 발 IK 범위로 남는다). 채택 여부는 시험 결과로 정한다 |
| D11 | 락온 이동 (#89) | 제안 | 락온 중에는 회전 방식을 "대상 바라보기"로 바꾸고 방향 이동을 쓴다. ABP 에 락온 전용 분기를 두지 않는다 |
| D12 | 출발·정지 (#89) | 제안 | 출발 상태는 두지 않는다. PC 정지는 방향별 정지 클립(앞·뒤·좌·우, 걷기·달리기)을 ABP 정지 상태에서 고른다. 적은 정지 대신 전투 자세 전환 액션을 쓴다. 정지 클립 추출은 이동 품질 요구(장르 결정 #81 때 정함) 뒤에 한다 |
| D13 | 판정·무적·효과 | 확정 | 기존 태스크로 표현한다: Hit Trace, Apply Loose Tag(무적 등 Status 태그), Apply Gameplay Effect, Play Sound·Camera Shake·Spawn VFX |
| D14 | LookAt 프로필 | 제안(낮음) | Target Tilt 설정을 "프로필 에셋(각도 제한·기준 위치)"으로 빼고, 액션 태스크가 프로필을 고르고 제한을 덮는 구조로 넓힌다. 공격 기본 프로필은 상하만(위 30°·아래 35°). [#51](https://github.com/jaykop/Kata/issues/51) 상시 LookAt 과 함께 본다 |
| D15 | 액션 중 발 IK 끄기 | 제안 | 액션 타임라인의 구간 태스크로 발 IK 를 끈다(Body 레이어가 읽을 C++ 값 필요). 지금의 `DisableFootIK` 커브 경로([#53](https://github.com/jaykop/Kata/issues/53) FI-3)를 이 방식으로 대신할지 #53 에서 정한다 |
| D16 | 애니 묶음 선택 키 | 제안 | 무기 데이터에 "동작 종류", "고유 동작(있으면 우선)", "잡기 자세(한손·양손)" 키를 두고 `UKataAnimLayerSetup` 이 고른다. 마법·스킬은 무기 레이어가 아니라 능력 데이터가 액션을 지정한다. 손별 키는 [장비 계획](Equipment-Plan.md) EQ-6, 양손 잡기 도입 여부는 #81 뒤에 정한다 |
| D17 | 애니메이션 API 의존 | 확정 | Kata 코드가 애니메이션 API(AnimInstance·AnimNode·Anim Layer Interface 등)에 직접 묶이는 범위를 지금 수준(14 파일)에서 늘리지 않는다. 새 C++ AnimNode·ABP 전용 기능은 꼭 필요할 때만 더하고, 절차적 처리는 Control Rig 에 둔다. 엔진의 차세대 애니메이션 프레임워크로 옮길 때 비용을 줄이기 위해서다(2026-10-15 사용자 결정, AGENTS.md 구현 원칙에 반영) |

## 영향과 제한

- 모듈 경계: 새 태스크와 Body 레이어 값은 `KataFramework` 에 둔다. 코어 `Kata` 에는 엔진 플러그인 의존을 더하지 않는다. Animation Warping 을 쓰게 되면 샘플 ABP 에서만 쓰고 Kata 코드는 참조하지 않는다.
- 태그: 입력 종류별 `Window.Transition.*` 태그를 더하면 [게임플레이 태그](../manual/Gameplay-Tags.md) 루트 표와 샘플 `Config/Tags/Window.ini` 를 갱신한다.
- 에셋: 샘플 ABP·BlendSpace·몽타주·그래프를 다시 저장한다. 기존 몽타주의 Blend In 값은 D7 기준으로 다시 맞춘다.
- D3 은 보관 규칙을 유지하므로 KataGraph 의 트리거 보관 계약은 바뀌지 않는다.
- D10 시험에서 가상 본을 더하면 시험 캐릭터 한 종의 스켈레톤 에셋을 다시 저장한다.

## 사용자 확인 항목

- AS-2~AS-8 은 각 완료 조건의 PIE 확인이 필요하다. 이 문서는 빌드·테스트 실행 권한을 주지 않는다.
- 저작 기준값(D4·D5·D7·D8)은 참고 분석의 중앙값이다. 샘플 플레이 감각으로 다시 정할 수 있다.
