작성: 2026-09-27  
갱신: 2026-09-27

대체 관계: [액션 게임 기반 시스템 계획](Action-Game-Systems-Plan.md)의 "1. 카메라" 절을 구체화한다.

## 목적과 현재 상태

플레이어 카메라를 위성 플러그인 `KataCamera`로 제공한다. 카메라는 전통적인 SpringArm(Boom Arm) 대신
플레이어 기준 궤도 트랙을 따라 움직이며, 상태별 프로필과 블렌딩, 장애물 회피, 디더링, 락온 화면 구성을 갖춘다.

현재 카메라 코드는 없다. `KataCamera` 플러그인도 아직 만들지 않았다.
락온 대상 선택과 좌·우 전환은 `UKataPlayerTargetingComponent`에 구현되어 있고, 대상 변경은 `OnLockTargetChanged(Old, New)`로 알린다.
카메라는 이 알림을 받아 화면 구성과 전환 블렌드만 맡는다.

## 범위

- 포함: `KataCamera` 플러그인 뼈대, 카메라 프로필 데이터, 궤도 트랙, 카메라 상태와 블렌딩, 장애물 Shrink,
  디더링(가림 물체·캐릭터 자신), 락온 화면 구성과 대상 전환 블렌드, 디버그 표시, KataFramework 캐릭터 조합.
- 제외:
  - 카메라 흔들림·FOV 펀치·일시 오프셋 등 타격감 태스크: [#23](https://github.com/jaykop/Kata/issues/23).
  - 입력 액션을 락온 호출로 잇는 부분: 입력 계층 [#19](https://github.com/jaykop/Kata/issues/19).
  - 락온 대상 선택·전환 규칙: KataTargeting [#13](https://github.com/jaykop/Kata/issues/13).
  - 월드에 배치한 레일을 따라가는 연출 카메라, 처형·보스 등장 연출 카메라.
  - 입력이 없을 때의 자동 정렬. 기본 조작 확인 뒤 후속 작업으로 검토한다.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 플러그인 위치 | 확정 | 위성 플러그인 `KataCamera`. [플러그인 분리 모듈화 계획](Plugin-Modularization-Plan.md) |
| 카메라 기반 | 확정 | 2026-09-27 사용자 결정. 자체 구현한다. 엔진 GameplayCameras 플러그인은 5.8에서 Experimental(0.1)이고 장기 유지보수를 보장할 수 없다고 판단해 의존하지 않는다 |
| 트랙 형태 | 확정 | 2026-09-27 사용자 결정. SpringArm 대신 플레이어 기준 궤도 트랙을 쓴다. 월드에 배치하는 Spline 레일이 아니다 |
| 트랙 조작 방식 | 제안 | Yaw는 트랙이 놓인 로컬 수직 평면을 피벗 주위로 회전한다. Pitch는 트랙 위 위치를 정하는 매개변수이며, 트랙 양 끝이 피치 제한이 된다 |
| 트랙 표현 | 제안 | 피치(도)를 입력으로 받는 커브: 카메라 위치 오프셋(뒤·옆·위), 조준점 오프셋, FOV. 시선을 위치 커브만으로 정하지 않고 조준점 오프셋으로 보정한다 |
| 평가 위치 | 결정 필요 | (A) `UCameraComponent`를 상속한 컴포넌트가 `GetCameraView`에서 평가한다. 상태가 폰에 속해 빙의가 바뀌면 함께 바뀐다. (B) `APlayerCameraManager` 파생 클래스가 `UpdateViewTarget`에서 평가한다. 상태가 플레이어에 속해 빙의·리스폰에도 유지되고, 피치 제한(`ViewPitchMin/Max`)·흔들림·뷰 타깃 블렌드와 같은 곳에 있다. 상태 선택을 StateTree로 하면 (B)를 권장한다 |
| 상태 선택 | 제안 | 2026-09-27 사용자 검토안. PC 카메라용 StateTree가 상태를 고르고, 상태 진입 태스크는 카메라 프로필과 블렌드 설정만 선언한다. 매 프레임 계산과 블렌드는 카메라 평가기가 블렌드 스택으로 수행한다. 블렌드 중 새 전이가 오면 현재 섞인 결과에서 다시 블렌드한다. StateTree는 카메라 갱신 시점에 직접 평가해 한 프레임 지연을 피한다 |
| 상태 전이 조건의 입력 | 제안 | StateTree 조건은 카메라가 가진 값(초점 대상 유무, 소유자 ASC 태그)만 읽는다. 락온 대상은 `KataFramework`가 카메라 초점 대상 API로 넣는다 |
| 블렌딩 공간 | 제안 | 최종 위치를 직선 보간하면 캐릭터를 관통할 수 있다. 피벗, Yaw, 트랙 매개변수, 오프셋처럼 궤도 공간의 값을 보간한 뒤 위치를 계산한다 |
| Shrink 방식 | 제안 | 피벗에서 목표 위치까지 구 스윕(`ECC_Camera`)하고 충돌 지점으로 광선을 따라 당긴다. 트랙을 따라 이동하지 않는다. 당길 때는 빠르게, 복귀할 때는 느리게 보간한다 |
| 디더링 방식 | 제안 | 카메라와 피벗 사이를 가리는 프리미티브와 가까운 캐릭터 자신에 Custom Primitive Data 스칼라로 페이드 값을 준다. 머티리얼이 그 인덱스를 읽어 디더 마스크를 만들어야 한다 |
| 디더링 순서 | 확정 | 2026-09-27 사용자 결정. 후순위로 미룬다. 머티리얼 함수 제공 방식은 착수할 때 정한다 |
| 락온 연결 경로 | 제안 | 위성 간 의존을 만들지 않기 위해 `KataCamera`는 `KataTargeting`을 참조하지 않는다. `KataFramework` 캐릭터가 `OnLockTargetChanged`를 구독해 카메라의 초점 대상 API를 호출한다 |
| 락온 화면 구성 | 제안 | Yaw는 플레이어→대상 방향에 옆 오프셋을 더해 정하고, Pitch는 높이 차로 정해 같은 트랙을 쓴다. 대상 크기에 따라 거리 배율을 준다. 대상 전환은 Yaw 블렌드로 처리한다 |
| 락온 중 입력 | 확정 | 2026-09-27 사용자 결정. 락온 중에는 대상 전환과 락온 해제 입력만 받고 시점 입력은 무시한다. 입력 차단은 입력 계층의 IMC 추가·제거로 하고, 락온 상태의 카메라도 시점 입력을 반영하지 않는다. 락온 상태는 카메라 회전을 컨트롤 회전에 기록해 해제 시 튀지 않게 이어간다 |

## 작업 순서와 완료 조건

|---|---|---|---|---|
| CAM-1 | 높음 | `KataCamera` 플러그인 뼈대, 카메라 프로필 데이터 에셋, 카메라 컴포넌트, KataFramework 캐릭터 조합 | 평가 위치 결정 | 프로필의 피벗 오프셋과 고정 거리로 플레이어 카메라가 동작한다 |
| CAM-2 | 높음 | 궤도 트랙: 피치 커브로 위치·조준점·FOV 계산, Yaw 평면 회전, 피치 제한, 디버그 트랙 표시 | CAM-1 | Pitch·Yaw 입력으로 카메라가 트랙을 따라 움직인다 |

| CAM-4 | 보통 | 카메라 StateTree와 궤도 공간 블렌드 스택: 탐색, 전투, 락온 | CAM-3, 상태 선택 결정 | 상태 전환 시 캐릭터를 관통하지 않고 부드럽게 바뀐다 |
| CAM-5 | 보통 | 락온 화면 구성과 대상 전환 블렌드, KataFramework의 `OnLockTargetChanged` 연결 | CAM-4, [#19](https://github.com/jaykop/Kata/issues/19) 락온 입력 | 플레이어와 락온 대상이 함께 보이고 대상 전환이 끊기지 않는다 |
| CAM-6 | 후순위 | 디더링: 가림 물체 페이드, 캐릭터 근접 페이드, 해제 시 원래 값 복구 | CAM-3, 디더 머티리얼 결정 | 가림 물체와 가까운 캐릭터가 디더로 사라지고 벗어나면 돌아온다 |

항목별 진행 상태는 연결 이슈의 체크리스트와 댓글로 관리한다.

## 영향과 제한

- 모듈 경계: `KataCamera`는 코어 `Kata`와 엔진 모듈에만 의존한다. StateTree를 쓰면 `StateTree`·`GameplayStateTree` 엔진 플러그인 의존이 생긴다(KataAI와 같은 의존). `KataTargeting`과의 연결은 `KataFramework`에서 한다.
  에디터 전용 트랙 미리보기가 필요해지면 그때 Editor 모듈을 추가한다.
- 실행 상태 분리: 현재 Yaw·트랙 매개변수, 블렌드 진행, Shrink 거리, 디더 적용 목록은 컴포넌트가 가진다. 공유 프로필 에셋에 저장하지 않는다.
- 자원 수명: 디더링으로 바꾼 Custom Primitive Data는 대상이 벗어나거나 컴포넌트가 종료될 때 원래 값으로 되돌린다. 파괴된 프리미티브는 약한 참조로 걸러 낸다.
- 디버그: 트랙·스윕·가림 판정 표시는 `ENABLE_DRAW_DEBUG`로 감싼 CVar(예: `Kata.Camera.Debug`)로 제공한다.
- 싱글플레이 전용: 복제나 예측을 추가하지 않는다.
