# 스포너 개체별 거리·휴면·스냅샷 계약 계획

작성: 2026-10-07  
갱신: 2026-10-07  
연결 이슈: 미게시. 기존 스포너 타임슬라이싱·그리드 작업의 후속 범위.  
현재 상태 근거: [스포너 사용법](../manual/Spawner.md), [디스폰 수명 기록](../devlog/2026-10-07-Spawner-Despawn-Lifecycle.md)  
대체 관계: [전체 계획](Spawner-Scheduling-And-Grid-Plan.md)의 스포너 원점 기준 일괄 제거·새 배치 재진입안을 개체별 휴면·복원안으로 대체

## 목적과 현재 상태

플레이어와 살아 있는 NPC의 거리를 개체별로 판정하고, 거리 이탈로 제거하는 NPC는 상태를 저장했다가 같은 개체로 복원한다. 전투 여부를 별도로 판정하지 않는다. 그리드를 붙이기 전에 거리 기준, 논리적 개체의 수명, 저장·복원의 성공과 실패 경계를 정한다.

현재 코드에는 배치 세대 ID, NPC·직접 생성한 Controller의 공유 소유 기록과 수동 `DespawnCharacters`가 있다. 수동 제거는 스포너의 전체 생성 기록을 대상으로 하며 스냅샷을 남기지 않는다. 세대 ID는 Actor가 바뀐 뒤에도 같은 NPC를 식별할 수 있는 개체 ID가 아니다. 아래 슬롯·휴면·복원 API와 거리 설정은 구현 전 제안이다.

## 범위와 결정 구분

| 항목 | 구분 | 계약 방향 |
|---|---|---|
| 이탈 판단 | 사용자 요구 | 전투 상태 대신 PC가 빙의한 Pawn과 각 NPC의 현재 위치 사이 거리를 사용 |
| 거리 제거 후 재진입 | 사용자 요구 | 거리 제거 전에 스냅샷하고 재생성 시 해당 상태를 복원 |
| 작업 순서 | 사용자 확정 | 개체별 거리·휴면 기록·스냅샷 계약을 먼저 정하고 그리드를 연결 |
| 최초 생성·복원 기준점 | 제안 | 최초 생성은 스포너 원점, 복원은 개체별 저장 위치 |
| 거리 계산 | 제안 | cm 단위 3D 제곱 거리. 진입은 `Distance <= SpawnDistance`, 휴면은 `Distance > DespawnDistance` |
| 경계·PC 미준비 | 제안 | 유한한 양수와 `DespawnDistance > SpawnDistance`를 요구. 유효한 플레이어 Pawn이 없으면 새로운 거리 전환을 보류 |
| 휴면 중 시간 | 결정 필요 | 남은 시간을 정지하는 안을 권고. 월드 시간 경과를 반영할지도 결정해야 함 |
| 상태 보존 범위 | 제안 | 현재 월드에서 로드된 스포너의 수명 동안 메모리 보관. 세이브·월드 종료·World Partition 언로드를 넘는 보존은 별도 |

NPC 격자 배치, 풀링, 사망 시스템 자체, 자동 결원 보충, 일반 Actor용 거리 컴포넌트는 추가하지 않는다. 사망한 슬롯을 거리 진입만으로 되살리지 않는 것은 휴면 경로의 계약에 포함한다.

## 1. 개체별 거리 판단

| 대상 | 판정 위치 | 결과 |
|---|---|---|
| 아직 최초 활성화하지 않은 스포너 | 스포너 원점 | `SpawnDistance` 안에서 최초 수량과 슬롯을 확정하고 초기 생성 시작 |
| 생성된 슬롯 | NPC의 최신 위치 | `DespawnDistance` 밖이면 해당 슬롯만 휴면 후보로 예약 |
| 휴면 슬롯 | 스냅샷의 월드 위치 | `SpawnDistance` 안이면 같은 슬롯의 복원 예약 |

스포너가 멀어졌다는 이유로 살아 있는 모든 NPC를 일괄 제거하지 않는다. NPC가 스포너에서 멀리 이동해도 플레이어 가까이에 있으면 유지한다. 휴면 후 플레이어가 스포너 원점에 돌아오는 것만으로 이동한 NPC를 복원하지 않는다.

최초 수량은 한 번만 확정한다. 거리 재진입 때 수량·위치를 다시 무작위로 뽑지 않는다. 최초 생성 중 플레이어가 스포너 범위에서 벗어나면 미제출·로드 대기 슬롯은 취소하고 `Unspawned`로 남긴다. 이미 생성된 NPC는 각자의 현재 거리로 판정한다. 다시 진입하면 남은 슬롯을 이어가며, 확정한 위치가 있으면 보존한다. 실제 생성 실패·사망·외부 제거를 자동 보충하지 않는다.

거리 판단과 큐 실행 사이에 플레이어가 이동할 수 있다. 캡처 직전, NPC 제거 직전, 실제 복원 생성 직전에 최신 거리·슬롯 ID·작업 버전을 재확인한다. 캡처 후 제거 전에 조건이 해제되면 캡처 후보를 버리고 NPC를 유지한다. NPC 제거가 시작된 뒤에는 Controller 정리를 끝낸 다음 저장 위치로 복원 조건을 다시 판단한다.

## 2. 논리적 개체와 휴면 기록

스포너는 Actor 수명보다 긴 개체 슬롯을 소유한다. 제안하는 `SpawnSlotId`는 스포너 등록 수명 안에서 유일하며 휴면·복원마다 바뀌지 않는다. `BatchId`는 최초 생성 작업, `OperationRevision`은 취소·새 전환 작업, 기존 생성 소유 기록은 현재 Actor·Controller의 정리를 구분한다. 새 Actor를 생성할 때 소유 기록은 새로 만들고 슬롯 ID만 유지한다.

| 슬롯 상태 | 의미와 다음 전환 |
|---|---|
| `Unspawned` | 최초 생성 전 또는 거리로 최초 생성 대기 취소. 스포너 진입 시 `Spawning` |
| `Spawning` | 최초 위치 준비·로드·생성. 성공 시 `Alive`, 거리 취소 시 `Unspawned`, 생성 실패 시 `Failed` |
| `Alive` | 유효한 Actor를 관리. 개체 거리 이탈 시 `Suspending` |
| `Suspending` | 캡처·NPC 제거·소유 Controller 정리. 정리 완료 시 `Dormant`, 제거 전 실패·조건 해제 시 `Alive` |
| `Dormant` | Actor 없이 확정한 스냅샷 보관. 저장 위치 진입 시 `Restoring` |
| `Restoring` | 로드·생성·상태 복원. 준비 완료 시 `Alive`, 실패·거리 취소 시 원본을 유지하고 `Dormant` |
| `Dead` | 게임플레이 사망 통지를 받은 슬롯. 거리 복원 대상에서 제외 |
| `Removed` / `Failed` | 외부 제거 또는 최초 생성 실패. 거리로 자동 재생성하지 않음 |

하나의 슬롯에 이전 Actor와 복원 Actor가 동시에 존재하지 않아야 한다. NPC 제거 후 Controller 정리만 실패한 슬롯은 `Suspending`에 남기고 복원을 막는다. 매 프레임 무한 재시도하지 않으며 실패 이유를 기록한다. 복원 실패도 원본을 보존하고 같은 진입 안에서 계속 재시도하지 않는다. 다음 유효한 이탈·재진입을 재시도 계기로 삼는 안을 제안한다.

사망은 소유한 게임플레이 경로의 명시적 통지로 구분한다. `Destroy`나 특정 HP Attribute 값만으로 사망·휴면을 추정하지 않는다. 외부 Actor 파괴는 `Removed`로 처리한다. 사망 통지는 해당 슬롯의 대기 작업을 무효화하고 휴면 후보를 버린다. 사망·외부 제거의 전달 경로는 슬롯 기반 단계에서 먼저 마련해야 한다.

현재 수동 `DespawnCharacters`를 자동 거리 휴면에 그대로 호출하지 않는다. 수동 API는 기존 계약을 보존하고 거리 관리용 개체 작업을 별도로 연결한다. 거리 관리 모드에서 수동 생성·전체 제거를 동시에 허용할지는 공개 API 연결 전에 정해야 하며, 초기안은 중복 관리 요청을 거절하는 것이다.

## 3. 스냅샷 데이터와 캡처 계약

제안하는 스냅샷은 다음 데이터를 보관한다. 설정 에셋에 실행 상태를 저장하지 않으며, 슬롯의 GC 추적 가능한 실행 기록이 스냅샷을 소유한다.

| 데이터 | 저장 계약 |
|---|---|
| 식별·버전 | 슬롯 ID, 스냅샷 스키마 버전, 캡처 작업 버전 |
| 생성 기준 | Character ID와 최초에 고정한 행 Context. 휴면 중 행 편집을 새 개체 설정으로 섞지 않음 |
| 공간 | 캡처 순간 Actor의 월드 Transform. 최초 Spawn Area 무작위 배치를 다시 수행하지 않음 |
| GAS | 명시적으로 선택한 Attribute와 지속 효과의 복원 데이터. 아래 GAS 규칙을 따름 |
| 개체 고유 상태 | 공급자별 고정 키·스키마 버전·`FInstancedStruct` 데이터. 장비·재고·퀘스트 등 필요한 항목을 등록 |
| 시간 정보 | 선택한 휴면 시간 정책에 필요한 남은 시간 또는 캡처 시각 |

Actor·Controller 포인터, GAS 실행 핸들, 델리게이트·타이머 핸들, StateTree 실행 인스턴스를 영속 데이터처럼 복사하지 않는다. 에셋은 식별자·에셋 참조로 기록하고 강한 UObject 참조가 필요하면 `UPROPERTY` 경로로 보관한다.

캡처 공급자는 Actor·필요한 컴포넌트의 지속 상태를 읽고 성공·실패를 반환한다. 캡처는 액터 제거·게임플레이 변경을 수행하지 않는다. 필수 공급자 하나라도 실패하거나 지원하지 않는 지속 상태가 있으면 휴면을 거절하고 NPC를 유지한다. 일부만 저장한 뒤 초기값으로 재생성하지 않는다.

캡처 결과는 우선 후보로 보관한다. NPC 제거에 실패하면 후보를 폐기하고 `Alive`를 유지한다. 제거가 수락되면 후보를 보존하되 소유 Controller 정리가 끝나기 전에는 복원 가능 기록으로 공개하지 않는다. 기존 EndPlay·OnUnPossess 경로가 상태를 지우기 전에 캡처해야 한다.

### GAS 보존 규칙

GAS 전체의 메모리 상태를 일반 직렬화로 복원하지 않는다. 캐릭터별 스냅샷 설정에 보존할 Attribute와 효과 정책을 명시한다. 기본 GameplayData의 AttributeSet·능력·효과·태그는 새 Actor에 정상 초기화하고, 런타임에 변한 지속 상태를 그 위에 복원한다.

- Attribute의 `BaseValue`와 효과가 반영된 `CurrentValue`를 구분한다. 버프로 증가한 Current 값을 Base로 넣은 뒤 같은 버프를 적용하지 않는다. 선택한 Attribute의 Base와 필요한 지속 효과를 복원해 Current를 재계산하는 경로가 기본이다.
- HP 등 소모 상태는 최대값·연관 효과를 먼저 복원한 뒤 소모 값을 복원한다. Current에 직접 개입하는 효과가 있으면 해당 Attribute 공급자가 GAS 규칙에 맞는 복원 방식을 제공해야 한다. 범용 코드가 임의로 역산하지 않는다.
- 초기 GameplayData가 부여한 효과와 캡처한 런타임 효과를 구분해 중복 부여를 막는다. 지속 버프·쿨다운을 보존하려면 효과 종류·레벨·스택·남은 시간과 필요한 동적 데이터를 재구성하는 공급자가 필요하다. 지원하지 않는 필수 효과가 있으면 캡처 실패로 처리한다.
- 진행 중인 Ability·공격, AI 타깃·StateTree 실행 위치, 몽타주·이동 요청은 재개하지 않는다. 지속 상태를 복원한 뒤 정상 초기 상태에서 실행을 시작한다. 실행 도중만 존재하는 상태와 지속 상태의 구분은 공급자 계약에 명시한다.

첫 복원 경로의 최소 확인 대상은 Transform과 지정한 HP·최대 HP 등 Attribute다. 장비·효과를 보존 대상으로 지정했다면 해당 공급자까지 구현해야 휴면을 허용한다. 공급자 지원 범위가 아직 없는 캐릭터를 상태 보존 가능한 것으로 간주하지 않는다.

## 4. 복원 순서와 실패 계약

1. 슬롯 ID·스키마·필수 공급자·거리 조건을 검사하고 원본 스냅샷을 보존한 채 복원 요청을 만든다. 필요한 에셋은 실제 생성 전에 준비한다.
2. 저장 위치에 Deferred Spawn하고 슬롯·새 소유 기록·복원 Context를 `FinishSpawning` 전에 연결한다. 기존 행 적용을 실행한다.
3. ASC 준비와 기본 GameplayData 적용 후, 게임플레이가 정상 동작하기 전에 스냅샷의 GAS·지속 상태를 적용한다. 현재 `AKataCharacter::PostInitializeComponents`와 `AKataAICharacter::BeginPlay` 사이에 명시적인 복원 경계가 필요하다. 생성 성공 콜백에서 뒤늦게 HP를 덮어쓰지 않는다.
4. 장비처럼 컴포넌트 BeginPlay·비동기 초기화에 의존하는 공급자는 준비 완료 장벽에 참여한다. 기본 StartingEquipment와 스냅샷 장비를 이중 적용하지 않는다. 복원 중임을 구분하고, 모든 필수 공급자가 끝나기 전 AI·입력·생성 성공 통지를 활성화하지 않는다. BeginPlay 호출 자체가 완료를 뜻하지 않는다.
5. 모든 필수 상태가 적용되고 슬롯·작업이 유효할 때 `Alive`로 전환한다. 최초 생성과 복원을 이벤트에서 구분하고 안정적인 슬롯 ID를 전달한다. 그때까지 원본 스냅샷을 소비하지 않는다.
6. 실패·취소 시 새 Actor와 이번에 생성한 Controller를 기존 소유 정리 경로로 제거한다. 정리가 끝난 뒤 원본 스냅샷으로 `Dormant`를 유지한다. 정리 실패 상태에서 중복 복원을 시작하지 않는다.

저장 위치의 충돌·NavMesh 조건이 달라졌다면 복원 실패로 처리하는 안을 제안한다. 충돌 설정으로 실제 위치가 바뀌었는지도 확인한다. 임의로 스포너 원점이나 무작위 위치로 대체하지 않는다. 허용할 보정 범위는 별도 정책으로 정할 수 있다.

## 5. 책임과 그리드 연결

- `AKataCharacterSpawner`: 최초 행·수량, 슬롯과 스냅샷의 소유자. 슬롯 상태 전환은 한 경로에서 처리한다.
- `UKataSpawnerSubsystem`: PC Pawn 관찰, 개체별 거리 검사와 작업 예약, 기존 공용 프레임 예산. Actor별 Tick을 추가하지 않는다.
- `UKataSpawnerComponent_DistanceActivation`: 거리 등 인라인 설정만 보관한다. 기존 `UKataSpawnerComponent` 파생 UObject이며 ActorComponent가 아니다.
- `UKataCharacterSpawnSubsystem`: 로드·생성과 복원 Context 전달. 거리·휴면 정책을 판단하지 않는다.
- 캐릭터·상태 공급자: ASC·장비 등의 지속 상태 캡처·적용과 준비 완료 통지. 코어나 KataAI에 Framework 역참조를 추가하지 않는다.

그리드는 최초 생성 후보인 스포너 원점과 휴면 슬롯의 저장 위치를 각각 인덱싱한다. 살아 있는 슬롯은 별도 목록에서 NPC의 최신 위치로 거리 검사한다. 스포너 원점의 셀 하나로 휴면 NPC를 찾지 않는다. 작업마다 등록 ID·슬롯 ID·작업 버전을 확인하며, 불완전한 스캔을 거리 이탈로 처리하지 않는다.

거리 검사·캡처·제거·복원은 공용 예산 안에서 개체별로 분산한다. 한 번의 캡처 공급자 호출이나 `FinishSpawning`·Destroy를 중간에 끊지는 않는다. 설정한 시간은 작업 사이에 적용하는 부드러운 상한이다.

## 작업 순서와 완료 조건

| ID | 우선순위 | 작업 | 선행 조건 | 완료 조건 |
|---|---|---|---|---|
| D1 | 높음 | 슬롯 ID·상태·종료 사유와 개체별 거리 설정 | 본 계약의 거리·수명 경계 | 같은 스포너의 NPC를 개별 판정하고 사망·외부 제거를 휴면과 구분 |
| D2 | 높음 | 스냅샷 형식·필수 공급자와 휴면 작업 | D1, 보존 항목 선택 | 캡처 성공 전에 제거하지 않으며 실패하면 NPC 유지 |
| D3 | 높음 | 복원 Context·GAS 적용·준비 완료 장벽 | D2, 휴면 시간 정책 | 같은 슬롯·저장 위치·선택한 상태로 복원하고 실패 시 원본 보존 |
| D4 | 높음 | 최초 원점·휴면 위치 그리드 연결 | D1~D3 | 원점에서 벗어난 휴면 NPC도 저장 위치에서 재진입 가능 |
| D5 | 보통 | 편집 미리보기·진단과 사용 문서 | D4 | 거리 기준과 슬롯 상태·복원 실패 원인을 사용자에게 표시 |

## 영향과 제한

이 계약은 거리 관리 모드의 제안이며 현재 수동 스포너 동작을 변경하지 않는다. 새 반영 타입·공개 이벤트·설정은 구현 단계에서 확정하고 기존 에셋의 기본 비활성 계약을 유지한다. 재사용 코드는 KataFramework에 둔다.

현재 월드·로드된 스포너의 수명만 대상으로 하는 초기안을 권고한다. 스포너 EndPlay 때 대기 작업을 무효화하고 진행 중 자원 정리를 인계하며 슬롯·휴면 기록은 종료한다. World Partition 언로드를 넘겨 보존하려면 배치 Actor와 독립된 작성 시점 식별자·월드 기록 소유자가 추가로 필요하다. 이 보존 범위를 사용자 확정으로 간주하지 않는다.

## 사용자 확인 항목

구현 후 사용자 실행 확인 대상은 다음과 같다. 이 문서 작성 중 빌드·테스트·별도 검사는 실행하지 않았다.

- 한 스포너의 NPC 둘 중 플레이어와 멀어진 한 개체만 휴면하는지 확인.
- NPC를 스포너 원점에서 이동시키고 HP를 변경한 뒤 휴면시켜, 원점 방문으로 복원되지 않고 저장 위치 방문 시 같은 슬롯·HP로 복원되는지 확인.
- 캡처 실패·Destroy 실패·복원 실패에서 생존 NPC 또는 원본 스냅샷이 유지되는지 확인.
- 사망한 개체·외부 제거 개체가 거리 진입으로 재생성되지 않는지 확인.
- 로드·제거·복원 중 경계 왕복, PC Pawn 상실, Controller 이전과 스포너 종료에서 중복 개체·미추적 Controller가 없는지 확인.
- 보존 대상으로 선택한 버프·쿨다운의 남은 시간과 중복 효과 여부, 복원 완료 전 AI 실행 여부를 확인.
