# 루트 모션 이동량 커브 계획

작성: 2026-10-10  
갱신: 2026-10-10  
연결 이슈: [#36 루트 모션 이동량 커브 추출과 편집](https://github.com/jaykop/Kata/issues/36)  
현재 상태 근거: [기본 태스크 확장 계획](Base-Task-Plan.md#루트-모션이동의-선행-결정), [프리뷰 시간 탐색 기록](../devlog/2026-09-24-Preview-Scrub-Simulation.md), [런타임 사용법](../manual/Runtime-Usage.md#기본-태스크)  
대체 관계: 없음. [기본 태스크 확장 계획](Base-Task-Plan.md)의 5순위 "루트 모션·이동"을 이 문서에서 구체화한다.

## 목적과 현재 상태

에디터 도구로 애니메이션의 루트 모션을 커브로 추출하고, 실행 중에는 루트 모션 대신 그 커브를 읽어 캐릭터를 움직인다.
추출 직후의 커브는 원본 루트 모션과 같은 이동량을 내야 하며, 기획자는 필요한 구간만 커브를 고쳐 이동 거리와 속도 분포를 조정한다.
추출·편집은 에디터 전용 기능이고, 런타임은 커브를 읽어 이동에 적용하는 일만 한다.

현재 코드에는 루트 모션을 다루는 Kata 구조가 없다.

- `UKataTask_PlayMontage`는 ASC 또는 AnimInstance로 몽타주를 재생할 뿐이다. 루트 모션은 엔진의 `UCharacterMovementComponent`가
  몽타주에서 꺼내 그대로 적용한다. 이동 거리를 바꾸려면 애니메이션 자체를 고쳐야 한다.
- `EKataTaskPhase::Movement`는 정의만 있고 코어에 이 단계를 쓰는 태스크가 없다.
- 액션 편집기(`SKataTimeline`, Kata Details, Task Details)에는 커브 편집 UI가 없다.
- 프리뷰는 탐색할 때마다 실제 실행을 프레임 단위로 시뮬레이션한다. CharacterMovement 경로로 구현한 이동은 재생·탐색 모두 프리뷰에 나타난다.

## 엔진 진단

| 경로 | 동작 | Kata에 주는 영향 |
|---|---|---|
| 몽타주 루트 모션 추출 | `FAnimMontageInstance`가 진행 구간마다 `UAnimMontage::ExtractRootMotionFromTrackRange`로 변화량을 구해 누적한다. Root Motion From Everything일 때만 몽타주 가중치로 섞는다(`QueueRootMotionBlend`). 트랙 구간은 `FAnimSegment::GetRootMotionExtractionStepsForTrackRange`가 세그먼트별 자르기·재생 속도·반복을 반영한 시퀀스 구간으로 나눈다 | 커브도 같은 방식으로 "트랙 구간 → 시퀀스 구간 → 구간별 변화량 합"으로 읽으면 자른 시퀀스와 이어 붙인 시퀀스를 루트 모션과 같은 규칙으로 처리한다 |
| 루트 모션 재생 중 포즈 진행 | `IsPlayingRootMotion`이 참이면 CharacterMovement가 매 이동 갱신에서 `TickCharacterPose`로 몽타주를 진행한다. 이 조건은 RootMotionMode가 `RootMotionFromMontagesOnly`이고 루트 모션 몽타주가 재생 중일 때다 | 루트 모션을 `IgnoreRootMotion`으로 끄면 몽타주 진행이 메시 Tick으로 돌아가 아래 URO 예외도 잃는다 |
| URO(Update Rate Optimization) | `AnimUpdateRateSetParams`는 루트 모션 몽타주 재생 중이면 업데이트 주기를 1로 고정한다. 화면 밖에서도 업데이트는 매 프레임이고 포즈 평가만 줄인다 | 몽타주 위치는 LOD·거리와 무관하게 매 프레임 진행한다. 반면 평가된 포즈의 커브 값(`UAnimInstance::GetCurveValue`)은 평가 주기 감소·LOD 커브 필터의 영향을 받는다 |
| 에셋 커브 직접 평가 | `UAnimSequenceBase::EvaluateCurveData(FName, const FAnimExtractContext&)`는 시퀀스의 지정 시각 커브 값을 게임 스레드에서 바로 계산한다 | 포즈 평가를 거치지 않으므로 URO·LOD·본 감소와 무관하다. 루트 모션 추출이 트랙 데이터를 직접 읽는 것과 같은 성질이다 |
| `ProcessRootMotionPreConvertToWorld` | 꺼낸 애니메이션 루트 모션을 월드 변환 전에 바꾸는 단일 바인딩 델리게이트. Motion Warping의 `UMotionWarpingCharacterAdapter`가 바인딩한다 | 루트 모션 경로를 그대로 두고 값만 커브 결과로 바꿀 수 있는 자리다. Motion Warping과 함께 쓰면 바인딩이 충돌한다 |
| `FRootMotionSource`(Override) | 루트 모션 소스로 속도를 덮어쓴다. 애니메이션 루트 모션이 있는 동안 회전은 애니메이션 값이 이긴다 | 델리게이트 충돌은 없지만 Yaw 커브를 적용할 수 없고, 속도 덮어쓰기 순서는 실측이 필요하다 |
| `UMotionExtractorModifier`, `UAnimationModifier` | 엔진 Editor 모듈 AnimationModifiers의 수정자는 시퀀스에 커브를 굽고, 적용 기록을 시퀀스에 남겨 일괄 적용·되돌리기를 지원한다 | Kata 추출 도구를 수정자로 만들면 엔진의 일괄 적용 UI와 재적용 흐름을 그대로 쓴다 |
| 몽타주 커브 | `UAnimMontage`의 커브는 `RawCurveData`로 런타임에도 남고, `UAnimSequenceBase::EvaluateCurveData`가 몽타주 트랙 시각으로 바로 평가한다. 압축하지 않는다 | 몽타주 커브는 세그먼트 분할 없이 트랙 구간으로 바로 읽는다. 시퀀스 커브보다 계산이 단순하고 압축 오차가 없다 |
| Motion Warping 계산 | `URootMotionModifier_SkewWarp`는 남은 이동량을 `UMotionWarpingUtilities::ExtractRootMotionFromAnimation`으로 원본 애니메이션 루트 트랙에서 구한다 | 커브로 바꾼 이동량을 모른 채 원본 기준으로 보정하므로 #36과 그대로 함께 쓸 수 없다 |
| 갱신 순서 | CharacterMovement의 `PerformMovement`가 `TickCharacterPose` → `FAnimMontageInstance::Advance` → `UAnimInstance::PostUpdateAnimation`(블렌드) → 루트 모션 소비 → `ConvertLocalRootMotionToWorld` 안의 델리게이트 순서로 진행한다. 델리게이트는 애니메이션 루트 모션이 있는 갱신에서만 호출된다 | 델리게이트 시점의 몽타주 위치 기록은 같은 갱신의 진행 결과다. 입력값에는 `ACharacter::GetAnimRootMotionTranslationScale` 배율이 이미 적용돼 있으므로 대체값에도 같은 배율을 적용한다 |
| 위치 기록 | `Advance`는 시작할 때 `DeltaTimeRecord`를 (현재 위치, 0)으로 두고 하위 구간 이동량을 `Delta`에 더한다. `bPlaying`이 거짓이면 기록을 갱신하지 않는다 | `GetPreviousPosition`은 이번 진행의 시작 위치, `GetDeltaMoved`는 섹션 전환을 포함한 총 이동량이다. 정지한 몽타주 인스턴스는 `IsPlaying`으로 걸러 지난 기록을 다시 쓰지 않는다 |
| 블렌드 가중치 | Root Motion Mode가 Root Motion From Montages Only(엔진 기본값)이면 루트 모션 몽타주(`GetRootMotionMontageInstance`) 하나만 가중치 없이 루트 모션을 낸다. 새 루트 모션 몽타주를 재생하면 이전 것을 멈춘다. 몽타주 블렌드 값 × `GetSlotNodeGlobalWeight`로 섞는 경로는 Root Motion From Everything일 때만 쓴다(`UAnimInstance::Montage_Advance`) | 커브 대체는 루트 모션 몽타주 하나만 계산하고 가중치를 섞지 않는다. Root Motion From Everything은 몽타주 밖 루트 모션도 섞으므로 1단계에서는 엔진 값을 그대로 쓴다. 2026-10-10 R1 구현 중 소스를 다시 읽고 처음 기록(가중치 혼합)을 바로잡았다 |
| 섹션 전환 | 반복·다음 섹션 연결은 `Advance` 안에서 처리되어 위치가 새 섹션 시작으로 바뀌고, 엔진은 하위 구간마다 루트 모션을 꺼낸다(최대 10회). `Montage_JumpToSection`은 `SetPosition`으로 위치만 바꾸고 다음 `Advance`가 새 위치에서 시작한다. 다음 섹션은 `FAnimMontageInstance::GetNextSectionID`로 읽을 수 있다 | 시작 위치 + 총 이동량이 현재 위치와 다르면 섹션이 바뀐 것이다. `GetNextSectionID`로 경로를 다시 만들어 섹션별로 계산한다. 코드 점프는 별도 처리가 필요 없다 |
| 커브 압축 | 엔진 기본 커브 압축은 ACL 코덱(`/ACLPlugin/ACLAnimCurveCompressionSettings`)이며 형태 목표가 아닌 커브의 허용 오차는 0.001이다. 프로젝트 설정은 이를 바꾸지 않는다 | cm·도 단위 누적값의 압축 오차는 0.001 이하라 도착 위치에 영향이 없다. 시퀀스별로 다른 압축 설정을 쓸 수 있으므로 추출 검사는 유지한다. 몽타주 커브는 압축하지 않는다 |
| 몽타주 에디터 커브 UI | `FAnimModel_AnimMontage`도 시퀀스와 같은 `RefreshCurveTracks`로 커브 트랙을 만든다. 에디터에서 몽타주를 열면 `Curves` 트랙이 보인다 | 몽타주 커브도 엔진 커브 편집 UI로 편집한다. Kata가 편집 화면을 만들 필요가 없다 |

## 범위

- 포함: 시퀀스 루트 모션의 커브 추출 도구, 커브 편집 흐름, 커브 기반 이동 적용, 몽타주 자르기·이어 붙이기·블렌드 처리,
  URO·LOD·애니메이션 최적화 대응, 원본 일치 검사.
- 제외: 대상까지 거리 보정(#37), 대상 기준 전진 제한(#38). 단, 런타임 적용 지점은 두 이슈가 이어 쓸 수 있게 설계한다.

## 설계안

### 커브 데이터: 애니메이션 시퀀스 커브

- 커브는 `UAnimSequence`의 애니메이션 커브로 둔다. 이름은 `Kata.RootMotion.X`, `Kata.RootMotion.Y`, `Kata.RootMotion.Z`,
  `Kata.RootMotion.Yaw` 네 개를 제안한다.
- 값은 시퀀스 첫 프레임 루트 기준의 누적 위치와 누적 Yaw다. 누적값이면 기획자가 "이 시각까지 몇 cm 갔다"를 바로 읽고,
  압축 오차가 프레임마다 쌓이지 않는다.
- 시퀀스의 `bEnableRootMotion`은 켜 둔다. 루트 고정과 엔진의 루트 모션 재생 경로(위 URO 예외 포함)를 유지하기 위해서다.
  커브가 있는 시퀀스만 커브 값으로 대체하고, 커브가 없는 시퀀스는 원래 루트 모션을 쓴다.
- 커브 데이터는 런타임 데이터다. 에디터 전용인 것은 추출·편집·검사 도구다.

### 몽타주 커브 층

같은 시퀀스로 새 몽타주를 만들어 이동량을 따로 정하고 싶을 때를 위해 몽타주에도 같은 이름의 커브를 둘 수 있게 한다.

- 우선순위는 몽타주 커브 → 시퀀스 커브 → 원래 루트 모션이다. 판단 단위는 몽타주 인스턴스 하나다.
- 몽타주 커브가 있으면 그 몽타주 전체를 몽타주 커브로 처리한다. 일부 구간만 몽타주 커브로 덮는 혼합은 두지 않는다.
  네 커브 중 일부만 있으면 검사에서 오류로 보고한다.
- 몽타주 커브 값은 몽타주 트랙 시각 기준 누적값이다. 섹션 시작 위치와 무관하게 트랙 0초를 원점으로 한다.
- 에디터 명령 "Bake Root Motion Curve To Montage"가 현재 몽타주의 실제 이동량(시퀀스 커브가 있으면 그 값, 없으면 원본 루트 모션)을
  세그먼트를 따라 트랙 시간축으로 구워 몽타주 커브를 만든다. 기획자는 이 커브에서 편집을 시작한다.

### 추출과 편집 (에디터 전용)

- 추출 도구는 `UAnimationModifier` 파생 `UKataRootMotionCurveModifier`로 만든다. 지정 간격(기본은 시퀀스 프레임 단위)으로
  루트 모션을 샘플링해 네 커브를 쓰고, 끝값이 원본 전체 루트 모션과 허용 오차 안에서 같은지 검사한다.
- 편집은 애니메이션 시퀀스 에디터의 커브 트랙에서 한다. 엔진 커브 편집기(키·탄젠트)를 그대로 쓰므로 Kata가 UI를 새로 만들 필요가 없다.
- Kata 액션 편집기에는 2단계로 "이 액션의 몽타주가 쓰는 시퀀스 커브 열기"와 이동 경로 표시 같은 보조 기능을 검토한다.

### 실행

캐릭터에 붙는 컴포넌트가 `ProcessRootMotionPreConvertToWorld`를 바인딩하고, 엔진이 꺼낸 루트 모션을 커브 결과로 바꾼다.

1. AnimInstance의 루트 모션 몽타주 인스턴스가 재생 중(`IsPlaying`)이면 이번 갱신의 시작 위치(`GetPreviousPosition`), 총 이동량(`GetDeltaMoved`),
   현재 위치(`GetPosition`)를 읽는다. 시작 위치 + 총 이동량이 현재 위치와 같으면 트랙 구간 하나, 다르면 섹션 링크를 따라
   섹션별 트랙 구간으로 나눈다. 몽타주 커브가 있으면 트랙 구간마다 시작·끝 값으로 변화량을 만들고 4로 간다.
2. 트랙 구간을 세그먼트별 시퀀스 구간으로 나눈다(엔진의 루트 모션 추출과 같은 분할).
3. 시퀀스 구간마다 커브가 있으면 `EvaluateCurveData`로 시작·끝 값을 읽어 변화량을 만들고, 없으면 원래 루트 모션을 쓴다.
   변화량은 시작 시각 Yaw로 회전해 루트 기준 국소 이동으로 바꾼다.
4. 구간 변화량을 차례로 누적하고 루트 모션 이동 배율을 적용해 엔진 값 대신 반환한다. 커브를 하나도 쓰지 않은 갱신은 엔진 값을 그대로 둔다.

몽타주 섹션 점프도 1단계에서 처리한다. 반복 섹션이나 다음 섹션 연결로 한 갱신 안에서 섹션이 바뀌면,
섹션 링크를 따라 "이전 위치 → 이전 섹션 끝"과 "새 섹션 시작 → 현재 위치"로 구간을 나눠 각각 변화량을 구한다.
한 갱신에서 섹션이 여러 번 바뀌어도 같은 방식으로 이어 간다. 엔진이 루트 모션을 섹션 단위 하위 구간으로 나눠 꺼내는 방식과 같다.
다시 만든 경로가 현재 위치와 맞지 않으면(갱신 도중 노티파이가 위치를 바꾼 경우) 그 갱신만 엔진 값을 쓴다. 역재생도 1단계에서는 엔진 값을 쓴다.
갱신 사이에 코드로 `Montage_JumpToSection`을 호출한 경우는 점프 자체에 이동이 없으므로 새 위치부터 계산한다.

누적값의 차이가 아니라 구간별 변화량을 이어 붙이므로 세그먼트·섹션 경계에서 위치가 튀지 않는다.
몽타주 루트 모션 경로를 그대로 두므로 URO 예외, 몽타주 재생 속도, 히트스톱·시간 배율이 루트 모션과 똑같이 반영된다.

### #37·#38과의 관계

델리게이트 바인딩은 하나뿐이므로 Kata 컴포넌트가 바인딩을 소유하고, 커브 대체 → 거리 보정(#37) → 전진 제한(#38) 순서로
같은 처리 안에서 이어 붙인다. Motion Warping의 보정 계산은 원본 루트 트랙을 기준으로 하므로 커브와 맞지 않는다.
2026-10-10 사용자 결정으로 #37은 Motion Warping을 도입하지 않고 자체 구현한다. 같은 커브에서 남은 이동량을 구해 대상 거리에 맞춘다.

### 검토한 대안: 태스크 소유 커브

액션 태스크가 Kata 타임라인 시간축의 커브를 갖는 방식이다. 액션별 편집이 쉽고 애니메이션 에셋을 바꾸지 않지만 다음 단점이 있다.

- 자르기·이어 붙이기는 추출 시점에 한 커브로 굽는다. 몽타주 구성이나 재생 속도가 바뀌면 다시 추출해야 하고, 블렌드 가중치를 반영하지 못한다.
- 커브는 Kata 시계, 몽타주는 애니메이션 시계를 따르므로 히트스톱·시간 배율·몽타주 중단에서 어긋난다.
- 편집 UI를 Kata가 직접 만들어야 한다(Details의 작은 커브 미리보기 또는 CurveEditor 모듈 패널).

## 영향과 제한

- 애니메이션 시퀀스 에셋에 커브가 추가된다. 같은 시퀀스를 쓰는 모든 몽타주·액션이 같은 이동량을 쓴다.
  시퀀스 에셋 변경은 Diversion 커밋 대상이며 GitHub에는 포함되지 않는다.
- 엔진 시퀀스 이름 규칙상 다른 도구가 같은 이름의 커브를 쓰면 충돌하므로 `Kata.` 접두사를 유지한다.
- 기본 ACL 커브 압축의 오차는 0.001 이하다. 시퀀스에 더 거친 압축 설정을 지정하면 도착 위치가 달라질 수 있어 수정자 검사로 확인한다.
- 화면 밖 캐릭터의 Visibility Based Anim Tick Option이 포즈 Tick을 막는 설정이면 루트 모션과 같이 이동도 멈춘다. 엔진 루트 모션과 같은 제약이다.
