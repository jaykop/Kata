# 그래프 노드 타입 계획

작성: 2026-09-26  
갱신: 2026-10-03  
연결 이슈: [#25 KataGraph 실행 불가 노드 타입: Conduit·Alias·SubGraph](https://github.com/jaykop/Kata/issues/25)  
현재 상태 근거: [현재 구현 상태](../devlog/Implementation-Status.md)  
대체 관계: 없음

## 목적과 현재 상태

콤보 그래프에서 출발지 N개와 목적지 M개를 직접 이으면 엣지가 N×M개가 되고, 공통으로 요구하는
조건도 엣지마다 반복된다. 노드를 추가할 때마다 엣지와 조건을 함께 늘려야 하므로 그래프가 커질수록
유지가 어렵다.

해결 방향은 액션을 실행하지 않는 노드 타입을 도입하는 것이다. 이런 노드는 상태가 아니라 전이를
해석하는 동안만 지나가는 지점이며, 엣지를 N+M개로 줄이고 공통 조건을 한 곳에 모은다.

전이 해석 단계와 Conduit 노드는 구현했다. Alias, SubGraph, Reroute는 남아 있다.

## 범위

- 포함: 전이 해석 단계, Conduit 노드, Alias 노드(Any State 포함), SubGraph 평탄화와 포트 노드, Reroute 재평가.
- 제외: 그래프 병렬 실행(레이어), 중첩 실행 인스턴스 방식의 SubGraph.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 상태와 경유의 구분 | 확정 | `UKataNode::IsExecutableState()`가 정한다. 기본값은 false이고 `UKataActionNode`만 true를 준다. 액션 하나가 곧 상태 하나라는 전제를 타입으로 드러내, 앞으로 추가할 실행 불가 노드가 같은 규칙을 따르게 한다. |
| 출발지 자격의 분리 | 확정 | 머무를 수 있는지와 별칭의 출발지가 될 수 있는지를 따로 둔다. SubGraph Port Out은 머무를 수 없지만 펼치면 머무를 수 있는 노드가 되므로 출발지 자격은 참이다. `IsExecutableState()` 하나로 두 뜻을 겸하지 않는다. |
| 전이 해석의 원자성 | 확정 | `UKataGraphInstance::ResolveExecutableTarget()`이 자식에서 출발해 실행 가능한 노드까지 내려가며 지나는 모든 노드의 EntryCondition과 엣지의 Condition을 확인한다. 한 곳이라도 막히면 전이가 성립하지 않는다. 경유 노드에 머무를 수 없기 때문이다. |
| 순환 방어 | 확정 | 갈래마다 방문 기록을 복사해 내려간다. 한 갈래에서 지난 노드가 다른 갈래를 막지 않으면서 순환 그래프에서도 끝난다. |
| Conduit 출구 엣지의 의미 | 확정 | 떠나는 액션이 없으므로 Required Window Tag와 Timing을 보지 않는다. 트리거는 첫 엣지에서 이미 받았으므로 비어 있거나 같은 트리거면 통과시킨다. 우선순위는 첫 엣지 값으로 경쟁해 경유 경로와 직결 경로를 같은 기준에서 비교한다. |
| Alias의 대상 선정 | 확정 | 노드 목록과 `bAnyState` 토글로 정한다. Any State는 별도 노드 타입이 아니라 Alias의 한 모드다. 목록에는 SubGraph Port Out도 넣을 수 있다. 서브그래프 여러 개를 묶거나 일반 노드와 섞을 때 필요하며, Port Out 하나로는 서브그래프 하나만 출발지가 되기 때문이다. |
| Alias를 태그로 선정(ByTag) | 확정(도입하지 않음) | Alias가 가리키는 출발지 집합은 언제나 그 그래프 안에 있다. 노드는 소유 그래프에 종속되고 `UKataGraphInstance::CurrentNode`도 항상 자기 그래프의 노드이므로, 그래프를 넘는 집합은 의미가 없다. 공용 액션의 재사용은 SubGraph가 담당한다. 공용 서브그래프 안에서 부모의 부분집합을 가리켜야 하는 상황이 실제로 생기면 재검토한다. |
| Alias 출발 엣지의 의미 | 확정 | Conduit 출구와 반대로 Required Window Tag와 Timing을 그대로 적용한다. Alias는 현재 액션을 떠나는 그 순간이고 Conduit은 이미 떠난 뒤의 경로이기 때문이다. |
| 자기 전이 허용 옵션 | 확정(도입하지 않음) | 해석 결과가 현재 노드와 같으면 항상 건너뛴다. 실제로 쓸 사례가 확인되지 않았고, 안 쓰는 옵션을 노출하지 않는다. 필요해지면 그때 추가해도 기본값이 곧 유일한 동작이므로 직렬화된 에셋에 영향이 없다. |
| SubGraph 방식 | 확정 | 컴파일 시 부모 그래프로 펼치는 평탄화를 사용한다. 실행기를 바꾸지 않고 "액션 하나 = 상태 하나" 전제도 유지한다. 중첩 실행 인스턴스는 현재 위치가 두 인스턴스로 쪼개져 이 전제를 깨므로 쓰지 않는다. |
| SubGraph 포트 구조 | 확정 | 부모 그래프에는 서브그래프를 가리키는 포트를 놓는다. 같은 서브그래프를 가리키는 포트를 여러 개 놓을 수 있고, 펼치면 사본은 한 벌만 생겨 모든 포트가 그 사본으로 이어진다. 진입 지점을 쓰는 노드 옆에, 이탈 지점을 목적지 옆에 두어 긴 엣지를 없애려는 것이다. |
| 포트의 런타임 대응 | 확정 | Port In은 Conduit처럼 머무르지 않고 서브그래프 안쪽 액션까지 해석되고, Port Out은 Alias처럼 서브그래프 안을 출발지로 삼는다. 둘 다 펼칠 때 사라지므로 `UKataGraphInstance`에 새 기계장치가 필요하지 않다. |
| 포트를 Conduit·Alias에 얹지 않는다 | 확정 | 의미는 비슷하지만 연결 규칙이 반대다. Conduit은 이 그래프의 자식으로 나가는 엣지를 그리지만 Port In은 목적지가 서브그래프 안이라 부모에 그릴 엣지가 없다. Alias의 목록은 손으로 고르지만 포트의 출발지는 참조에서 자동으로 나온다. 한 클래스에 조건부 규칙을 섞으면 에디터가 잘못된 연결을 막을 수 없다. |
| 포트 노드 구성 | 확정 | 추상 기반 `UKataSubGraphPortNode`에 `SubGraph`와 `PortName`을 두고 `UKataSubGraphPortInNode`·`UKataSubGraphPortOutNode`로 나눈다. 방향을 프로퍼티로 두면 엣지를 다 연결한 뒤 방향을 바꿔 조용히 깨진 상태가 생기고, 우클릭 메뉴에도 항목이 하나만 나온다. 클래스를 나누면 그 상태가 존재할 수 없고 연결 제한도 생성자에서 고정한다. |
| 포트 이름 규칙 | 확정(도입하지 않음) | 포트에 이름을 두어 서브그래프의 특정 입구·출구와 짝지으려 했으나 넣지 않는다. 입구가 하나면 고를 것이 없고, 여럿이어도 각 진입 노드의 조건과 엣지 우선순위가 실행 중에 가르는 편이 낫다. 판단이 서브그래프 안에 모이고 부모가 내부 사정을 몰라도 된다. 정상 종료는 이름 없는 Port Out에 트리거를 비운 자동 전이를 걸어 표현한다. 이름을 넣으려면 `UKataEntryNode`에 런타임 이름과 새 Exit 노드 타입이 함께 필요하므로, 입구가 여럿인 서브그래프를 실제로 만들게 되면 그때 함께 도입한다. |
| 서브그래프 사본을 무엇에서 만드나 | 확정 | 서브그래프의 런타임 그래프를 복사한다. 저장된 상태를 기준으로 삼으면 되고 편집기 구조를 다루지 않아도 된다. `Rename`이 아니라 `DuplicateObject`를 쓴다. 지금 `RebuildKataGraph()`가 하듯 `Rename`하면 원본 에셋에서 노드를 빼앗아 온다. |
| 같은 서브그래프를 두 벌 쓰기 | 확정(도입하지 않음) | 부모당 사본 한 벌로 시작한다. 포트마다 엣지와 조건이 따로라 맥락별 차이는 이미 표현된다. 필요해지면 포트에 인스턴스 이름을 더해 (에셋 + 이름)으로 묶으면 되고, 기본값이 빈 이름이라 기존 에셋에 영향이 없다. |
| SubGraph 재컴파일 시점 | 확정 | 부모 그래프를 저장할 때 `RebuildKataGraph()` 안에서 펼친다. 이미 그 시점에 도는 단계라 배선을 더하지 않아도 된다. 서브그래프를 고치고 부모를 저장하지 않으면 부모가 낡은 사본을 쓰는 것이 대가다. 에셋 의존을 추적해 자동으로 다시 펼치는 것은 별도 작업으로 둔다. |
| Reroute 노드 | 제안 | Conduit·Alias·포트가 들어온 뒤 선 꼬임이 남는지 보고 판단한다. 액션 노드를 여러 곳에 중복 배치하는 방식은 현재 위치가 모호해지므로 쓰지 않는다. 포트는 머무를 수 없어 이 문제가 없으므로 중복 배치를 허용한다. |
| 포트의 내장·외장 선택 | 확정 | 토글 하나와 필드 둘로 나눈다. 외장은 기본 오브젝트 피커를 그대로 쓰고, 내장은 그래프가 가진 서브그래프를 콤보로 고른다. 필드를 하나로 합치면 내장과 에셋을 한 피커에 담아야 해서 에셋 브라우징까지 직접 만들어야 한다. 포트 하나는 서브그래프 하나를 가리키므로 내장 선택은 체크 목록이 아니라 단일 선택이다. 꺼진 쪽은 `EditConditionHides`로 숨겨 둘 다 채워지는 상태를 만들지 않는다. 구현은 [#27](https://github.com/jaykop/Kata/issues/27)에서 한다. |
| 내장 서브그래프 | 확정(별도 이슈) | 한 그래프 안에서 서브그래프를 만들고 더블클릭으로 편집한다. 같은 에셋에 들어 있어 함께 저장되므로 외장 사본이 낡는 문제가 없다. 오브젝트 이름은 자동 생성이라 구분할 수 없으므로 사용자가 붙이는 표시 이름이 필요하다. 런타임과 평탄화는 바꾸지 않는다. 내장도 `UKataGraph`라 포트 참조와 `DuplicateObject` 평탄화가 그대로 동작한다. [#27](https://github.com/jaykop/Kata/issues/27). |
| 외장 서브그래프의 낡은 사본 | 확정(완화만) | 부모가 사본을 들고 있는 한 원본이 바뀌면 낡는다. 부모를 열 때 다시 펼쳐 메모리를 맞추고, 참조 대상이 바뀐 부모에 저장이 필요하다는 표시를 띄우는 선까지 한다. 디스크와 쿡 데이터는 사람이 부모를 저장해야 맞는다. 열지 않은 에셋을 임의로 덮어쓰지 않기 때문이다. 펼침을 로드 시점으로 옮기면 원천적으로 사라지지만 펼침 코드를 런타임으로 옮기고 로드 순서를 다뤄야 한다. 내장 서브그래프가 들어오면 외장 의존 자체가 줄어 문제의 크기가 작아지므로 [#27](https://github.com/jaykop/Kata/issues/27) 이후에 다시 본다. |
| 그래프 병렬 실행 | 제외 | 상·하체처럼 두 줄기가 동시에 도는 구조는 SubGraph가 아니라 별개 기능이다. 평탄화로는 표현할 수 없으므로 필요해지면 따로 설계한다. |

## 작업 순서와 완료 조건

| ID | 우선순위 | 작업 | 선행 조건 | 완료 조건 |
|---|---|---|---|---|
| G1 | 높음 | 전이 해석 단계와 Conduit 노드 | 없음 | 경유 노드를 지나 액션 노드까지 전이가 성립하고, 경유 노드의 조건이 막히면 전이가 무산된다 |
| G2 | 높음 | Alias 노드와 Any State 토글 | G1 | 현재 노드를 포함하는 Alias의 엣지가 현재 노드의 엣지와 함께 평가되고, 자기 전이는 건너뛴다 |
| G3 | 보통 | SubGraph 포트 노드와 평탄화 | 재컴파일 시점 결정 | 같은 서브그래프를 가리키는 포트가 여럿이어도 사본은 한 벌만 생기고, Port In으로 들어가 Port Out으로 나가는 전이가 성립한다 |
| G4 | 낮음 | Reroute 필요 여부 재평가 | G2, G3 | 도입 또는 미도입을 근거와 함께 결정한다 |

G2는 끝났다. Alias의 "전체" 판정을 `UKataGraphBase::AllNodes` 기준으로 두었으므로 평탄화가 들어와도
펼쳐진 노드가 그대로 포함된다. G3에서 Alias의 후보 목록에 Port Out을 더하는 작업이 남는다.

## 영향과 제한

전이 대상 결정이 `KataGraph` 런타임에서 바뀐다. 이전에는 엣지가 가리키는 자식을 `UKataActionNode`로
캐스팅해 실패하면 건너뛰었으므로, 액션을 실행하지 않는 노드는 전이 대상이 될 수 없었다.

기존 그래프의 동작은 유지된다. Conduit이 없던 시점에는 액션 노드가 아닌 자식이 생길 경로가 없었고,
진입 노드는 들어오는 연결이 0으로 막혀 있다.

우선순위에서 이미 밀린 후보는 해석하지 않고 건너뛴다. 해석이 하위 노드를 훑는 만큼 비용이 생기는데,
조건 평가에 부작용이 없어 건너뛰어도 결과가 달라지지 않는다.

새 노드 타입은 `UKataGraph::NodeType`이 `UKataNode`이므로 그래프 우클릭 메뉴에 자동으로 나타난다.
직렬화된 기존 에셋에는 새 타입이 없으므로 Redirect가 필요하지 않다.

경유 노드가 막다른 길이면 전이가 조용히 성립하지 않는다. 에디터 검증으로 잡을 문제이며 아직 없다.

포트는 부모 그래프에서 다른 에셋을 참조하므로 순환 참조를 막아야 한다. A가 B를, B가 A를 가리키면
펼침이 끝나지 않는다. 자기를 포함하는 재귀 서브그래프도 같은 이유로 펼칠 수 없다.

펼쳐진 노드는 사본이라 런타임에 어느 서브그래프에서 왔는지 드러나지 않는다. 진단할 때 아쉬워질 수 있다.

## 사용자 확인 항목
