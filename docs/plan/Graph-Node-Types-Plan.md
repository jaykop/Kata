# 그래프 노드 타입 계획

작성: 2026-09-26  
갱신: 2026-09-26

현재 상태 근거: [현재 구현 상태](../devlog/Implementation-Status.md)  
대체 관계: 없음

## 목적과 현재 상태

콤보 그래프에서 출발지 N개와 목적지 M개를 직접 이으면 엣지가 N×M개가 되고, 공통으로 요구하는
조건도 엣지마다 반복된다. 노드를 추가할 때마다 엣지와 조건을 함께 늘려야 하므로 그래프가 커질수록
유지가 어렵다.

해결 방향은 액션을 실행하지 않는 노드 타입을 도입하는 것이다. 이런 노드는 상태가 아니라 전이를
해석하는 동안만 지나가는 지점이며, 엣지를 N+M개로 줄이고 공통 조건을 한 곳에 모은다.

전이 해석 단계와 Conduit 노드는 구현했다. Alias, SubGraph, Reroute는 남아 있다.

## 범위

- 포함: 전이 해석 단계, Conduit 노드, Alias 노드(Any State 포함), SubGraph 평탄화, Reroute 재평가.
- 제외: 그래프 병렬 실행(레이어), 중첩 실행 인스턴스 방식의 SubGraph.

## 확정 사항과 미확정 사항

| 항목 | 구분 | 내용과 근거 또는 필요한 결정 |
|---|---|---|
| 상태와 경유의 구분 | 확정 | `UKataNode::IsExecutableState()`가 정한다. 기본값은 false이고 `UKataActionNode`만 true를 준다. 액션 하나가 곧 상태 하나라는 전제를 타입으로 드러내, 앞으로 추가할 실행 불가 노드가 같은 규칙을 따르게 한다. |
| 전이 해석의 원자성 | 확정 | `UKataGraphInstance::ResolveExecutableTarget()`이 자식에서 출발해 실행 가능한 노드까지 내려가며 지나는 모든 노드의 EntryCondition과 엣지의 Condition을 확인한다. 한 곳이라도 막히면 전이가 성립하지 않는다. 경유 노드에 머무를 수 없기 때문이다. |
| 순환 방어 | 확정 | 갈래마다 방문 기록을 복사해 내려간다. 한 갈래에서 지난 노드가 다른 갈래를 막지 않으면서 순환 그래프에서도 끝난다. |
| Conduit 출구 엣지의 의미 | 확정 | 떠나는 액션이 없으므로 Required Window Tag와 Timing을 보지 않는다. 트리거는 첫 엣지에서 이미 받았으므로 비어 있거나 같은 트리거면 통과시킨다. 우선순위는 첫 엣지 값으로 경쟁해 경유 경로와 직결 경로를 같은 기준에서 비교한다. |
| Alias의 대상 선정 | 확정 | 노드 목록과 `bAnyState` 토글로 정한다. Any State는 별도 노드 타입이 아니라 Alias의 한 모드다. |
| Alias를 태그로 선정(ByTag) | 확정(도입하지 않음) | Alias가 가리키는 출발지 집합은 언제나 그 그래프 안에 있다. 노드는 소유 그래프에 종속되고 `UKataGraphInstance::CurrentNode`도 항상 자기 그래프의 노드이므로, 그래프를 넘는 집합은 의미가 없다. 공용 액션의 재사용은 SubGraph가 담당한다. 공용 서브그래프 안에서 부모의 부분집합을 가리켜야 하는 상황이 실제로 생기면 재검토한다. |
| Alias 출발 엣지의 의미 | 확정 | Conduit 출구와 반대로 Required Window Tag와 Timing을 그대로 적용한다. Alias는 현재 액션을 떠나는 그 순간이고 Conduit은 이미 떠난 뒤의 경로이기 때문이다. |
| 자기 전이 허용 옵션 | 확정(도입하지 않음) | 해석 결과가 현재 노드와 같으면 항상 건너뛴다. 실제로 쓸 사례가 확인되지 않았고, 안 쓰는 옵션을 노출하지 않는다. 필요해지면 그때 추가해도 기본값이 곧 유일한 동작이므로 직렬화된 에셋에 영향이 없다. |
| SubGraph 방식 | 확정 | 컴파일 시 부모 그래프로 펼치는 평탄화를 사용한다. 실행기를 바꾸지 않고 "액션 하나 = 상태 하나" 전제도 유지한다. 중첩 실행 인스턴스는 현재 위치가 두 인스턴스로 쪼개져 이 전제를 깨므로 쓰지 않는다. |
| SubGraph 입구·출구 | 결정 필요 | 전용 Entry·Exit 노드를 새로 둘지, 기존 `UKataEntryNode`를 재사용할지. |
| SubGraph 재컴파일 시점 | 결정 필요 | 서브그래프를 수정했을 때 부모를 언제 다시 펼칠지. 저장할 때, 열 때, 수동 중에서 고른다. |
| Reroute 노드 | 제안 | Conduit과 Alias가 들어온 뒤 선 꼬임이 남는지 보고 판단한다. 같은 노드를 여러 곳에 중복 배치하는 방식은 현재 위치가 모호해지므로 쓰지 않는다. |
| 그래프 병렬 실행 | 제외 | 상·하체처럼 두 줄기가 동시에 도는 구조는 SubGraph가 아니라 별개 기능이다. 평탄화로는 표현할 수 없으므로 필요해지면 따로 설계한다. |

## 작업 순서와 완료 조건

| ID | 우선순위 | 작업 | 선행 조건 | 완료 조건 |
|---|---|---|---|---|
| G1 | 높음 | 전이 해석 단계와 Conduit 노드 | 없음 | 경유 노드를 지나 액션 노드까지 전이가 성립하고, 경유 노드의 조건이 막히면 전이가 무산된다 |
| G2 | 높음 | Alias 노드와 Any State 토글 | G1 | 현재 노드를 포함하는 Alias의 엣지가 현재 노드의 엣지와 함께 평가되고, 자기 전이는 건너뛴다 |
| G3 | 보통 | SubGraph 평탄화 | 입구·출구와 재컴파일 시점 결정 | 서브그래프를 참조한 부모 그래프가 펼쳐진 노드로 실행되고, 서브그래프 수정이 부모에 반영된다 |
| G4 | 낮음 | Reroute 필요 여부 재평가 | G2, G3 | 도입 또는 미도입을 근거와 함께 결정한다 |

G2와 G3은 순서를 바꿀 수 있다. Alias의 "전체" 판정을 `UKataGraphBase::AllNodes` 기준으로 두면
평탄화가 나중에 들어와도 펼쳐진 노드가 그대로 포함된다.

## 영향과 제한

전이 대상 결정이 `KataGraph` 런타임에서 바뀐다. 이전에는 엣지가 가리키는 자식을 `UKataActionNode`로
캐스팅해 실패하면 건너뛰었으므로, 액션을 실행하지 않는 노드는 전이 대상이 될 수 없었다.

기존 그래프의 동작은 유지된다. Conduit이 없던 시점에는 액션 노드가 아닌 자식이 생길 경로가 없었고,
진입 노드는 들어오는 연결이 0으로 막혀 있다.

우선순위에서 이미 밀린 후보는 해석하지 않고 건너뛴다. 해석이 하위 노드를 훑는 만큼 비용이 생기는데,
조건 평가에 부작용이 없어 건너뛰어도 결과가 달라지지 않는다.

새 노드 타입은 `UKataGraph::NodeType`이 `UKataNode`이므로 그래프 우클릭 메뉴에 자동으로 나타난다.
직렬화된 기존 에셋에는 새 타입이 없으므로 Redirect가 필요하지 않다.

경유 노드가 막다른 길이면 전이가 조용히 성립하지 않는다. 에디터 검증으로 잡을 문제이며 아직 없다.

## 사용자 확인 항목

구현 완료와 실행 확인을 구분한다.

- G1: 사용자 에디터 빌드 확인 완료. 그래프 실행 확인은 아직이다. 확인할 것은 기존 콤보 그래프의
  진입·자동 전이·취소 전이가 이전과 같은지, Conduit을 거친 전이가 이어지는지, Conduit의 조건이
  막혔을 때 전이가 무산되는지, 나가는 엣지가 없는 Conduit으로 전이가 되지 않는지다.
- G2 이후: 미착수.
